# 실사용 확인표

현재 시제품의 불편을 찾기 위한 짧은 확인이다. 정식 성능 평가(Task 8)가 아니며, 결과를 인식률로 쓰지 않는다. 시험 담당 제안: 기정 님(직접 합의 전).

## 시험 전 준비

1. 폰에 남길 세션이 있으면 먼저 옮긴다. 저장소 맨 위에서 폰을 USB로 연결하고 실행한다.

   ```powershell
   node tools/pull-phone-sessions.js --keep
   ```

2. 이 APK는 다른 PC에서 서명했으므로 처음 한 번은 기존 앱을 지우고 설치한다(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`). 앱을 지우면 폰의 세션과 연결 기록도 지워진다. 그다음부터는 같은 PC에서 만든 APK를 덮어쓸 수 있다.
3. 앱을 열어 주변 기기 권한을 허용하고, 접근성 설정에서 'RingPilot 스와이프'를 켠다.
4. 보드에는 `firmware/gesture_infer` 최신본(입력 지우기, 일시정지 0.5초)이 올라가 있어야 한다.
5. USB를 빼고 배터리로 쓴다. USB 무게가 동작을 바꾼다.

## 시험 순서(10~15분)

앱에서 **연속 기록 시작**, **스와이프 제어 켜기**를 누른 뒤 유튜브나 네이버 시리즈로 넘어간다. 넘기고, 멈추고, 자세를 바꾸고, 쉬는 평소 흐름으로 쓰되 아래를 한 번씩 넣는다.

| 상황 | 해 볼 것 |
|---|---|
| 빠른 반복 | 같은 방향으로 빠르게 5번 |
| 위·아래 번갈아 | 위·아래를 빠르게 번갈아 10번 |
| 아래 반복 | 편한 간격으로 아래 10번(PC 재채점에서 가장 낮은 방향) |
| 전환 직후 | 좌우로 전환하고 바로 위·아래 조작, 3번 |
| 좌우 모드 사용 | 좌우 모드로 한동안 사용 |
| 자세 바꾸기 | 사용 중 눕는 방향이나 손 위치를 바꾼 뒤 조작 |
| 일시정지 | 일시정지하고 잠깐 쉰 뒤 재개해서 조작 |

끝나면 앱으로 돌아와 **연속 기록 중지**, **세션 종료**를 누른다.

## 메모할 것

대략의 시각과 함께 한 줄씩 적는다. 시각을 모르면 "번갈아 하다가"처럼 상황만 적어도 된다.

- **명령 문제:** 안 먹음, 잘못된 방향, 원치 않는 전환
- **모드 문제:** 지금 모드를 헷갈림, 배너를 놓침
- **조작 부담:** 손이 피곤함, 전환이 번거로움, 일시정지가 불편함
- **끊김:** 앱 연결이 끊김, 앱이 꺼짐, 연속 기록이 멈춤

마지막에 "가장 자주 사용을 끊은 문제 하나"를 적는다.

## 보내 줄 것

저장소 맨 위에서 폰을 USB로 연결해 옮긴 뒤 아래 파일과 메모를 보낸다.

```powershell
node tools/pull-phone-sessions.js --keep
```

- `data/sessions/phone-connection-logs/`의 연결 기록(제스처, 앱 판단, 스와이프 결과, 연결·일시정지)
- `data/sessions/phone-<세션>/`의 `continuous.*.csv`와 같은 이름의 사이드카(원시 센서값)
- 메모

세션에 개인 정보는 없지만 시험 기록이므로 공개 저장소에 올리기 전에 확인한다. adb나 Node가 없으면 메모만 먼저 보내고 파일 전달 방법을 다시 정한다.

## 이 기록으로 알 수 있는 것과 없는 것

- 알 수 있음: 어떤 제스처가 언제 들어왔고, 그때 모드가 무엇이었고, 어떤 스와이프를 요청했으며 완료됐는지 취소됐는지
- 후보만 알 수 있음: 무발행. 연속 기록의 자이로 볼록으로 후보를 찾고, 조작하려던 동작인지는 메모로 판단한다.
- 알 수 없음: 화면이 실제로 원하는 대로 움직였는지. `swipe_result=completed`는 시스템이 주입을 마쳤다는 뜻이다. 메모로 확인한다.
