# 실사용 확인표

현재 시제품의 불편을 찾기 위한 짧은 확인이다(약 5분). 정식 성능 평가(Task 8)가 아니며, 결과를 인식률로 쓰지 않는다. 시험 담당 제안: 기정 님(직접 합의 전).

## 준비

1. 앱 설치: 처음 쓰는 PC에서 만든 APK면 서명이 달라 기존 앱을 지우고 설치해야 하고(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`), 그러면 폰의 세션과 연결 기록도 지워진다. 남길 세션은 먼저 `node tools/pull-phone-sessions.js --keep`으로 옮긴다.
2. 앱에서 주변 기기 권한을 허용하고, 접근성 설정에서 'RingPilot 스와이프'를 켠다.
3. 보드에는 `firmware/gesture_infer` 최신본이 올라가 있어야 한다. USB는 빼고 배터리로 쓴다(USB 무게가 동작을 바꾼다).

## 시험(약 5분)

앱에서 **연속 기록 시작**, **스와이프 제어 켜기**를 누르고 유튜브나 네이버 시리즈로 간다.

| 상황 | 해 볼 것 |
|---|---|
| 빠른 반복 | 같은 방향으로 빠르게 5번 |
| 번갈아 | 위·아래를 빠르게 번갈아 6번 |
| 아래 | 편한 간격으로 아래 5번(PC 재채점에서 가장 낮은 방향) |
| 전환 직후 | 좌우로 전환하고 바로 위·아래 조작, 2번 |
| 자세 바꾸기 | 손 위치를 바꾼 뒤 위·아래 몇 번 |

끝나면 앱에서 **연속 기록 중지**, **세션 종료**를 누른다.

## 메모

문제가 있던 상황만 한 줄씩 적는다(예: "번갈아 하다가 아래가 안 먹음"). 안 먹음, 잘못된 방향, 원치 않는 전환, 모드 헷갈림, 끊김을 구분해 주면 좋다. 마지막에 가장 거슬린 문제 하나를 적는다.

## 보내 줄 것

폰을 USB로 연결해 `node tools/pull-phone-sessions.js --keep`으로 옮긴 뒤 메모와 함께 보낸다.

- `data/sessions/phone-connection-logs/`의 연결 기록(제스처, 앱 판단, 스와이프 결과)
- `data/sessions/phone-<세션>/`의 `continuous.*.csv`와 사이드카(원시 센서값)

시험 기록이므로 공개 저장소에 올리기 전에 확인한다. adb나 Node가 없으면 메모만 먼저 보낸다.

## 이 기록으로 알 수 있는 것

- 알 수 있음: 어떤 제스처가 언제 들어왔고, 그때 모드와 요청한 스와이프, 완료·취소 여부.
- 후보만: 무발행. 연속 기록에서 후보를 찾고 메모로 판단한다.
- 알 수 없음: 화면이 실제로 원하는 대로 움직였는지. `swipe_result=completed`는 시스템이 주입을 마쳤다는 뜻이라 메모로 확인한다.
