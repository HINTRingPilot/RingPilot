# RingPilot 초기 모델 학습·평가 계획

작성: 2026-10-21. 학습 데이터 구성, 비교 실험, 평가 절차를 관리한다. 모델의 연결 구조와 입출력 사양은 [아키텍처 설계](ModelArchitecture.md)에 둔다. 아래 후속 작업은 실행 전 계획이다.

> **2026-10-23:** 아래 분할·개수·세션 이름(`phone-20261021-*`, 원본 66개, 최종 평가 22개 등)은 삭제된 테스트 세션 기준이다. 해당 데이터와 `data/splits/`는 더 이상 없으므로, 새로 수집한 데이터(자이로 ±2000 dps, 4초 클립)로 분할을 다시 정해야 한다. 평가 원칙(원본 단위 분할, 교차검증, 고정 epoch 등)은 그대로 적용한다. 새 수집 구성은 아래 [재수집 계획](#재수집-계획--2026-10-25)을 따른다.

> **2026-10-25:** 새 데이터로 하는 첫 정식 실험은 [BLE v2 실험](#ble-v2-실험--평가-방식-sc-비교-2026-10-25) 절에 있다.

## 재수집 계획 — 2026-10-25

실행 전 계획이다. 개수는 제안값이며 검증된 최소치가 아니다. 수집 후 실제 개수·제외 수를 기록한다.

### 수집할 데이터 한눈에 보기

현재 앱(4초 클립, 1초 뒤 동작 신호, ±2000 dps)으로 세션 5개를 모은다. **세션 하나가 자세 하나다**(2026-10-25 사용자 결정).

| 세션 | 자세 |
|---|---|
| P1 | 앉은 자세 |
| P2 | 누운 채 팔을 침대에 그대로 내림 |
| P3 | 누운 채 팔을 하늘로 90도 올림(거치대의 폰을 만지던 도중) |
| P4 | 한쪽으로 돌아누워 팔을 꺾음 |
| P5 | 한쪽으로 돌아누워 팔을 꺾지 않음 |

| 종류 | 앱 기능 | 세션당 | 5세션 합계 | 쓰임 |
|---|---|---|---|---|
| 방향 클립 `raw_up/down/left/right` | 방향 안내 수집(방향별 15회) | 60개 | 300개(방향별 75) | 방향 학습·검증 |
| `idle` | idle 10초 | 3개(30초) | 15개(150초) | 정지 상태 NONE |
| `other` | other 10초 | 5개(50초) | 25개(250초) | 헷갈리는 동작 NONE, 오발행 확인 |

- **방향은 손가락 기준이다.** 돌아누운 자세에서도 화면·하늘이 아니라 손가락에 대한 방향으로 움직인다. 바깥 기준으로 하면 같은 라벨이 반지 축에서는 다른 동작이 된다.
- **세기는 일반화를 위해 다양하게 섞는다.** 약·중·강을 섞되 개수를 맞추거나 기록하지 않는다. 앱은 세기를 안내하지 않는다.
- **날짜와 재착용은 통제하지 않는다.** 날짜는 관련 없는 요인으로 보고 뺐다. 반지 착용 각도는 경우가 끝없이 많아 수집으로 덮기 어려우므로 학습 때 증강으로 다룬다([착용 각도 증강](#착용-각도-증강-계획)).
- 세션 하나에 방향 클립만 약 7~8분이다. P3(팔 90도)처럼 힘든 자세는 **일시정지**로 쉬어 가며, 피로가 쌓이지 않게 세션 사이에도 쉰다.
- 평가용은 세션 하나를 통째로 떼는 방식과 다섯 세션에서 일부씩 떼는 방식을 모두 해 보고 비교한다(아래 [분할](#분할)).
- 10-21 데이터는 방향 원본 60개·배경 60초였고, 그중 개발용 방향은 35개, 검증 배경은 20초였다.
- 연속 기록은 이번 수집에서 뺐다(2026-10-25 사용자 결정). 이유와 재검토 거리는 아래 [보류: 연속 기록](#보류-연속-기록)에 둔다.

### 왜 데이터를 바꾸는가

삭제의 직접 계기는 2026-10-23 세션의 자이로 환산 불일치(펌웨어 ±2000 dps, 앱 ±1000 dps 환산)로 자이로가 실제의 절반으로 기록됐을 가능성이었다(실측 확정은 안 함). 그 전의 10-21 세션도 다시 쓰지 않는 이유는 아래와 같다. 실험 1~5에서 모델·라벨·입력 길이·구조를 바꿔도 결론이 모두 "구분 불가"로 끝났고, 그 원인이 대부분 데이터 쪽에 있었다. 단, BLE-01~07a는 정식 실험이 아니라 코드 동작 확인용 테스트였으므로(2026-10-25 사용자 확인) 아래 수치는 수집 형식의 문제를 찾은 참고 자료로만 쓴다.

| 드러난 한계 | 근거 | 새 수집에서 바꾸는 것 |
|---|---|---|
| 수집 형식이 바뀌었다 | 삭제한 세션(10-21, 10-23)은 모두 3초(300행)·동작 신호 500 ms·±1000 dps 환산. 커밋 `5600c45`(10-21 09:43)부터 4초(400행)·1초·±2000 dps | 새 형식만 쓴다. 두 형식을 섞으면 클립 길이·자이로 범위 차이가 조건 차이와 섞인다 |
| 자이로 포화 | `raw_up.1` 최대 1002 dps로 ±1000 한계에 닿아 제외([데이터 검토](experiments/ble-v1/01-data-review.md)) | ±2000 dps. `near_gyro_limit` 플래그 수를 기록 |
| 정답 창이 버퍼 준비에 잘림 | 첫 판정이 1590 ms인데 완료가 1270·1420 ms인 2개는 양성 0창으로 제외, 훈련 4·검증 2개는 1창만 남아 2회 연속 발행 조건을 원리상 못 채움([실험 1](experiments/ble-v1/실험1_진행기록.md), [실험 4](experiments/ble-v1/실험4_진행기록.md)) | 동작 신호를 1초로 늦췄다. 기록에 남은 10-21 완료 시각 예(1270~1830 ms)는 신호 뒤 약 0.8~1.3초였으므로 새 완료는 1590 ms 뒤로 예상되나 미확인. 원본별 양성 창 수를 수집 직후 확인 |
| 검증이 8동작·같은 세션 | seed만 바꿔도 정검출 0~3/8([실험 2](experiments/ble-v1/실험2_진행기록.md)). 비교 4번 모두 조건 효과가 seed 차이 안에 묻힘 | 자세별 세션 5개, 방향별 원본 75개로 확대, 평가용 60개(두 방식) |
| 검증 창의 96.5%가 NONE | val_loss 최저가 epoch 1에 나와 방향을 못 내는 모델이 선택됨([실험 1](experiments/ble-v1/실험1_진행기록.md), [실험 5](experiments/ble-v1/실험5_진행기록.md) GAP) | 고정 epoch(개발 평가 v2) 유지. 방향 원본 수를 늘려 양성 창 비중을 키운다 |
| 배경이 60초뿐 | 검증 배경은 같은 20초(판정 16.82초) 하나를 매번 반복했다. 발행 0회였지만 모델들이 방향 clip에서도 발행이 적어(정검출 0~3/8) 오작동률 근거가 안 됨 | idle/other를 세션마다, 헷갈리는 동작 위주로 |
| 연속 자료 없음 | 라벨 폭(150/300 ms)의 정식 선택 보류([실험 3](experiments/ble-v1/실험3_진행기록.md)), 실험 7b 미실행 | 이번에도 수집하지 않는다(보류). 라벨 폭·후처리는 clip 기준으로만 정하고, 연속 사용 성능은 주장하지 않는다 |
| 완료 시각이 센서 기반뿐 | `raw_down.1`·`raw_up.3`이 완료 60~90 ms 전에 반복 발행됐지만 주석 오차인지 모델 문제인지 가를 근거가 없음(실험 2·3) | 이번에는 해결하지 않는다(연속 기록 보류). 완료 시각은 지금처럼 센서 기반 후보와 REVIEW 확인으로 정한다 |
| 재착용·자세 변화 없음 | 방향 세션 2개, 최종 평가만 세션 분리 | 자세 5개를 세션으로 나눠 모은다. 착용 각도는 증강으로 다룬다 |

실험 1~5에서 바꾼 것과 결과(검증 방향 8동작, 3 seed 평균)는 다음과 같다.

| 실험 | 바꾼 것 | 정검출/8 (기존 → 변경) | 미매칭 발행 (기존 → 변경) | 결정 |
|---|---|---|---|---|
| [1](experiments/ble-v1/실험1_진행기록.md) | 무증강 기준선 | 0 (seed 1개) | 0 (발행 자체 없음) | 기준으로만 보존 |
| [2](experiments/ble-v1/실험2_진행기록.md) | class weight | 1.33 → 2.00 | 2.67 → 6.67 | 미채택 |
| [3](experiments/ble-v1/실험3_진행기록.md) | 훈련 라벨 폭 150 → 300 ms | 0.67 → 1.67 | 0.33 → 5.00 | 미채택 |
| [4](experiments/ble-v1/실험4_진행기록.md) | 입력 160 → 120행 | 1.33 → 1.67 | 2.67 → 4.00 | 미채택 |
| [5](experiments/ble-v1/실험5_진행기록.md) | Flatten → GAP | 1.33 → 0 | 2.67 → 0 (발행 없음) | 미채택 |

같은 기존 조건도 seed에 따라 정검출이 0~3/8로 달랐다. 변경마다의 차이가 이 범위 안이라, 미채택은 "효과 없음"이 아니라 "이 데이터로는 가를 수 없음"이다. 모델 쪽을 더 바꿔도 같은 8동작·같은 세션·잘린 정답 창으로는 판단이 나아지지 않으므로, 다음 단계를 모델 변경이 아니라 데이터 재수집으로 정했다. 이 테스트들의 채택/미채택 결정(개발 후보 B 포함)은 이어받지 않고, 정식 비교는 새 데이터로 다시 한다.

### 세션 진행 방법

자세를 바꿀 때마다 **세션 종료** 후 새 세션으로 시작한다. 한 세션 안의 순서는 다음과 같다.

1. **수집 전:** 세션 메모에 자세(P1~P5)를 적는다. 네 방향의 손가락 동작은 첫 세션 전에 손가락 기준으로 한 문장씩 정하고 모든 세션에 같은 문장을 쓴다. 10-23 세션에서 right 3개가 다른 회전 축(Z-, Y+)으로 시작했다. 세기·속도는 다양하게 하되 같은 방향은 같은 움직임으로 한다.
2. **방향 안내 수집(방향별 15회):** 앱의 방향별 횟수를 15로 바꾼다(기본 10). "삐빅" 신호 전에는 움직이지 않는다. 이동 후 자연스럽게 복귀하고 가만히 있는다. 잘못하면 **방금 것 다시**를 누른다.
3. **idle 10초 × 3:** 그 세션의 자세 그대로 가만히 있는다.
4. **other 10초 × 5:** 그 세션의 자세에서 10초 동안 가만히 있기와 명령이 아닌 여러 움직임을 섞는다(2026-10-25 사용자 설계 확인. 클립 하나에 동작 하나가 아니다). 넣을 움직임 예: 엄지 스틱 누르기·밀기(같은 반지라 IMU가 함께 움직임), 이불 정리, 머리 긁기, 돌아눕기, 거치대로 손 뻗기·손가락 굽히기. 클립 전체가 NONE이며 학습 때는 창으로 잘라 모두 쓴다.
5. **세션 종료:** 메모에 자세와 착용 손가락을 확인하고 종료한다.

### 분할

평가용을 떼는 방식 두 가지를 모두 해 보고 비교한다(2026-10-25 사용자 결정). 방식마다 모델을 따로 학습한다. 모델 학습은 팀원이 한다.

| | 방식 S: 세션 통째로 | 방식 C: 세션마다 일부 |
|---|---|---|
| 평가용 방향 | 세션 P5(돌아누워 팔을 꺾지 않음)의 60개 전부 | 세션×방향마다 3개(20%), 세션당 12개, 합계 60개(방향별 15) |
| 평가용 배경 | 그 세션의 idle 3개·other 5개(80초) | 세션마다 idle 1개·other 1개, 합계 10개(100초). 창이 서로 겹치므로 창 단위가 아니라 클립 단위로 뗀다 |
| 학습·개발용 방향 | 나머지 4세션의 240개 | 나머지 240개(다섯 세션 모두 포함) |
| 평가가 보여주는 것 | **학습에 없던 세션(자세)**에서의 성능 | **학습에 있던 세션(자세)**에서의 성능 |

- 두 방식 모두 학습용 약 240개·평가용 약 60개로 양이 비슷하다. 그러나 다른 것은 평가 세션이 학습에 들어갔는지만이 아니다. 평가 클립·배경의 구성(S는 P5뿐, C는 다섯 세션 혼합)도 다르다.
- 두 점수는 서로 다른 질문의 답이다. 어느 방식이 "맞는지"를 가리는 비교가 아니다. C − S 차이는 **새 자세·세션에 대한 일반화 문제의 단서**로 읽는다. 세션 하나가 자세 하나이므로 자세와 함께 수집 시각·착용 상태 등 세션 차이가 섞여 있어, **자세만의 효과로 분리한 값이 아니다**(2026-10-25 검토 반영).
- 방식 C는 평가 클립과 같은 세션(같은 자세·착용·시간대)의 다른 클립이 학습에 들어가므로 낙관적일 수 있다. 실사용도 이 다섯 자세 근처라 쓸모는 있으나 보고할 때 이 점을 적는다.
- 방식 S는 어느 세션을 빼느냐에 따라 결과가 크게 달라질 수 있다. 예를 들어 P1(앉음)은 다른 자세와 중력 방향이 크게 달라 빼면 성능이 크게 떨어져도 이상하지 않다. 그래서 다음을 따른다.
  - 공식 S 평가 세션은 **P5(돌아누워 팔을 꺾지 않음)**로 수집 전에 정했다(2026-10-25 사용자 결정). 비슷한 P4(돌아누워 팔을 꺾음)가 학습에 남아 있어, 동떨어진 자세를 뺄 때보다 중간 자세 일반화를 가늠하기 좋다. 결과를 보고 바꾸지 않는다.
  - 다섯 세션을 하나씩 돌아가며 빼는 5회 반복을 **기본으로 한다**(2026-10-25 검토 반영, 처음에는 선택이었음). 같은 평가 데이터에 seed만 바꾸는 반복은 학습 무작위성만 보여 주고, 평가 세션이 바뀔 때의 변동은 보여 주지 않기 때문이다. 공식 S 결과는 P5로 두고, 세션별 결과와 평균·범위를 함께 보고한다.

**공통 규칙**

- 평가용 분할은 **수집 직후·학습 전**에 정한다. 방식 C는 실제 남은 파일 목록에서 고정 seed로 세션×방향마다 3개를 뽑는다. 두 방식의 분할표를 각각 저장한 뒤 바꾸지 않는다. "방금 것 다시"로 지운 번호는 다시 쓰지 않아 번호가 비므로 번호로 미리 정하지 않는다. 세기는 기록하지 않으므로 세기별로 맞추지 않는다.
- 평가용은 모델·문턱·epoch를 고를 때 열지 않는다. 그런 선택은 각 방식의 학습용 240개 안에서 개발 평가 v2(원본 클립 단위 교차검증·고정 epoch·seed 5개)로 한다. 두 방식에 같은 절차를 쓴다. 방식 S의 교차검증 fold는 세션 단위(4개)로, 방식 C는 클립 단위로 세션×방향 비율을 맞춰 나눈다.
- 모델 구조·입력·라벨·증강·학습 설정·seed는 두 방식에 똑같이 둔다. 바꾸는 것은 평가용을 떼는 방식뿐이다.
- 평가용에는 학습한 모델을 **한 번만** 적용한다. 평가 결과를 보고 설정을 바꾸면 그 자료는 더 이상 평가용이 아니다.
- 보고: 방식별 정검출률, 미매칭 발행(조기·방향 오류·중복·늦은 발행), 배경 오발행(분당), 방향별·자세별 결과표. 5개 seed의 seed별 값과 평균·범위로 쓴다. 분모와 형식은 [BLE v2 실험의 보고](#보고)를 따른다.
- 기존 `ble-v1-cv5.json`의 원본 35개 배정은 재사용하지 않는다.

### 착용 각도 증강 계획

반지가 손가락 둘레로 돌아간 각도는 수집에서 통제하지 않고 증강으로 다룬다(2026-10-25 사용자 결정). 실행 전 계획이다.

- 손가락 길이 방향과 나란한 IMU 축을 먼저 정해야 한다. 보드가 반지에 붙은 방향으로 정해지며 아직 확인하지 않았다.
- 그 축을 중심으로 작은 각도만큼 돌린 회전을 가속도와 자이로에 **똑같이** 적용한다. 각도 범위는 축을 확인한 뒤 정한다.
- 정지 구간의 중력 방향으로 착용 각도를 되돌리는 후처리는 쓰기 어렵다. 중력 방향은 자세에 따라서도 바뀌어 착용 각도와 구분되지 않는다.
- 평가용이 학습과 같은 착용에서 나오므로, 이 증강의 효과는 이번 평가로 확인되지 않는다.

### 보류: 연속 기록

2026-10-25 사용자 결정으로 이번 재수집에서 뺐다. 앱의 연속 기록 버튼(정답 없이 센서만 저장)은 그대로 있지만 이 계획에서는 쓰지 않는다. 그 결과 아래 항목은 계속 미해결이다. 이번 데이터로 낸 결과는 clip 기준으로만 보고한다.

- 라벨 폭(실험 3)의 정식 선택, 후처리의 연속 검증(실험 7b)
- 빠른 반복·다른 움직임 직후의 명령, 재무장 동작
- 실사용 오작동률

재검토할 때 볼 것(같은 날 검토 내용):

- **정답 남기는 법:** 자유 동작+메모, 표시 버튼, 영상 동기화, 앱 지시를 비교했고 앱 지시(무작위 간격으로 방향을 지시하고 지시 시각·방향을 파일로 남김)가 가장 현실적이었다. 앱 구현은 시작했다가 되돌렸다(커밋하지 않음).
- **앱 지시의 한계:** 방향 음성이 먼저 나오면 사용자가 하던 움직임을 멈추고 기다리게 되어, 명령이 클립처럼 "정지 → 동작" 모양이 되기 쉽다. 지시 간격이 일정하면 타이밍도 예측된다. 지시 사이의 일상 동작은 실제 생활이 아니라 연기다.
- **오작동률은 따로:** 세션당 3~5분으로는 명령 아닌 구간이 개발용 합계 약 12분이다. 이 동안 오발행이 0회여도 95% 상한이 약 15회/시간이라 근거가 약하다. 명령 없이 실제로 생활하며 30~60분 착용한 기록이 더 낫다. 이 기록에서 나온 발행은 모두 오발행이므로 라벨이 필요 없다.
- **보완 아이디어:** 명령이 아닌 동작("스틱", "긁기")도 지시해 NONE으로 남긴다. 음성이 나와도 하던 움직임을 이어가도록 안내한다. 음성과 삐빅 사이 간격을 무작위로 바꾼다.

## BLE v2 실험 — 평가 방식 S/C 비교 (2026-10-25)

실행 전 계획이다. 자세별 5세션([재수집 계획](#재수집-계획--2026-10-25))으로 하는 첫 정식 실험이다. 기록은 [BLE v2 실험 기록](experiments/ble-v2/README.md)에 남기고 실행 ID는 `V2-…`로 쓴다. BLE v1(테스트) 결과·결정은 이어받지 않는다.

이 절과 아래 v1 절(입력 생성부터 구현 순서까지)이 다르면 이 절을 따른다. "개발 평가 v2"는 v1에서 정한 평가 규칙(교차검증·고정 epoch·seed 5개)의 이름이며, 이 실험은 그 규칙을 새 데이터에 맞게 적용한다.

### 질문

무증강 기준선을 같은 설정으로 학습했을 때, **세션 전체를 빼는 평가(S)**와 **세션 안에서 클립을 나누는 평가(C)**에서 clip 성능이 얼마나 달라지는가.

- 방식 S(P5 통째로)는 **학습에 없던 세션(자세)**, 방식 C(세션마다 일부)는 **학습에 있던 세션(자세)**의 성능이다.
- C − S 차이는 새 자세·세션에 대한 일반화 문제의 단서로 읽는다. 자세와 세션(수집 시각·착용 상태)이 함께 바뀌고 평가 구성도 달라서 **자세만의 효과로 분리한 값이 아니다.** 어느 방식이 "맞는지"를 가리는 비교도 아니다([분할](#분할)).
- 평가 세션이 바뀔 때의 변동을 보려고 방식 S는 P1~P5를 돌아가며 빼는 5회를 모두 한다(공식 결과는 P5).
- 모델 학습은 팀원(조현준)이 한다. 요청 배경은 2026-10-25 팀원 대화(장기정): 세션 통째 평가만으로는 학습하지 않은 자세를 추론할 수 있는지 의문이라 방식 C를 추가했다.

### 데이터 처리 순서(누수 방지)

학습 집합(최종 학습)과 교차검증의 각 fold에 똑같이 적용한다.

1. **원본 클립을 먼저 나눈다.** 평가용/학습용, 그리고 학습용 안의 fold를 원본 클립 단위로 정한다. 같은 원본에서 나온 창은 절대 서로 다른 쪽에 들어가지 않는다.
2. **그다음 창을 만든다.** 원본마다 160행 창을 50 ms 간격으로 만든다. 파일 경계를 넘어 붙이지 않는다.
3. **정규화 통계는 학습 부분만으로 계산한다.** 교차검증에서는 fold마다 그 fold의 학습 부분 원본만으로 다시 계산한다. 학습용 전체로 한 번 계산한 값을 fold 안에서 쓰지 않는다. 최종 학습은 학습용 전체로 계산한다. 계산한 값을 검증·평가 창에 그대로 적용한다.
4. **NONE 추출은 학습 부분에만 한다.** 검증·평가는 모든 판정 시각을 그대로 replay한다.
5. 학습·검증 손실 외에 검증·평가 데이터에서 계산한 어떤 값도 학습 설정에 쓰지 않는다.

### 발행·채점 protocol

결과를 바꾸는 조건이므로 학습 전 protocol 파일에 그대로 적는다. 현재 `ml/baseline.py`의 `issue_events()`·`classify_events()` 동작을 문서로 고정한 것이다.

- **판정 시각:** 원본의 시작부터 160행이 찬 첫 시각(1590 ms)부터 5행(50 ms)마다. 그 전 구간은 판정하지 않으며 앞을 가짜 값으로 채우지 않는다.
- **발행 시각:** 발행 조건을 처음 만족한 판정 시각(2회 연속 중 두 번째 창의 마지막 샘플 시각).
- **초기 상태:** 원본마다 잠금 해제·후보 없음으로 시작한다. 원본 사이에 상태를 넘기지 않는다.
- **완료 시각 e는 발행에 쓰지 않는다.** 발행과 재무장은 모델 점수와 고정 규칙으로만 진행하고, e는 정답 라벨과 사후 채점에만 쓴다.
- **분류 우선순위:** 발행 하나를 다음 순서로 처음 해당하는 것으로 분류한다. 배경 원본 → 배경 오발행, t < e → 조기, t > e+500 ms → 늦은 미매칭, 다른 방향 → 방향 오류, 이미 정검출이 있음 → 중복, 그 밖 → 정검출. 정검출이 없는 방향 원본은 누락 1회.
- **허용 구간이 클립 끝에서 잘리는 경우:** 마지막 판정이 3990 ms이므로 e > 3490 ms이면 e+500 ms까지 관측하지 못한다. 이 원본은 그대로 채점하되(관측 범위 안에 정검출이 없으면 누락) 목록을 따로 남기고 결과표에 표시한다. e > 3890 ms이면 양성 창도 3개가 안 된다.

### 분할 개수(제외 5개 반영)

수집 후 남은 방향 클립은 P1 58, P2 60, P3 59, P4 60, P5 59, 합계 296개다(`excluded/` 5개 제외). 배경은 세션마다 idle 3·other 5다.

| | 방식 S | 방식 C |
|---|---|---|
| 평가 방향 | P5 전체 59개(UP14·DOWN15·LEFT15·RIGHT15) | 세션×방향마다 3개, 60개(방향별 15·세션별 12) |
| 평가 배경 | P5 idle 3·other 5(80초) | 세션마다 idle 1·other 1(10개, 100초) |
| 학습 방향 | P1~P4 237개 | 나머지 236개(다섯 세션 모두) |
| 학습 배경 | P1~P4 32개(320초) | 나머지 30개(300초) |
| 보정 교차검증 | 세션 단위 4 fold(P1~P4 각 1 fold). 배경도 세션을 따른다 | 클립 단위 5 fold. 세션×방향·세션×배경 종류마다 고르게 나눈다 |

- 방식 C 평가용은 각 세션 폴더에 실제로 남은 파일 목록을 이름순으로 정렬하고 seed 20261021로 세션×방향마다 3개, 세션×종류마다 idle 1·other 1을 뽑는다. 번호로 미리 정하지 않는다("방금 것 다시"로 번호가 빈다).
- 교차검증 fold 배정도 같은 seed로 학습 전에 한 번 정한다.
- 평가 방향 수가 59/60으로 다르므로 비교는 개수가 아니라 비율(정검출률 등)로 한다.

### 절차

**0. 코드·환경 준비** (2026-10-25 완료. 결과는 [V2-prep 기록](experiments/ble-v2/README.md#v2-prep-기록))

- 이 PC에 `ml/.venv`(Python 3.12, `ml/requirements.txt`)를 만든다. TensorFlow·Keras·NumPy 버전을 실행마다 기록한다.
- `ml/baseline.py`는 v1(3초) 전용이라 그대로 못 쓴다. 바꿀 곳: 고정된 세션 이름(`OLD`·`NEW`·`BG`) → 세션 목록, 방향 300행 검사 → 400행, `positive_count()`의 판정 범위(3000 → 4000 ms), 신호 전 NONE 경계(500 → `pre_roll_cue_ms`), 주석·분할 경로(`ble-v1` → `ble-v2`). v1 실험 스크립트(`experiment*.py`)는 고치지 않고, v2 학습·평가는 새 스크립트로 둔다. 시간 경계·후처리·매칭 테스트를 400행 기준으로 다시 통과시킨다.
- 구현: `ml/v2.py`(데이터·창·분할·채점·fold 학습·protocol), `ml/test_v2.py`. 발행·채점·NONE 추출 함수는 v1 동작을 옮기고 테스트가 v1 함수와 같은 결과를 내는지 비교한다. 보정 반복(seed×fold×E)과 최종 학습·평가 실행기는 아직 없다(V2-cal 단계에서 작성).

**1. 완료 주석 저장** (2026-10-25 완료)

- `tools/suggest-gesture-completions.js --local-dir`로 다섯 세션의 완료 후보를 만들어 `data/annotations/ble-v2/`에 세션별로 저장한다. 2026-10-25 수집 때 도구를 돌렸지만 산출 파일은 저장되지 않았다.
- `excluded/`의 5개는 그대로 뺀다. 남은 REVIEW 클립은 파형 검토로 남긴 것이므로 자동 완료 시각을 정답으로 쓴다. 모델 결과를 본 뒤에는 주석·제외를 바꾸지 않는다.
- 원본별 양성 창 수를 센다. 3창 미만이나 0창 원본은 목록으로 남기고, 학습에서 빼지 않되 결과표에 따로 표시한다. 판정 시각이 1590 ms부터 50 ms 간격이므로 완료가 3890 ms보다 늦으면 3창이 안 된다.
- 원본 SHA-256 목록을 함께 저장한다.

**2. 분할·protocol 고정(학습 전)** (2026-10-25 완료)

- 분할 6개를 `data/splits/`에 저장했다: `v2-C.json`, 방식 S의 `v2-S-P1.json`~`v2-S-P5.json`(공식 S는 `v2-S-P5.json`, 나머지 넷은 회전). 평가용·학습용 원본 경로와 교차검증 fold가 들어 있다. 저장한 뒤 덮어쓰지 않는다.
- 학습 전에 `docs/experiments/ble-v2/results/protocol.json`에 분할 해시, 고정 조건, 데이터 처리 순서, 발행·채점 protocol, E 후보와 선택 점수·규칙, 보고 형식을 시각과 함께 저장한다.

**3. 보정: 고정 epoch E 정하기(방식마다)**

- 학습용 안에서만 한다. 평가용은 열지 않는다.
- E 후보 {1, 5, 10, 20, 30, 40, 60}. v1에서 val_loss 최저가 epoch 1이었다는 것만으로 이른 epoch가 나쁘다고 볼 수 없으므로 이른 후보도 넣는다(2026-10-25 검토 반영).
- (seed, fold)마다 한 번 60 epoch까지 학습하고, 각 후보 epoch가 끝난 시점의 가중치를 저장해 검증 fold를 replay한다. 학습률 스케줄이 없는 Adam .001 고정이라, 같은 seed면 E epoch에서 멈춘 별도 학습과 같은 가중치다. 학습은 S 4 fold × 5 seed = 20회, C 5 fold × 5 seed = 25회이고, 평가하는 후보 모델은 각각 140개·175개다.
- **선택 점수(seed마다):** 그 seed의 모든 fold 검증 예측을 합쳐 (정검출 수 − 방향 원본에서 나온 미매칭 발행 수) ÷ 검증 방향 원본 수. 배경 오발행은 점수에 넣지 않고 따로 보고한다. 배경이 fold당 수십 초뿐이라 동작 지표와 섞을 가중치를 정할 근거가 없기 때문이다.
- **선택 규칙:** 5 seed 점수의 평균이 가장 큰 E. 같으면 작은 E. 방식마다(그리고 S 회전마다) 이 **같은 선택 원칙**으로 따로 정하므로, 방식 간에 E 값이 다를 수 있다. 이 경우 결과는 "같은 설정값"이 아니라 "같은 선택 원칙"을 적용한 비교라고 쓴다.
- 보정 결과(E별 seed 평균·범위, 배경 오발행 포함)는 그대로 보고한다. 이 단계의 교차검증 성능은 평가 결과가 아니다.

**4. 최종 학습**

- 방식마다 학습용 전체로 정규화를 다시 계산하고, 정한 E로 5 seed 모델을 만든다(합계 10회).

**5. 평가(한 번)**

- 각 방식의 5개 모델을 그 방식의 평가용에 한 번 적용한다. 결과를 보고 설정·주석·분할을 바꾸지 않는다. 바꾸면 그 평가용은 개발용이 되고, 새 평가 자료가 필요하다.

**6. 방식 S 회전(기본)**

- 공식 S는 P5다. P1~P4도 하나씩 평가용으로 빼서 같은 절차(분할 고정 → 남은 4세션의 세션 단위 보정 → 최종 학습 → 평가 한 번)를 반복한다. 평가 세션이 바뀔 때의 변동을 보기 위해서다(2026-10-25 검토 반영으로 선택에서 기본으로 올림).
- 회전마다 보정 20회 + 최종 5회 = 25회 학습이다. P1~P4 추가분은 100회다. 공식 P5와 방식 C를 합친 전체는 155회다.
- 각 회전의 분할표(`v2-S-P1.json` 등)도 학습 전에 고정한다. 공식 결과(P5)를 회전 결과로 바꾸지 않는다.

### 해석(기술 보고)

- 통계적 판정 규칙을 두지 않는다. 처음 넣었던 "5 seed 같은 부호 + 보정 seed 범위보다 크면 차이 있음" 규칙은 검증된 기준이 아니어서 뺐다(2026-10-25 검토 반영). seed는 학습 무작위성만 바꾸고, 교차검증 fold끼리는 학습 데이터가 겹쳐 독립이 아니므로 그 범위로 차이의 확실성을 판단할 수 없다.
- 대신 차이의 크기, seed별 일관성(5 seed 중 몇 개에서 C > S인지), S 회전에서 세션별로 얼마나 흩어지는지를 그대로 쓴다.
- S 회전의 세션별 값이 크게 흩어지면, P5 하나의 S 값이나 C − S 하나로 결론 내리지 않는다.
- 정검출이 두 방식 모두 낮으면 평가 방식 차이보다 기준선 자체의 문제로 보고 v1 실험 2·4·5 같은 단일 요인 비교를 따로 계획한다.
- 어느 경우에도 "자세 효과"로 단정하지 않는다. 자세와 세션이 함께 바뀐 결과다.

### 하지 않는 것·한계

- 증강, 문턱 튜닝, 구조·입력 길이·라벨 폭 변경은 하지 않는다.
- 결과는 4초 clip replay 기준이다. 연속 사용, 빠른 반복 명령, 실사용 오작동률은 주장하지 않는다. 배경은 방식별 80~100초뿐이다.
- 착용 각도는 통제하지 않았고 평가용도 같은 착용이다. 재착용 일반화는 이번 평가로 알 수 없다.
- 방식 C는 같은 세션의 다른 클립이 학습에 들어가 낙관적일 수 있다. 공식 방식 S는 P5 한 세션의 결과이며, 회전 결과도 세션 5개뿐이다.
- 자세와 세션이 1:1이라 자세 효과와 세션 차이(수집 시각·착용 상태·피로)를 나눌 수 없다.
- 완료 시각은 센서 기반 자동 후보이며 독립 확인이 없다.
- 사용자 1명, 같은 날 연속 수집이다.

## 입력 생성과 라벨 정책

> 여기부터 "구현 순서"까지는 BLE v1(3초 클립, 테스트) 기준이다. v2에서 달라진 값은 위 [BLE v2 실험](#ble-v2-실험--평가-방식-sc-비교-2026-10-25) 절을 따른다.

판정 시각 t는 마지막 실제 샘플 timestamp다. 삭제된 이전 exporter의 `end * 10` 기준은 마지막 행보다 10 ms 크므로 입력 생성과 replay 구현 시 맞춘다. 3초 방향 파일과 10초 idle/other 파일을 모두 160행씩 자르며 파일 경계를 넘어 붙이지 않는다.

방향 목표는 자연 복귀 완료 e부터 `e <= t < e + 150 ms`이고 나머지는 NONE이다. idle/other는 실제 명령 동작이 없는지 검토한다. 준비 시간이 부족하거나 양성 구간이 기록 끝에서 잘린 이벤트는 별도 표시하고 유효 양성 창 수와 평가 불가 이벤트 수를 보고한다.

2026-10-21 사용자가 원하는 명령 시점은 자연 복귀가 끝난 뒤로 확인했다. 따라서 완료 전 발행을 목표로 하는 안은 현재 명령 정책 후보에서 제외한다. 완료 시점 방식의 최적성이 입증된 것은 아니며, 완료 후 라벨 폭과 발행 안정성은 별도 비교한다. [실험 3](experiments/ble-v1/실험3_진행기록.md)의 150/300 ms 훈련 라벨 사전 비교는 완료했지만, 완료 시각의 독립 검토와 개발용 연속 자료를 통한 정식 정책 선택은 아직 필요하다. 복귀 중 목표는 NONE으로 유지한다.

## 학습 설정과 분할

아래 값은 첫 실행 설정이며 최적값 또는 성능 보장이 아니다.

| 항목 | 초기값 |
|---|---|
| Optimizer | Adam, learning rate=0.001 |
| Loss | sparse categorical crossentropy |
| Batch size | 16 |
| 최대 epoch | 100 |
| 조기 종료 | BLE-01~05: val_loss, patience=12, 최저 val_loss 가중치 복원. BLE-06부터: 사용하지 않고 고정 epoch E([개발 평가 v2](#개발-평가-v2--ble-06부터)) |
| Seed | BLE-01~05: 20261021(비교는 20261021~23). BLE-06부터: 20261021~25; 라이브러리 버전·실행 환경도 기록 |
| 증강 | 없음 |
| 훈련 NONE 추출 | 총 방향 양성 창 수와 비슷한 수를 고정 추출 |

NONE은 idle/other뿐 아니라 방향 파일의 시작·진행·완료 후 구간에서 골고루 뽑는다. 후보가 부족한 종류는 실제 개수를 기록한다. 우선 class weight 없이 시작하고, 검증 replay의 오작동·누락을 보고 NONE 수나 loss 가중치 중 한 가지씩 조정한다. 추출로 달라진 클래스 비율 때문에 softmax 점수를 실제 환경의 확률로 해석하지 않는다.

검증·평가는 NONE을 줄이지 않고 원본 전체를 replay한다. 창 정확도만으로 모델을 선택하지 않는다.

방향과 NONE의 혼동이 있으면 먼저 잘못 판정한 시각과 완료 e·양성 종료 e+150 ms 사이의 거리를 확인한다. 경계 집중이 확인되면 학습에서만 작은 경계 무시 구간을 비교하고, 최종 평가는 경계까지 모두 포함한다. 150 ms 양성 구간에 양쪽 ±100~200 ms 제외를 일괄 적용하지 않는다. 완료 정답의 주석 오차와 유효 양성 창 수를 함께 확인하며, 라벨 경계가 원인이라고 사전에 확정하지 않는다.

원본을 먼저 분할한 뒤 창을 만든다. 첫 방향 세션 `phone-20261021-091621`의 방향별 5회는 최종 평가로 보류하고, `phone-20261021-094346`의 방향별 10회는 훈련 8회/검증 2회로 고정 분리하는 안을 사용한다. 주석 검토에서 제외된 샘플이 나오면 각 분할의 실제 유효 수를 기록한다. 평가 세션의 REVIEW는 훈련용으로 빼지 않고 정답 검토 후 평가 가능 여부를 기록한다.

idle/other는 종류별 3개 원본을 훈련/검증/평가에 1개씩 배정하고 원본 경로를 목록으로 저장한다. 배경 세션은 둘뿐이므로 이 배정은 세션 전체를 분리한 배경 일반화 시험이 아니다. 같은 원본에서 나온 모든 창은 반드시 한 분할에만 둔다. 향후 증강을 추가해도 부모 원본의 분할을 상속한다.

최종 평가 자료로 threshold나 모델을 반복 선택하지 않는다. 테스트 결과를 보고 수정하면 그 자료는 개발 평가 자료로 역할이 바뀌며 새 최종 평가 녹화가 필요하다.

원본·증강 부모 그룹을 보존한 validation으로 모델과 문턱을 선택한다. validation을 일괄 배제하고 testing으로 계속 튜닝하지 않는다. 기준선 이후 비교가 필요하면 원본 분할·정규화·라벨·후처리를 고정하고 증강 유무×얕은/깊은 구조의 2×2를 같은 seed 집합으로 각각 2~3회 이상 반복한다. 비교·선택은 validation에서 하며, 평균·범위와 원본별 성공 여부를 보고한다. 무작위 초기화 변동과 녹화 조건 변동은 구분한다.

## 개발 평가 v2 — BLE-06부터

2026-10-21 실험 1~5 검토 후 정했다. BLE-01~05의 결과와 결정은 그대로 보존하고, 아래 규칙은 실험 6 이후에만 적용한다. 두 방식의 수치를 서로 직접 비교하지 않는다.

### 바꾸는 이유

BLE-01~05의 비교 네 번이 모두 미채택이었다. 하지만 조건 차이보다 seed 차이가 더 컸다. 기록된 실행을 모으면 선택 epoch와 정검출 수가 함께 움직인다.

| 선택 epoch | 정검출/8 (해당 실행) |
|---|---|
| 1 | 0 (BLE-01-r03, 02-r01, 03-r01, 04-r01, 04-r02, 05-r01, 05-r02, 05-r04) |
| 3 | 0, 1, 0 (03-r03, 03-r04, 05-r06) |
| 6~10 | 1~3 (02-r02~r06, 03-r02, 03-r05, 03-r06, 04-r03, 04-r05) |
| 15~16 | 2, 3 (04-r04, 04-r06) |

02-r01·04-r01·05-r01은 BLE-01-r03을, 04-r03·04-r05는 02-r03·02-r05를 같은 조건으로 재현한 실행이므로 독립 표본이 아니다. 검증 창의 96.5%가 NONE이라 val_loss 최저점이 학습 초기에 나오기 쉽다. 그러면 조건 효과와 학습량 효과가 섞인다. 실험 4의 120행은 epoch 15~16, 160행은 7~8을 골랐다. 또 같은 검증 8동작에 "어느 seed도 악화 없음"을 요구하는 규칙에서는 어떤 변경도 통과하기 어렵다. 따라서 BLE-01~05의 미채택은 "효과 없음"이 아니라 "이 조건에서는 구분 불가"로 해석한다. 이 관찰은 상관이며 원인을 확정한 것은 아니다.

### 원본 단위 5-fold 교차검증

- 대상: 기존 훈련+검증 방향 원본 35개(UP8/DOWN10/LEFT9/RIGHT8)다. 최종 평가 보류 22개와 제외 5개는 그대로 둔다.
- fold: 원본 단위로, 방향별 개수를 최대한 고르게 5개 fold에 나눈다. fold당 방향 원본은 약 7개다. 배정은 학습 전에 seed 20261021로 한 번 정하고 `data/splits/ble-v1-cv5.json`에 새 버전으로 저장한다. 기존 `ble-v1.json`은 덮어쓰지 않는다.
- 배경: 원본이 4개뿐이라 fold로 나누지 않는다. 모든 fold에서 훈련 배경은 09:43 idle/other, 검증 배경은 09:33의 .1을 쓴다. 배경 결과는 fold마다 같은 20초를 반복 측정한 것이므로 관측 시간을 더하지 않는다.
- fold마다 다시 계산하는 것: 정규화 계수(그 fold 훈련 원본만), NONE 추출(기존 규칙), 증강(훈련 원본에만).
- 결과: seed마다 5개 fold의 검증 예측을 합쳐 방향 동작 35개를 한 번씩 평가한다.

### 고정 epoch

- val_loss 조기 종료와 최저 가중치 복원은 쓰지 않는다. val_loss는 기록만 한다.
- E는 실험 6 시작 전 보정 단계(BLE-06-cal)에서 정한다. 기준 구조(160행, 150 ms, Flatten, 무증강)만 사용한다. E ∈ {10, 20, 30, 40, 60}을 5 fold × 5 seed로 학습한다.
- E 선택 규칙: seed별 합산 (정검출 − 미매칭 발행)의 평균이 가장 큰 E를 고른다. 같으면 더 작은 E를 고른다. 이 규칙은 보정 실행 전에 protocol 파일로 고정한다.
- 정한 E는 실험 6~8의 모든 조건에 같게 적용한다. 증강 조건은 epoch당 표본 수가 늘어나므로, 같은 E에서 갱신 횟수가 달라진다는 점을 함께 기록한다.

### 결과 판정

- seed는 20261021~25의 5개다. 조건 간에 같은 seed와 fold를 짝지어 비교한다.
- 주 지표: seed별 합산 정검출/35, 미매칭 발행(조기·방향 오류·중복·늦은 발행·배경 발행)과 조기 발행이다. 원본×seed 성공표도 남긴다.
- 판정은 세 가지로 나눈다. 아래 수치 기준은 보정 단계의 기준 구조 seed 범위를 본 뒤, 실험 6 protocol에 고정한다.
  - **개발 후보:** 평균 정검출이 늘고, 5 seed 중 4개 이상에서 정검출이 늘며, 평균 미매칭 발행이 늘지 않는다.
  - **악화:** 반대 방향으로 같은 조건을 만족한다.
  - **판단 불가:** 그 밖의 경우다. 기존 설정을 유지하되 결정 기록에는 판단 불가로 쓴다.
- 보조 보고: 완료 e 직전 0~100 ms의 조기 발행을 따로 센다. 센서 기반 완료 주석의 오차 범위를 보기 위한 것이다. 성공으로 세지 않고 성공 허용 구간도 바꾸지 않는다.
- 완료 시점 재검토가 필요하면 모델 예측을 본 원본만 고치지 않는다. 훈련+검증 원본 전체에 같은 절차를 적용하고 새 주석 버전으로 저장한다.

### 최종 모델과 최종 평가

실험 8에서는 잠근 설정과 E로 훈련+검증 원본 39개 전체를 다시 학습한다. 정규화도 이 39개에서 다시 계산한다. 최종 평가 22개는 5개 seed 모델 모두에 한 번 적용해 평균·범위를 보고한다. 배포 모델의 seed는 최종 평가 전에 20261021로 정해 둔다. 최종 평가 방향 원본은 첫 세션(09:16)이라, 지금 자료 중 유일하게 세션이 분리된 평가다.

## 구조 비교

GAP 비교가 필요하면 다른 조건을 고정한 Flatten/GAP 비교에서 최종 실행 코드·설정·수치를 보존한다. 과거 USB 실험 8b는 정확한 testing 수치와 최종 실행 코드가 없어 GAP의 부적합을 입증한 결과로 취급하지 않는다. 원래 결과와 해석 한계는 [과거 실험 기록](진행기록_조현준.md)에 있다.

2026-10-21 현재 BLE 데이터의 [실험 5](experiments/ble-v1/실험5_진행기록.md)에서3 seed의 Flatten/GAP 비교를 완료했다. GAP의 선택된 모델 모두 방향 명령0/8로 누락해 해당 변경을 채택하지 않았고 Flatten 기준을 유지한다. 이번 코드·모델·정량 결과는 개별 기록에 보존했으며 GAP 일반에 대한 결론으로 확장하지 않는다.

## 첫 평가에서 보고할 것

- 클래스별 precision/recall/F1, 혼동행렬, 평가 원본/이벤트 수.
- 전체 원본 replay에서 이벤트 정검출·방향 오류·누락·중복·복귀 중 오발행.
- 완료 e 이후 500 ms 이내 같은 방향 예측을 이벤트와 일대일 매칭하는 초기 평가 규칙을 사용한다. 조기 발행은 성공으로 계산하지 않고 별도 집계하며, 매칭되지 않은 발행과 이벤트를 숨기지 않는다. 허용 구간은 검증 단계에서 고정하고 평가 때 바꾸지 않는다.
- 올바르게 매칭된 이벤트의 완료→발행 지연 median/p95와 표본 수. 지연은 주석 오차의 영향을 받는다.
- 배경 평가의 실제 관측 시간과 오발행 수. 현재 전체 배경도 60초에 불과하고 평가 배경은 그 일부이므로 장시간 FP/hour 성능을 확정하지 않는다.
- 각각의 3초 파일은 독립 replay로 처리한다. 파일을 이어 붙여 빠른 반복 명령이나 연속 실사용 성능을 검증했다고 주장하지 않는다.

연속 평가 자료는 첫 학습과 함께 준비한다. 앱의 연속 기록으로 명령·자연 복귀·일상 동작을 수집하고 방향/완료 시점을 주석 처리한 뒤, 개발용 연속 검증과 미사용 최종 연속 평가로 분리한다. 라벨 정책·출력 문턱은 개발용 자료에서 선택한다. 기존 3초 clip 평가와 새 연속 평가 결과는 별도로 보고하며, 배경 관측 시간이 짧으면 FP/hour 환산치만으로 장시간 성능을 주장하지 않는다. 연속 자료 확보와 평가 실행은 아직 계획이다.

재착용·보드 추론·전력도 별도 검증이 필요하다. 이번 학습만으로 완성 제품 수준의 성능을 선언하지 않는다.

## 배포 검증

훈련 원본만으로 대표 입력을 구성해 int8 변환을 시도한다. float와 int8의 같은 replay 결과를 비교하고 지원 연산·peak RAM·Flash·전처리+추론 시간 median/p95/max를 측정한다. 50 ms 주기를 목표로 BLE와 100 Hz 샘플링을 함께 켠 상태에서 확인한다. 수집을 막지 않는 스케줄링/FIFO도 검증한다.

## 구현 순서

1. 추가 방향 40개 완료 주석과 REVIEW를 검토하고 유효 양성 창 수를 확인한다.
2. 원본별 train/validation/test 목록과 정확한 시간 기준을 고정하고, 별도 연속 검증/최종 평가 녹화와 주석을 준비한다.
3. 기존 내보내기 도구의 로컬 idle/other 처리·validation 분리·시각 정렬을 보완하거나 전용 로컬 입력 파이프라인을 만든다.
4. 고정 정규화와 아키텍처 문서의 CNN으로 무증강 기준선을 훈련한다.
5. 검증 replay로 이벤트 문턱을 고정한 뒤 최종 평가를 한 번 실행한다.
6. int8 변환 및 보드에서 시간·메모리·BLE 동시 동작을 측정한다.

## 수행 결과 기록

모델 생성과 영 입력 추론의 실행 결과는 [BLE 모델 구성 점검](진행기록_조현준.md#ble-모델-구성-점검)에 기록했다. 새 BLE 실험 1~8은 [개별 실험 기록](experiments/ble-v1/README.md)에 조건·결과·결정 근거를 남긴다. 과거 USB 실험 번호와 구분하며 공용 진행 기록에는 작업 요약과 해당 실험 링크를 남긴다. 최종 평가 실행은 새 실험 계획의 후보 확정 이후로 미루고, 그 전에는 validation으로 비교한다.

2026-10-25부터 자세별 5세션으로 하는 실험은 [BLE v2 실험 기록](experiments/ble-v2/README.md)에 남긴다.
