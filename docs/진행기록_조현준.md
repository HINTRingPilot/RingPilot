# RingPilot 개발 진행 기록 (조현준)

`zoon` 브랜치 전용 기록. 공용 `진행기록.md`와 내용이 겹치지 않도록 이 브랜치의 작업만 여기에 적고, 나중에 합친다.
계획, 실제 수행, 사용자 확인을 구분하고 미검증 성능을 성과로 쓰지 않는다.

## 2026-10-21 — CNN 학습 세팅 검토 및 데이터 분할 설계

### 목적

3층 CNN(실험 8c, testing 66.67%) 이후 학습 환경과 분할 방식을 정리하고, 다음 학습 전에 평가 체계를 바로잡는다.

### 수행 (계획 수립만, 코드·학습 실행 없음)

- `docs/진행기록.md`, `docs/ModelExperiments.md`, `docs/WindowLengthComparison.md`, `tools/export-gesture-windows.js`를 읽고 현재 상태를 확인했다.
- 현재 분할 확인: `assignCategories`(`tools/export-gesture-windows.js:104`)가 방향별로 원본 샘플 20%를 통째로 testing에 둔다. 따라서 test 누수는 없다.
- 문제로 본 점:
  - train/validation 분할은 Edge Impulse Studio가 윈도우 단위로 하므로 겹치는 윈도우와 증강본이 양쪽에 섞일 수 있다(실험 7의 validation 98.6% 대 testing 44.44% 괴리의 추정 원인).
  - 기존 testing 36개는 구조 선택에 여러 번 쓰여 최종 성능 보고용으로는 오염됐다.
  - 1·2차 세션이 섞여 있고 세션 구분이 없다. 방향당 원본이 11~17개뿐이다.
  - `data/windows*`는 gitignore 대상이라 현재 디스크에 없으며, 학습 전에 export를 다시 실행해야 한다.
- 어노테이션 CSV: 1차 `gesture-completions.csv` 40행, 2차 `gesture-completions-session-2026-10-06.csv` 37행. 1차는 `source_path`가 비어 있어 원시 샘플이 Edge Impulse 원격에만 있을 가능성이 있다(미확인).

### 설계안 (미구현)

```
원본 샘플(AUTO ~54개 + 새로 녹화할 3차 세션)
 ├─ FINAL TEST : 3차 세션 전체 (다른 날, 재착용, 튜닝에 사용 안 함)
 └─ 개발 세트  : 1·2차 AUTO
        └─ 그룹 5-fold CV (그룹 = sample_id, 방향별 층화)
             각 fold: train 4/5 → 증강은 여기에만 / val 1/5 → 증강 없음
```

- 그룹은 `sample_id`로 하고 방향별로 층화한다. 증강은 분할 뒤 train fold에만 적용하고 val·test는 원본을 쓴다.
- REVIEW 14개는 stress set으로만 쓰고, 이상치 3개(`raw_up.1`, `raw_left.9`, `raw_right.5`)는 제외를 유지한다.
- NONE 윈도우 캡(30)은 train fold에만 적용한다. idle/other 10초 녹화는 한 그룹으로 취급한다.
- fold 분할 시드를 3개 이상 바꿔 반복하고, 분할 정의는 `data/splits/split_seed{N}.json`에 고정한다(예정).
- 학습 환경은 로컬 Keras → TFLite int8을 권장했다. 사용자의 최종 선택은 아직 받지 않았다.
- 기타 학습 세팅 권장값(고정 스케일 가속도/9.8·자이로/1000, Adam lr 1e-3, early stopping, label smoothing 0.05, class weight, on-the-fly 증강, 시간 이동 ±20~30 ms 제한)은 제안 단계이며 시험하지 않았다.

### 브랜치 작업

- `main`에서 `zoon` 브랜치를 새로 만들어 전환했다.
- 이 브랜치의 기록은 `진행기록_조현준.md`에 작성한다(사용자 요청). AGENTS.md는 `진행기록.md`를 지정하고 있어, 병합 시 두 파일을 정리해야 한다.

### 검증 결과

- 아직 학습, 분할 스크립트, 성능 측정은 수행하지 않았다. 위 내용은 문서와 코드를 읽은 검토 결과다.

## 2026-10-21 — BLE v1 실험 1~7 점검과 요약

### 목적

`docs/experiments/ble-v1/`의 실험 1~7 기록을 서로 대조해 수치·상태가 맞는지 점검하고, 이 브랜치의 흐름을 한곳에 요약한다. 세부 수치·근거는 각 실험 문서에 있고 여기에는 판단 흐름만 남긴다. 과거 USB 실험 1~8과 번호 체계가 다르다.

### 공통 조건

- 데이터: 휴대폰 BLE 수집 66개 원본. 방향 세션 09:16(방향별 5개, 최종 평가 보류)과 09:43(방향별 10개), idle/other 세션 09:33·09:43. 완료 시점 e는 센서 기반 운영 정답이며 영상·사용자 확인은 없다.
- 실험 1~5: 고정 분할(훈련 29 / 검증 10 / 최종 평가 보류 22 / 제외 5), 160행×6축, 2층 CNN(9,493 파라미터), val_loss 조기 종료, 검증 방향 동작 8개.
- 실험 6~: 개발 평가 v2(원본 단위 5-fold CV, 방향 35개, seed 5개, 고정 epoch, 개발 후보/악화/판단 불가 판정). 실험 1~5와 수치를 직접 비교하지 않는다.
- 최종 평가 22개는 실험 1~7 내내 모델 예측을 열지 않았다.

### 흐름에 대한 해석

- 실험 1~5의 미채택 결정 네 번은 모두 seed 차이보다 작은 차이 안에서 나왔다. 선택 epoch와 정검출이 함께 움직이는 경향도 보였다(검증 창 96.5%가 NONE이라 val_loss 최저점이 학습 초기에 나오기 쉬움). 그래서 실험 6부터 평가 방식을 v2로 바꿨다. 실험 1~5의 결과는 "효과 없음"이 아니라 "구분 불가"로 읽는다.
- v2에서 처음으로 seed 변동보다 큰 일관된 변화가 나온 것이 증강(B)이다. 다만 미매칭(특히 조기 발행)도 함께 늘었다. 증강 효과와 학습량 차이도 사전 계획으로 분리하지 못했다. 갱신 횟수를 대략 맞춘 사후 비교에서는 B가 두 지표 모두 나았다.
- 조기 발행은 반복해 나타났다. 실험 2·3에서는 `raw_down.1`, `raw_up.3`이 완료 60~90 ms 전에 발행됐고, 실험 6·7a에서도 조건별 평균 5.8~10.2건(seed당 합산, 35동작 기준)이었다. 센서 기반 완료 시점의 오차일 가능성과 실제 오작동을 아직 구분하지 못했다.

### 점검 결과

- 수치 대조: 실험 2·4·5의 160행/Flatten 기준 조건이 실험 1의 BLE-01-r03(창 정확도 92.11%, 정검출 0/8)과 일치했다. 실험 6의 A 조건은 보정 단계 E=10 결과(16.0/12.4)를 정확히 재현했다. 문서 사이 수치 불일치는 찾지 못했다.
- 고친 것:
  - `README.md` 진행 표와 실험 6·7 문서 머리말의 상태가 "미실행 계획"으로 남아 있어 실제 상태로 갱신했다.
  - `final-architecture.md`에 B 개발 후보 갱신을 추가했다. 최종 선정은 아니다.
  - 실험 1~5 문서가 링크한 `results/BLE-01-r03`, `BLE-02`~`BLE-05`, `assets/`가 커밋본에 빠져 있어 메인 체크아웃에서 복사했다(178개 파일, 약 4.7 MB). 링크 점검 결과 남은 깨진 링크는 Git 제외 경로인 `ml/runs/BLE-01-r03/model.keras` 하나다.
- 남은 차이: 실험 6 절차 4(기존 방식 A의 5 seed 연결 확인)는 미실행이다. 실험 3의 정식 연속 검증과 7b는 연속 자료가 생길 때까지 대기한다.
