# RingPilot 모델 개발·실험 기록 (조현준)

`zoon` 브랜치의 모델 관련 검토와 프로젝트에 남아 있던 실험 결과를 정리한 기록이다. 날짜는 한국 시간 기준이다. **실행한 결과, 원인 가설, 미실행 계획을 구분한다.** 과거 USB 결과를 현재 BLE 모델의 성능으로 사용하지 않는다.

모델의 연결 구조는 [아키텍처 설계](ModelArchitecture.md), 앞으로 수행할 절차는 [학습·평가 계획](TrainingPlan.md)에서 관리한다. 공용 [진행 기록](진행기록.md)의 날짜별 이력은 보존하고 이 문서에 모델 관련 내용을 모았다.

## 현재 상태 요약

| 구분 | 상태 |
|---|---|
| 과거 USB 모델 | 실험 1~8 수행 기록 있음. 데이터는 2026-10-21 폐기, 현재 BLE 성능으로 해석 불가 |
| 현재 BLE 원본 | 최근 수집 기록 기준 방향별 15회, idle/other 각 3개. 원본 구성은 공용 진행 기록 참고 |
| 현재 CNN | 입력 160×6, Conv1D 2층, 5클래스 출력. 모델 정의와 기본 실행 확인 완료 |
| BLE 학습·성능 | 실험 1~2·4~5 검증 및 실험 3 clip 사전 비교 완료. 클래스 가중치·300 ms 라벨 폭·1200 ms 입력·GAP 변경 미채택. 실험 3 정식 연속 검증은 대기 중이며 사용 가능한 방향 인식 모델은 아직 없음 |
| 보드 추론·최종 평가 | 미실행. 영 입력 실행·오프라인 학습을 보드 실동작 검증으로 취급하지 않음 |

## 과거 USB 데이터 실험 — 2026-09-28~2026-10-06

기존 `ModelExperiments.md`의 조건·수치·해석을 아래에 옮겼다. 실험 번호는 이전 기록과 대응하도록 유지한다.

### 현재 상태 — USB 데이터로 수행한 과거 실험

**실험 1~8은 모두 USB 케이블을 연결한 상태에서 수집한 데이터에 대한 과거 기록이다. 66.67%를 포함한 아래 결과는 현재 BLE 데이터나 새 모델의 성능이 아니다.**

2026-10-21에 사용자 요청으로 PC 작업 폴더의 USB 원본·주석·학습 윈도우와 Edge Impulse 프로젝트 1122630/1129540의 샘플을 삭제했다. 프로젝트 자체는 유지했다. 케이블의 무게·당김과 움직임 제약이 실제 무선 사용 조건과 다르다는 사용자 판단에 따른 결정이다. 케이블이 성능에 미친 영향의 크기를 대조 실험으로 측정한 것은 아니다.

커밋된 2차 세션·주석 일부는 Git 이력에서 복원할 수 있지만, PC 사본이 없던 1차 원격 원시 샘플은 복구할 수 없다. 따라서 현재 상태에서 실험 전체를 그대로 재현할 수 없다. 아래 수치와 당시 선택은 이력을 보존하되, 2026-10-21 검토에서 근거보다 강했던 해석을 수정했다.

현재 무선 데이터의 구성은 [진행 기록](진행기록.md), 새 기준 모델은 [초기 1D-CNN 설계](ModelArchitecture.md)를 따른다. 이 문서의 삭제된 파일 경로는 당시 입력을 식별하기 위한 기록이다.

### 짧은 고찰 — USB 데이터를 폐기한 이유와 수집 방식의 교훈

2026-10-21 기록. 목표는 배터리로 동작하는 무선 착용형 리모컨인데, 초기 데이터는 USB 케이블을 연결한 채 수집했다. 케이블의 무게와 당김이 손가락의 움직임·자연 복귀에 영향을 줄 수 있어 실제 사용 조건을 대표하기 어렵다고 판단했고, 사용자 결정에 따라 기존 USB 학습 데이터를 폐기하고 배터리·BLE 수집으로 기준을 다시 잡았다. USB 전송 자체가 센서 데이터를 손상시켰다는 뜻은 아니며, 케이블 영향이 정확도를 얼마나 바꿨는지는 대조 실험으로 확인하지 못했다.

돌아보면 실제 착용 조건과 평가 방법을 먼저 고정하지 않은 채, 짧은 방향별 녹화에서 겹치는 창과 증강본을 늘려 학습량을 확대했다. 이렇게 만든 표본은 서로 비슷해 개수가 늘어도 독립적인 동작·세션·착용 조건의 다양성이 같은 만큼 늘지는 않는다. 일상 움직임과 연속 명령에 대한 평가도 부족했고, Studio 내부 validation의 부모 원본 분리를 확인하지 않은 상태에서 같은 testing 자료로 구조를 반복 선택해 새로운 사용 조건에서의 성능을 판단하기 어려웠다. 실제 데이터 누수가 발생했다고 확인한 것은 아니다.

앞으로는 실제 무선 사용 조건에서 수집하고, 세션·착용 조건·완료 시점과 원본 식별자를 기록한 뒤 원본 단위로 훈련·검증·최종 평가를 먼저 나눈다. 그다음 훈련 자료에만 창 추출·증강을 적용하고, 별도로 모은 연속 동작과 배경 자료에서 누락·중복·오발행을 확인한다. 또한 학습 대상에서 제외하는 것과 원본을 삭제하는 것은 별개다. 이번에는 일부 원격 원본을 복구할 수 없어 재현성이 사라졌으므로, 향후에는 제외 사유를 표시하고 원본·주석·실행 설정을 보존하는 방식을 기본으로 삼는다.

### 공통 전제

- 원본 데이터: `RingPilot`(1122630)의 `raw_up/down/left/right`(3초, 100 Hz, 6축) 및 `idle`/`other`(10초).
- 완료 시점 정의: 방향 이동과 자연 복귀의 자이로 에너지 99% 이후, IMU가 180 ms 안정되기 시작한 첫 시점(`tools/suggest-gesture-completions.js`).
- 윈도우: 1600 ms, 50 ms stride, 완료 시점 뒤 150 ms만 해당 방향 양성, 나머지 `NONE`(`tools/export-gesture-windows.js`).
- 입력: 6축(accX/Y/Z, gyrX/Y/Z) raw, 160 샘플(1600 ms × 100 Hz) = 960 features.
- NONE은 학습 30개로 캡(원본 샘플마다 번갈아 샘플링), 테스트는 `NONE 개수 × test-fraction(0.2)`.

#### 공통 해석 한계

- 완료 후 150 ms를 50 ms 간격으로 자르면 원본 이벤트 하나에서 양성 창이 보통 3개 나온다. 겹치는 창은 독립 표본이 아니므로 testing 36개를 독립 동작 36회로 해석하지 않는다. 정확한 원본 수와 유효 표본 수·신뢰구간은 창 수만으로 확정할 수 없다.
- 실험 2~8의 원본별 train/test 분리와 별개로, Studio 내부 train/validation의 원본·증강 부모 그룹 보존은 확인하지 못했다. 세션 전체를 보류한 일반화 평가도 하지 않았다.
- 실험 2~8은 조건별 결과 한 세트만 기록돼 있고 seed별 반복 결과와 변동 범위가 없다. 실험 1의 5-fold 진단과도 구분한다. 작은 차이를 통계적으로 유의하다고 주장하지 않는다.
- 같은 testing set을 구조 비교에 반복 사용했으므로 아래 testing 결과도 모델 선택에 사용된 개발 평가다. 선택된 모델의 성능을 확인하는 미사용 최종 평가로 볼 수 없다.
- 큰 validation-testing 차이는 분할·분포·라벨·표본 수를 조사할 신호이며 누수의 단독 증거는 아니다. validation 자체가 무효라는 결론도 아니다. 현재 분할·모델 선택 원칙은 [학습 설정과 분할](TrainingPlan.md#학습-설정과-분할)에 정리한다.

### 이 실험에서 얻은 교훈

- 원본·증강 부모가 분할 사이에 섞이지 않았는지 확인하지 않으면 높은 validation 수치를 일반화 성능의 근거로 삼기 어렵다. 이 실험에서 실제 누수가 확인된 것은 아니다.
- 창 단위 정확도만으로 실제 명령의 검출·중복·오작동을 판단할 수 없다. 짧은 clip의 진단도 장시간 연속 사용 평가와 구분해야 한다.
- 실행 코드와 정확한 수치를 남기지 않으면 성능 변화의 원인을 판단하기 어렵다. 실험 8b의 GAP 후보 제외가 이에 해당한다.
- 같은 테스트 자료로 모델을 반복 선택했다면 그 결과는 개발 평가다. 선택된 모델의 성능을 확인할 별도 최종 평가가 필요하다.

### 실험 1 — 입력 길이 선별(800/1200/1600 ms), 로컬 선형 모델

- 날짜: 2026-09-28. 상세: `WindowLengthComparison.md`.
- 목적: 최종 모델이 아니라 입력 길이 후보를 거르는 진단.
- 모델: 10개 시간 bin의 6축 평균/표준편차 + 양 끝 차이로 만든 126개 특징, 635-parameter 선형 softmax.
- 데이터: AUTO 30개(단일 세션), 5-fold 교차검증.

| 길이 | 맥락 포함 | 이벤트 검출 | macro F1 |
|---:|---:|---:|---:|
| 800 ms | 6/30 | 6/30 | 0.216 |
| 1200 ms | 19/30 | 12/30 | 0.253 |
| 1600 ms | 28/30 | 8/30 | 0.272 |

- 결론: 800 ms는 동작 시작 맥락을 자주 잃어 제외. 1600 ms를 기본 후보로 채택. RIGHT F1은 세 조건 모두 0.08 미만으로 특히 낮았음(이 선형 모델 한정).

### 실험 2 — 1차 Edge Impulse 업로드, Dense 기준선

- 날짜: 2026-10-06.
- 데이터: 단일 세션 AUTO 30개 → 학습 91개(NONE 30/UP 18/RIGHT 18/DOWN 13/LEFT 12), 테스트 24개.
- 모델: Dense 20→10, cycles 30, learning rate 0.0005(Studio 기본값).

결과(validation): 정확도 52.6%, loss 11.30.

| 클래스 | DOWN | LEFT | NONE | RIGHT | UP |
|---|---:|---:|---:|---:|---:|
| F1 | 0.29 | 0.50 | 0.33 | 0.44 | 1.00 |

- DOWN의 80%가 RIGHT로 오분류.

### 실험 3 — 1D conv 1층 + 입력 스케일 조정

- 구조: Reshape(6열) → 1D conv/pool(8 filters, kernel 3) → Flatten → Dense(5). 데이터는 실험 2와 동일.
- 스케일 1.0(기본): 정확도 63.2%, loss **12.73**. DOWN F1 0.75, RIGHT F1 0.29, NONE 75%가 LEFT로 오분류.
- **당시 원인 가설과 정정**: 입력 크기가 학습에 영향을 주었을 가능성을 검토했다. 하지만 높은 loss만으로 softmax의 exp() 계산이 불안정했다고 확인할 수는 없다. 잘못된 클래스에 강한 확신을 주는 예측에서도 crossentropy는 커지며, 당시 logits·수치 오류·학습 과정은 확인하지 않았다.
- Raw data 블록의 Scale axes를 0.01로 조정 후 재학습: loss **0.94**로 급락, 정확도는 63.2%로 동일(검증 19개 기준 윈도우 1~2개 차이는 재배열).
- 모든 축에 같은 0.01을 곱했으므로 전체 입력 크기만 줄었고 가속도와 자이로의 상대 크기 차이는 그대로다. 센서 간 단위 차이를 해소했다고 해석하지 않는다. loss 감소의 정확한 원인은 반복·통제 실험이 없어 미확인이다. 현재 정규화 설계는 [전처리와 버퍼](ModelArchitecture.md#전처리와-버퍼)를 참고한다.

결과(validation, 스케일 0.01): 정확도 63.2%, loss 0.94.

| 클래스 | DOWN | LEFT | NONE | RIGHT | UP |
|---|---:|---:|---:|---:|---:|
| F1 | 0.75 | 0.40 | 0.55 | 0.57 | 1.00 |

- 해석 한계: 검증 윈도우가 약 19개(클래스당 3~6개)뿐이라 수 퍼센트 차이는 통계적으로 거의 의미 없음.

### 실험 4 — DOWN/RIGHT 혼동 원인 점검(로컬, 읽기 전용)

- DOWN과 RIGHT가 Dense 기준선에서 서로 혼동되는 것을 보고 로컬에서 파형을 직접 비교.
- DOWN(6개): 자이로 Y축 에너지 비율 83~97%, 음→양 순서.
- RIGHT(7개): X/Z축이 섞임(Z 43~64%), 음→양 순서.
- 클래스 평균 자이로 파형 코사인 유사도: DOWN-RIGHT **-0.23**(비슷하지 않음), UP-DOWN -0.85.
- 해석: 조사한 파형과 클래스 평균에서 축별 차이를 관찰했다. 다만 평균 코사인 유사도만으로 개별 창의 유사성이나 라벨 경계 문제를 배제할 수 없으므로, 혼동 원인이 모델·데이터 양이라고 확정하지 않는다.

### 실험 5 — 2차 세션 녹화 및 완료 시점 재계산

- `tools/record-gesture-samples.js` 추가(시리얼 녹화, `edge-impulse-cli` 번들 `serialport` v8 재사용).
- 2차 세션(`data/sessions/2026-10-06T04-12-41/`) 40개 녹화. 축/패턴 스크리닝으로 `raw_up.1`(주축이 다른 9개와 다름), `raw_left.9`(주축 불명확), `raw_right.5`(최대 자이로 1038 deg/s, ±1000 포화 범위 초과)를 이상치로 제외, 37개로 진행.
- `return_pose_offset`(시작-종료 중력 방향 12도 이상 차이) 조건을 AUTO/REVIEW 판정에서 제거: 제스처의 최종 자세가 시작 자세와 같아야 할 근거가 없다고 판단.
  - 조건 제거 전/후: 기존 40개 AUTO 30→31, 신규 37개 AUTO 14→23.
- 남은 REVIEW 14개 사유: `early_motion`(LEFT/RIGHT에 집중, 녹화 스크립트에 카운트다운이 없어 급하게 시작했을 가능성), `late_completion`(DOWN에 집중, 3초가 빠듯했을 가능성), `no_180ms_settle` 2개. 원인은 가설이며 파형으로 확인하지 않음.

### 실험 6 — 두 세션 합산 재학습

- 두 세션 AUTO 합산(UP 17/DOWN 11/LEFT 13/RIGHT 13 원본 샘플) → 학습 145개(NONE 30/UP 39/DOWN 25/LEFT 24/RIGHT 27), 테스트 36개.
- 구조는 실험 3과 동일(Reshape+1D conv 1층, 스케일 0.01).

결과(validation): 정확도 **75.9%**, loss **0.82**.

| 클래스 | DOWN | LEFT | NONE | RIGHT | UP |
|---|---:|---:|---:|---:|---:|
| F1 | 0.40 | 0.80 | 0.67 | 0.83 | 0.95 |

- 실험 3 대비 validation 정확도 63.2%→75.9%, loss 0.94→0.82로 개선을 관찰했다. 구조·스케일은 같았지만 원본 구성·내부 분할·학습 무작위성도 영향을 줄 수 있다. 데이터 추가의 효과와 일치하는 관찰이나, 데이터 부족이 원인이었음을 입증한 결과는 아니다. 같은 독립 평가 자료에서의 확인은 하지 못했다.
- 한계: Studio 내부 train/validation의 실제 세션 구성은 확인하지 못했다. 세션 전체를 보류한 평가가 아니므로 새로운 세션에 대한 일반화 성능으로 해석할 수 없다. DOWN F1은 0.40으로 가장 낮았다(25%는 NONE, 25%는 UP으로 분산).

### 실험 7 — 데이터 증강(5배) 및 재학습, validation-testing 괴리 발견

- `tools/augment-gesture-windows.js`(사용자가 별도 에이전트 자문으로 작성, 업로드 전 에이전트가 직접 검증: 테스트셋 바이트 동일/학습 원본 바이트 동일/겹치는 윈도우 동일 시각 노이즈 공유/`sample_id` 기준 train-test 누수 없음/전부 160행 확인).
- 방식: 학습 윈도우마다 원본 1개 + 변형 4개(`sample_id`당 하나의 강체 회전 ±5도, 랜덤 축 + 가우시안 노이즈: 가속도 std 0.02 m/s², 자이로 std 0.2 deg/s, ±3σ 클리핑). 테스트는 증강하지 않음.
- 업로드: 학습 725개(NONE 150/UP 195/DOWN 125/LEFT 120/RIGHT 135), 테스트 36개(원본 유지).

결과(validation): 정확도 **98.6%**, loss **0.14**.

결과(Model testing, 증강되지 않은 testing 36개로 평가): 정확도 **44.44%**.

| 클래스 | DOWN | LEFT | NONE | RIGHT | UP |
|---|---:|---:|---:|---:|---:|
| F1 | 0.80 | 0.20 | 0.33 | 0.00 | 0.94 |

- RIGHT F1 0.00(9개 전부 NONE 또는 `uncertain`으로 오분류). LEFT는 절반이 `uncertain`.
- **확인한 사실**: validation 98.6%와 testing 44.44% 사이에 큰 차이가 있었다. 이 validation을 원본이 다른 자료에서의 성능으로 그대로 보고할 수 없다.
- **미확인 가설**: 같은 원본의 variant 5개가 모두 `training` 카테고리에 있어 Studio 내부 분할에서 유사한 변형이 train/validation 양쪽에 들어갔을 가능성이 있다. 실제 분할 목록은 확인하지 못했으므로 누수가 확정된 것은 아니다. 성능 차이에는 증강과 원본의 분포 차이, 과적합, 작은 평가 표본 수도 영향을 줄 수 있다.
- **끝내 확인하지 못한 것**: 증강 전 모델(실험 6)을 같은 testing 36개로 평가하지 않아 증강 자체가 성능을 악화시켰는지 구분할 수 없다. 당시 계획했던 재업로드 비교는 실행 기록이 없고 원본 삭제 후 현재 상태에서 수행할 수 없다. 후속 비교 계획은 [학습 설정과 분할](TrainingPlan.md#학습-설정과-분할)을 참고한다.

### 실험 8 — 구조 변경(conv 2~3층 + dropout), GAP 시도와 당시 후보 제외

데이터는 실험 7과 동일(증강본, 학습 725개/testing 36개, 원본 유지).

동일한 증강 조건에서 모델 구성을 비교한 결과다. 깊이 외에 필터 수·Dropout·Dense 구성도 달라졌으므로 층 수만의 효과를 분리하지 못했다. 증강하지 않은 조건과의 상호작용도 확인하지 않았다.

#### 8a. conv 2층 + dropout + Dense(32)

- 구조: `Reshape(6) → Conv1D(16,k5,same)+MaxPool(2)+Dropout(0.25) → Conv1D(32,k5,same)+MaxPool(2)+Dropout(0.25) → Flatten(1280) → Dense(32)+Dropout(0.3) → Dense(5,softmax)`.
- 결과(Model testing, testing 36개): 정확도 **63.89%**.

| 클래스 | DOWN | LEFT | NONE | RIGHT | UP |
|---|---:|---:|---:|---:|---:|
| F1 | 0.91 | 0.55 | 0.37 | 0.46 | 1.00 |

- 실험 7의 1층 구조(testing 44.44%) 대비 +19.45%p, RIGHT F1 0.00→0.46을 관찰했다. 같은 증강 데이터에서 모델 구성 변경 후 개선된 결과지만, 깊이 부족이 원인이었다고 확정하거나 무증강 조건에도 같은 효과가 난다고 일반화하지 않는다.
- 파라미터 추정: Dense(32) 직전 Flatten(1280)이 전체의 약 93%(40,992/약 44,000)를 차지. Dense 직전 크기를 줄이는 게 다음 개선 지점으로 식별됨.

#### 8b. GlobalAveragePooling1D(GAP) 시도 — 당시 후보 제외, 정량 근거 부족

- Studio 기본 UI의 레이어 목록에 GAP이 없어, "커스텀 러닝 블록" 안내를 보고 에이전트가 조사. Custom learning block(Docker+CLI 필요, 타 프레임워크/사전가중치용)과 Expert Mode(Studio 안에서 Keras 코드 직접 편집, 추가 도구 불필요)를 구분해 Expert Mode로 충분하다고 안내.
- 사용자가 공유한 Studio 자동생성 Expert Mode 코드에 이미 `GlobalAveragePooling1D()` → `Conv1D(32, kernel=1, activity_regularizer=l1(1e-5))`(Dense와 수학적으로 동일하게 표현한 패턴) 구성이 들어있었음.
- 코드 검토로 버그 2개 발견: (1) import 문에 `GlobalAveragePooling1D` 누락(`NameError` 가능), (2) GAP 출력(2D)에 바로 `Conv1D`(3D 입력 요구)를 적용해 차원 불일치 가능성. `Conv1D(32,1,...)`를 `Dense(32,...)`로 대체하도록 수정 제안.
- 수정 제안이 실제 학습 코드에 어떻게 반영됐는지와 최종 실행 코드는 보존된 기록으로 확인하지 못했다.
- 사용자가 GAP 버전으로 실제 학습: **검증 정확도 소폭 감소, Model testing 정확도 대폭 감소**(정확한 testing 수치는 기록되지 않음, 8a보다 뚜렷이 낮았다고 보고됨).
- 파라미터 계산: GAP(32) 뒤 Dense(32)는 1,056개로 8a의 40,992개보다 97% 이상 적다. 해당 Dense의 파라미터 증가로 성능 하락을 설명할 근거는 약하다. 전체 모델의 실제 연산량·추론 시간은 측정하지 않았다.
- 원인 가설: GAP는 시간 위치별 특징을 평균내므로 완료 시점 판정에 필요한 위치 단서가 약해졌을 수 있다. 다만 앞선 convolution이 순서 특징을 채널에 인코딩할 수 있어 모든 시간 순서 정보가 반드시 사라진다고 단정할 수 없다. 또한 정답 펄스 150 ms는 입력 안의 동작 신호 지속시간과 다르므로, 그 숫자만으로 신호 희석이나 과소적합을 입증할 수 없다.
- 당시 선택: 사용자 보고에 따라 GAP를 후보에서 제외했다. **정확한 testing 수치·최종 실행 코드·반복 실험이 없어 근거가 약하며, GAP 자체가 이 태스크에 부적합하다는 결론은 미확인이다.**

#### 8c. conv 3층(중간 Dense 제거)

- 구조: `Reshape(6) → Conv1D(16,k5,same)+MaxPool(2)+Dropout(0.2) → Conv1D(32,k5,same)+MaxPool(2)+Dropout(0.25) → Conv1D(32,k3,same)+MaxPool(2)+Dropout(0.25) → Flatten(640) → Dropout(0.3) → Dense(5,softmax)`. GAP 대신 conv를 한 층 더 쌓아 시간 정보를 유지하면서 Flatten 직전 크기(1280→640)를 줄이고, 중간 Dense(32)는 제거.
- 결과(Model testing, testing 36개): 정확도 **66.67%**. 사용자 보고로 validation은 8a 대비 소폭 감소.

| 클래스 | DOWN | LEFT | NONE | RIGHT | UP |
|---|---:|---:|---:|---:|---:|
| F1 | 1.00 | 0.73 | 0.27 | 0.46 | 1.00 |

- 8a 대비 +2.78%p. DOWN·LEFT 개선, NONE 악화(0.37→0.27, `uncertain` 비중 증가), **RIGHT는 0.46으로 변화 없음**.
- 해석 한계: testing 36개에서 2.78%p는 창 1개 차이다. 창 사이 상관과 seed별 반복 결과가 없어 개선의 유의성이나 수익체감을 판단하지 못한다. validation 감소와 testing 증가가 함께 나타난 사실만으로 validation이 무효라고 결론내리지 않는다.
- RIGHT→NONE 혼동(이 조건에서 66.7%)은 남았다. 과거 RIGHT 최대 자이로가 약 86~347 deg/s로 상대적으로 작았다는 관찰은 있으나, 진폭·라벨 경계·완료 시점 오차·모델 구성 중 어느 원인이 큰지 비교하지 못했다. 특히 틀린 창의 판정 시각과 완료 시점 사이 거리를 조사하지 않아 경계 가설도 미확인이다.

## BLE 모델 구성 점검

날짜: 2026-10-21. 목적은 첫 CNN의 연결 구조를 정의하고 코드가 그 사양대로 생성되는지 확인하는 것이었다.

- 변경: `ml/model.py`에 입력 `(160,6)` → Conv1D(16,k5) → Pool → Dropout(0.2) → Conv1D(32,k5) → Pool → Flatten(1280) → Dropout(0.3) → Dense(5,softmax)를 정의했다.
- 선택 이유: 작은 두 층 모델로 시작하고 Flatten에서 시간 위치별 특징을 유지하도록 설계했다. 성능 우위가 확인된 결론은 아니다.
- 관련 코드: [모델 정의](../ml/model.py). 레이어별 크기와 실행 경로는 [아키텍처 설계](ModelArchitecture.md)를 참고한다.

2026-10-21 로컬 `ml/.venv`의 Python 3.12.15 / TensorFlow 2.21.0에서 모델을 생성했다. 각 레이어 출력 크기와 총 파라미터 9,493개가 아키텍처 사양과 일치했다. 0으로 채운 `(1,160,6)` 입력의 추론 결과는 `(1,5)`였고 모든 값이 유한하며 점수 합은 1.0이었다. 이는 모델 구성과 실행 경로의 기본 점검이며 학습 또는 제스처 인식 검증은 아니다. MAC 수식 288,000을 별도 계산했고 문서 내부 파일 링크의 대상 존재도 확인했다. int8 변환과 보드 실행은 수행하지 않았다.

**미실행:** BLE 데이터 학습, 인식 성능 측정, int8 변환, 보드 추론, BLE 동시 실행 시 지연·메모리 측정. 영 입력 실행 성공은 제스처를 인식한다는 증거가 아니다.

## 2026-10-21 — BLE 실험 3 사전 비교: 복귀 후 훈련 라벨 폭

사용자가 원하는 발행 시점을 “손가락이 자연스럽게 복귀한 뒤”로 확인했고, 지금은 새 연속 데이터를 수집하기 어렵다는 답을 받았다. 완료 전 발행을 목표로 하는 안은 후보에서 제외하고, 정식 연속 검증은 대기 상태로 남겼다. 대신 기존 clip에서 완료 후 훈련 라벨150/300 ms를 비교하는 사전 실험을 진행했다.

원본·완료e·정규화·분할은 유지했다. 연장 구간을 빠뜨리지 않도록 두 조건 모두 같은221개 훈련 창(기존144+추가77)을 사용하고, 81개의 훈련 라벨만 바꿨다. 검증570창과150 ms 정답, e~e+500 ms 성공 규칙, 모델·문턱은 공통으로 고정했다. 따라서 앞선144창 실험과 직접 비교하지 않고 이번 두 조건만 비교한다.

BLE-03-r01~r06, seed20261021/22/23의 결과에서 정검출은150 ms의0/0/2개 대300 ms의1/1/3개, 미매칭은0/0/1회 대6/4/5회였다. 평균 정검출0.67→1.67개, 미매칭0.33→5.00회, 조기 발행0.33→3.33회였다. macro F1은0.2256→0.3359로 늘었지만 모든 seed에서 조기/미매칭 발행이 증가해300 ms 변경은 미채택했다. 사용자 목표인 복귀 후 발행을 만족하는 정책으로 검증된 것은 아니다.

실제 조건·지연 표본 수·원본별 사례·한계는 [실험3_진행기록](experiments/ble-v1/실험3_진행기록.md)에 남겼다. 사전 프로토콜과 실행별 결과/로그는 `results/BLE-03/`, 구현은 `ml/experiment3.py`에 있다. 원본66개 해시 불변, 공통 검증 입력/정답 불변, 여섯 저장 모델 재로딩 일치와11개 테스트 통과를 확인했다. 새 수집·연속 검증·최종 평가·보드 추론은 미실행이다.

이번에 완료한 것은 clip 사전 비교다. 정식 실험3의 라벨 선정과 연속 검증은 수집 가능한 시점에 별도 자료를 확보한 뒤 재개한다. 현재 설계 사양은 바꾸지 않았고 커밋·푸시는 수행하지 않았다.

## 2026-10-21 — BLE 실험 4: 입력 1600/1200 ms 비교

현재 채택하지 않은 클래스 가중치·300 ms 라벨 변경은 빼고, 실험1의 훈련144창과150 ms 라벨로 돌아가 입력 길이만 비교했다. 두 조건은 같은 끝 시각의 원본을 사용하며120행 입력은160행의 마지막120행이다. `ml/model.py`에 길이 인자를 추가했고 기본160행은 유지했다.

## 2026-10-21 — BLE 실험 5: Flatten/GAP 비교

현재160행·150 ms 라벨·원래 훈련144창과 검증570창을 고정하고, Flatten만 GlobalAveragePooling1D로 바꿔 비교했다. 그 뒤 Dropout .3과 Dense5를 유지하고 중간 Dense는 추가하지 않았다. seed20261021/22/23의 세 쌍(BLE-05-r01~r06)을 실행했다.

GAP의 파라미터는9,493→3,253(약65.7% 감소)이었지만 Conv/Dense MAC 감소는288,000→281,760(약2.17%)에 그쳤고 평균 연산 비용은 별도다. 선택한 GAP 모델은 세 seed 모두 방향 명령0/8, 방향 양성20창도 모두 NONE이었다. macro F1 평균은 Flatten0.3013 대 GAP0.1716이었다. GAP seed23의 정확도96.49%는570창 모두 NONE으로 답한 결과이므로 성공으로 취급하지 않는다. 다른 두 GAP 모델은 idle을 LEFT로 분류한 창도 있었지만 발행 문턱을 통과한 명령 자체가 없었다.

GAP는 작은 모델이지만 정검출 유지 기준을 충족하지 못해 변경을 채택하지 않는다. 현재 Flatten도0~3/8로 부족하며 사용 모델로 확정하지 않는다. 시간 위치 평균화와 용량 감소·Dropout 특징 수·학습/검증 선택 절차를 분리하지 못했으므로 GAP가 일반적으로 부적합하다고 결론내리지 않는다. 과거 USB 수치를 재사용하지 않고 이번 코드·모델·정확한 수치를 보존했다.

[실험5_진행기록](experiments/ble-v1/실험5_진행기록.md)에 조건·평균/범위·실패 양상·근거를 기록했다. 기본 모델 호환성과 출력 계약을 포함한17개 점검 통과, 세 Flatten 제어 실행의 이전 예측 재현, 여섯 모델 재로딩 점수 일치, 원본66개 해시 불변을 확인했다. 연속·최종 평가·보드 실측은 수행하지 않았다. 다음 비교는160행·Flatten·150 ms 라벨을 기준으로 증강과 깊이의 영향을 분리한다. 커밋·푸시는 하지 않았다.

### 흐름에 대한 해석

- 실험 1~5의 미채택 결정 네 번은 모두 seed 차이보다 작은 차이 안에서 나왔다. 선택 epoch와 정검출이 함께 움직이는 경향도 보였다(검증 창 96.5%가 NONE이라 val_loss 최저점이 학습 초기에 나오기 쉬움). 그래서 실험 6부터 평가 방식을 v2로 바꿨다. 실험 1~5의 결과는 "효과 없음"이 아니라 "구분 불가"로 읽는다.
- v2에서 처음으로 seed 변동보다 큰 일관된 변화가 나온 것이 증강(B)이다. 다만 미매칭(특히 조기 발행)도 함께 늘었다. 증강 효과와 학습량 차이도 사전 계획으로 분리하지 못했다. 갱신 횟수를 대략 맞춘 사후 비교에서는 B가 두 지표 모두 나았다.
- 조기 발행은 반복해 나타났다. 실험 2·3에서는 `raw_down.1`, `raw_up.3`이 완료 60~90 ms 전에 발행됐고, 실험 6·7a에서도 조건별 평균 5.8~10.2건(seed당 합산, 35동작 기준)이었다. 센서 기반 완료 시점의 오차일 가능성과 실제 오작동을 아직 구분하지 못했다.
