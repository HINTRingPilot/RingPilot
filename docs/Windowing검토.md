# TinyML-only sliding window 설계 검토

2026-09-28. 사용자 확정 구조를 기준으로 한 분석 및 실험 제안이다. 모델 성능이나 제스처 파형을 검증한 결과는 아니다.

## 확정 제약

- 연속 IMU → 고정 길이 sliding window → TinyML → 출력 후처리 → GestureEvent → BLE.
- 출력은 RIGHT / LEFT / UP / DOWN / NONE. 기존 idle/other는 원본 출처를 보존하면서 학습용으로 NONE에 매핑한다.
- 원시 IMU 임계값 gating, nucleus 추출, DTW, 입력 이벤트 segmenter를 넣지 않는다.
- 모델은 재무장 대기 중에도 계속 추론한다. 후처리는 모델 출력만으로 이벤트 중복을 줄인다.
- 400 ms / 50 ms는 기준 실험값이다. 300/400/500/600 ms와 필요 시 더 긴 창을 비교한다.
- 왕복과 주변 맥락을 원본에 보존한다. 수집 단계에서 복귀를 제거하지 않는다.

## 1. 가장 큰 위험: 관측 가능한 맥락 길이

고정 창마다 독립 추론하는 모델은 이전 창을 기억하지 않는다. 학습 파일에 왕복 전체가 있더라도, 현재 입력에서 빠진 앞부분을 모델이 볼 수는 없다. RIGHT의 복귀만 들어간 창이 LEFT 시작 창과 같거나 비슷하면 라벨을 달리 주어도 확실하게 구분할 정보가 없다. NONE 추가는 관측 가능한 차이를 학습하는 데 유효하지만 사라진 맥락을 복구하지 않는다.

W=창 길이, S=추론 간격, D=인식에 필요한 왕복 구간 길이라고 하자. 완전 포함을 양성 조건으로 쓰면 그 이벤트를 담을 수 있는 창 끝 시각 구간은 [종료, 시작+W]이고 길이는 W-D다.

- D>W이면 완전한 왕복이 들어간 창은 없다.
- 임의 시작 위상에서도 완전 포함 창 1개를 보장하려면 대략 W-D≥S의 여유가 필요하다.
- N회 연속 양성 검출을 요구한다면, 기하학적으로 대략 W-D≥N×S의 여유가 있어야 임의 위상에서도 N개 창을 확보할 수 있다. 경계의 샘플 정의와 모델 오류는 별도다.
- 예: W=400, S=50, D=350 ms이면 여유는 50 ms뿐이다. 완전 포함 창 2회 연속 검출을 모든 시작 위상에 요구할 수 없다.

따라서 창 길이, offset 증강, 연속 N회 확인은 독립 하이퍼파라미터가 아니다. 실제 동작 길이 분포를 먼저 보고 같이 정해야 한다. 창 길이 확장은 TinyML-only 제약과 양립하지만 반응성·중복·연속 명령 간섭을 다시 평가해야 한다.

## 2. 윈도우 라벨 계약

원본 파일의 행동 라벨과 모델 입력 창의 라벨을 구분한다. 10초 RIGHT 파일을 그대로 RIGHT로 학습시키면 대기·복귀 꼬리만 들어간 창까지 RIGHT가 될 수 있다.

첫 기준 실험에는 다음의 보수적인 계약을 제안한다.

1. 원본 연속 데이터에 session_id, event_id, 방향, 출발 시각, 반환 전환점, 복귀 완료 시각을 주석으로 저장한다. 시작/종료 주석은 오프라인 정답이며 런타임 segmenter가 아니다.
2. 학습/검증/시험 세션을 먼저 나눈 뒤 각 세션에서 실제 추론과 같은 과거 전용 창을 생성한다.
3. 방향을 구분하는 왕복 전체를 포함하고 다른 이벤트가 섞이지 않은 창을 해당 방향 양성으로 둔다.
4. 실제 비명령 구간은 NONE. 부분 동작과 복귀 꼬리는 이 계약에서는 NONE 후보로 넣되 별도 하위 유형으로 보존한다.
5. 사람도 경계를 확신하지 못하는 좁은 주석 구간, 두 명령이 겹친 창은 학습 손실에서 제외하는 후보로 관리한다. 연속 평가에서는 제외하지 않는다.
6. 부분 창을 무조건 NONE으로 학습하면 짧은 완전 제스처와 충돌할 수 있다. 충돌이 많거나 양성 창이 없는 이벤트가 많으면 창 길이/계약을 변경한다. 단순 데이터 증량으로 덮지 않는다.

완전 포함은 첫 비교 기준이지 유일한 정답이 아니다. 실험에서 너무 느리거나 재현율이 낮으면 방향을 판별할 충분한 앞부분을 양성으로 허용하는 별도 계약을 비교할 수 있다. 이 경우 복귀 꼬리와 빠른 반대 명령의 오류를 반드시 따로 측정한다.

시간 이동 증강은 이동 후 다시 라벨을 계산한다. 완전 포함을 벗어났는데 방향 라벨을 유지하면 모순이다. 큰 zero padding보다 원본의 실제 전후 배경을 사용한다. 모든 왕복을 400 ms로 압축하는 것도 실시간 원본과 다른 속도 분포를 만들므로 기본 처리로 사용하지 않는다.

## 3. 얇은 후처리의 정의와 한계

제안 기준선은 방향 후보가 N회 확인될 때 이벤트를 즉시 1회 내고, 이후에는 모델이 NONE을 M회 연속 확신할 때까지 모든 방향 이벤트를 억제하는 방식이다. 후보 방향이 바뀌면 연속 확인 수를 초기화한다. NONE 확신은 단순히 방향 최고 점수가 낮다는 뜻과 다르다. NONE의 점수와 방향 점수를 함께 보고 정한다.

- raw IMU를 보지 않으며 모든 창을 계속 추론하므로 입력 segmenter와 다르다.
- 첫 유효 검출 때 출력하면 NONE까지 기다리는 것보다 빠르다. NONE 복귀 때 출력하는 방식도 가능하지만 출력 지연과 NONE이 나오지 않을 때의 동작을 따로 정의해야 한다.
- RIGHT→LEFT→NONE에서 LEFT를 억제하면 복귀 오검출을 줄일 수 있으나 실제 RIGHT 다음 LEFT 명령도 놓칠 수 있다.
- RIGHT→짧은 NONE→RIGHT는 한 동작 안의 출력 흔들림일 수도 있고 명령 두 번일 수도 있다. M은 중복률과 최소 반복 간격의 교환관계다.
- timeout만으로 강제 재무장하면 지속 오인식이 주기적인 명령으로 바뀔 수 있다. 초기에는 자동 반복을 넣지 않는다.
- 400/50 ms 창은 87.5% 중첩되므로 N회 확인은 독립 투표 N개가 아니다.

정지점에서 바로 재무장하면 늦은 복귀를 새 명령으로 볼 수 있다는 점에서 이전 motion-gate 제안 역시 복귀 문제를 보장하지 못했다. 이번 구조에서도 마찬가지로 출력 시퀀스와 실제 복귀 지연을 시험해야 한다.

## 4. NONE과 사용자 의도

idle, 손가락 미세 동작, 손목 자세 변경, 스틱 조작, 이불 접촉, 부분 제스처, 복귀 꼬리를 NONE의 하위 메타데이터로 보존한다. 학습 출력은 하나로 합친다. 현재 수집한 idle/other는 원본을 유지하며 재사용 후보로 둔다. 파형·길이·결측과 착용 조건을 확인하기 전 품질까지 검증 완료로 취급하지 않는다.

똑같은 IMU 궤적을 명령/비명령 의도로 각각 수행하면 IMU만으로 의도를 구분할 수 없다. 명령 동작에 일상 동작과 구별되는 재현 가능한 형태가 있는지 먼저 시험해야 한다. 모델이 의도를 직접 읽는다고 가정하지 않는다.

명령 방향의 좌표계도 고정한다. 화면 기준인지 손/반지 기준인지, 손을 뒤집었을 때도 같은 명령인지 정의해야 한다. 반지 회전·손 자세·전완 회전이 센서축에 영향을 준다. 무작위 축 회전이나 부호 반전을 라벨 유지 증강으로 쓰면 잘못된 학습이 될 수 있다.

## 5. 모델과 MCU

- 100 Hz, 400 ms = 40×6 입력. float32 원시 창은 960 bytes이며 50 ms stride는 5개 새 시점이다. 센서 ODR 104 Hz와 호스트 100 Hz 읽기는 동일하지 않으므로 시간 간격 검증을 유지한다.
- 첫 모델은 부호와 시간 순서를 보존하는 작은 1D CNN을 제안한다. receptive field가 필요한 왕복 맥락을 덮는지 점검한다.
- gyro 3축 vs accel+gyro 6축 비교. 6축 원본을 보존하면 재수집 없이 비교 가능하다.
- 순수 spectral power는 부호 반전·시간 순서를 잃을 수 있으나 Edge Impulse Spectral Analysis 전체가 반드시 모든 방향 정보를 잃는다고 단정하지 않는다. 비교 기준으로는 둘 수 있다.
- 정규화 통계는 학습 세션에서만 계산하고 PC/MCU에서 동일하게 적용한다. 각 창별 과도한 정규화는 정지 잡음을 키우거나 진폭 정보를 지울 수 있다.
- 최소 구현은 IMU 원형 버퍼에서 일정 stride마다 완전한 창을 복사하고 run_classifier를 호출하는 방식이다. run_classifier_continuous라는 함수명만 보고 임의 IMU/DSP 조합 지원을 가정하지 않는다.
- run_classifier는 blocking이다. 50 ms 안에 추론이 끝나더라도 그동안 10 ms 간격 샘플링을 멈추면 안 된다. FIFO/별도 수집 태스크 및 버퍼 전달, 타임스탬프/순번 누락 검증을 고려한다.
- 전체 전처리+추론+후처리 시간에 여유를 확보한다. 예를 들어 10 ms 추론을 초당 20회 하면 그 연산만 약 20% 시간을 쓴다. 전력은 실제 보드에서 측정한다.
- 25 ms stride는 100 Hz에서 2.5샘플이다. 20/30 ms 교대 스케줄 또는 보간 정책이 필요하며 이를 로그에 남긴다. 첫 실험은 정수 stride인 50 ms로 한다.

## 6. 실험 순서와 판정

### A. 파형 관측

방향별 20~30회 정도를 여러 짧은 연속 기록으로 받는다. 평소 빠르기, 느린 동작, 빠른 동작, 복귀 지연, 같은 방향 반복, 반대 방향 연속을 포함한다. 중립→이동→자연 복귀와 전후 대기를 그대로 남긴다. 명령 안내/키 입력 시각은 동작 경계와 같다고 가정하지 않고 파형·동기화 관찰로 확인한다.

지속시간 분포와 각 W에서 완전 포함 가능한 이벤트 비율, 확보되는 양성 창 수를 먼저 계산한다. 이 단계는 성능 주장용 데이터량이 아니다.

### B. 작은 기준 실험

400 ms / 50 ms / 6축 / 5클래스 / 작은 1D CNN을 출발점으로 삼되, A에서 400 ms가 맥락을 못 담으면 더 긴 창도 포함한다. 같은 원본에서 300/400/500/600 ms를 비교하고 이후 3축/6축, 후처리 값을 순차 비교한다. 최초부터 모든 조합을 탐색하지 않는다.

### C. 연속 replay

별도 세션의 원시 스트림 전체를 시간순으로 통과시킨다. 제스처 사이에 모델 출력 후처리 상태를 임의 초기화하지 않는다. 모든 창의 5개 점수, 이벤트 시각, 주석 이벤트를 저장한다. 시작 위상을 stride 내에서 바꿔 50 ms 격자 운에 민감한지도 확인한다.

시험 세션은 파라미터 선택에 사용하지 않는다. 사용자 간 일반화는 사람 단위 분리 평가가 있어야 주장할 수 있다. 첫 사용자 모델 성공과 여러 사용자 지원을 구분한다.

### D. 지표

- 정답 이벤트와 출력 이벤트를 사전에 정한 시간 허용 범위 내에서 일대일 매칭한다.
- 인식률, 잘못된 방향, 제스처당 추가 이벤트, 비명령 구간 FP/hour를 각각 보고한다.
- 의도한 제스처의 복귀에서 잘못 나온 반대 명령은 별도 항목으로 기록한다. NONE-only FP/hour만 보고하면 놓친다.
- 지연은 출발 시각 기준과 복귀 완료 기준을 함께 보고하고 median/p95를 구한다. 조기 출력은 복귀 완료 기준에서 음수일 수 있다.
- 이벤트 간격별 누락률을 측정해 최대 반복 속도를 보고한다.
- 후보 목표 예시: 개인별 인식률 95% 이상, 중복률 1% 이하, 비명령 FP 1회/시간 이하. 승인된 사양이나 달성 성과가 아니며 사용자 체감과 함께 확정한다.
- 10분에서 오작동 0회는 0 FP/hour의 보장이 아니다. 정상 Poisson 발생 가정에서 0건/T시간의 단측 95% 상한은 약 3/T회/시간이다. 10분이면 약 18회/시간, 3시간이면 약 1회/시간이다. 실제 동작 상관과 상황 다양성 때문에 이것만으로 실사용 보장을 하지 않는다.

## 7. 다음 구현물 제안

1. 타임스탬프/순번이 있는 원시 6축 기록과 별도 이벤트 주석.
2. 세션 분리 → causal window 생성 → 라벨 정책 적용 → Edge Impulse 학습 입력 내보내기.
3. 연속 replay와 출력 중복 제거 평가 도구.
4. 동일 전처리·축 순서·단위·int8 모델을 사용하는 MCU 통합 및 BLE 이벤트 시험.

이는 제안이며 이번 검토에서는 수집 펌웨어, 원격 프로젝트, 데이터 라벨, 학습 모델을 변경하지 않았다.
