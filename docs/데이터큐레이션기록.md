# 데이터 큐레이션 기록 (Data Curation Log)

데이터셋을 목적에 맞게 다듬은 결정을 한곳에 모은다. 무엇을, 왜 뺐는지만 짧게 적는다. 자세한 경과는 [진행기록](진행기록.md)의 해당 날짜에 있다.

원칙
- 원본은 지우지 않는다. 각 세션의 `excluded/` 폴더로 옮기고, 사유는 `excluded/EXCLUDED.txt`와 `data/annotations/ble-v2/records.json`(`excluded_by_user`: 경로·sha256·사유, `revisions`: 날짜·뺀 경로)에 남긴다.
- 분할은 다시 뽑지 않는다. 고정 분할(`data/splits/v2-*.json`)에서 뺀 경로만 지우고 `revisions`에 기록한다.
- 기준을 먼저 정하고 그 기준에 맞는 클립을 모두 뺀다. 모델 결과를 본 뒤에 정한 기준은 그렇다고 밝힌다.

### 3. 약한 동작 — 14개 (2026-10-28, 모델 무발행 진단 뒤)

제품 규칙: **약한 제스처는 명령으로 받지 않는다.** 사용자는 정상 세기로 동작하면 된다.
기준: 복귀 피크 세기 < 같은 방향 중앙값의 **0.6배**. 중앙값은 제외 전 294개 기준 UP 457, DOWN 444, LEFT 227, RIGHT 202 dps다(방향마다 정상 세기가 달라 방향별로 잰다).
학습과 평가에서 모두 뺐다. NONE으로 학습하지 않은 이유는 0.6배 바로 위 정상 동작과 경계가 너무 가까워서다.

| 세션 | 클립(복귀 세기 배율) |
|---|---|
| P1 | up.6 (0.45), up.7 (0.40), up.8 (0.36), up.9 (0.56), down.7 (0.57), down.8 (0.55), down.10 (0.59), down.11 (0.55), right.2 (0.51), right.5 (0.50) |
| P2 | right.1 (0.55), right.2 (0.58) |
| P3 | up.10 (0.54) |
| P5 | right.12 (0.49) |

- 주의: 기준은 S-P5 P1 fold의 무발행 클립 7개를 본 뒤 정했다. 그중 6개가 걸린다. 이후 정검출 상승의 일부는 어려운 클립을 뺀 효과다.
- 영향: P1(앉은 자세)에서 10개가 빠졌다. 그 자세에서는 사용자가 의식적으로 더 크게 동작해야 한다.
- 새 데이터에도 같은 기준(방향 중앙값의 0.6배)을 그대로 적용한다.
