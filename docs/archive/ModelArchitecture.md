# RingPilot 1D-CNN 아키텍처 설계 v1

> **보관 문서:** 처음 설계한 1D-CNN(v1)이다. 지금 쓰는 모델은 [모델 구조](../모델구조.md)를 본다.

이 문서는 **어떤 입력을 받아, 어떤 레이어를 거쳐, 어떤 출력을 만드는지** 정의한다. 구현 기준은 [모델 정의](../../ml/model.py)다. 학습·평가 절차는 [학습 계획](TrainingPlan.md), 수행 결과는 [진행기록_조현준.md](../진행기록_조현준.md)에서 관리한다. 아래는 첫 모델의 설계 사양이며 보드 통합 전이다.

새 BLE 실험의 출발 사양으로 사용한다. [실험 1~8 기록](../experiments/ble-v1/README.md)과 [최종 설계 결정 기록](../experiments/ble-v1/final-architecture.md)에 비교·채택 근거를 남긴다. 현재 구조가 최종 확정된 것은 아니다.

## 전체 구조

```text
IMU 6축 · 100 Hz
      │
      ▼
물리 단위 환산 + 축별 고정 정규화
      │
      ▼
최근 160행 버퍼 ── 새로운 5행마다 입력 갱신
      │
      ▼
1D-CNN ── 입력 (160, 6) → 출력 (5,)
      │
      ▼
동일 방향 연속 확인 + 중복 발행 방지
      │
      ▼
방향 이벤트 → BLE → Android 스와이프
```

CNN은 방향별 점수를 계산하고, 후처리 모듈은 그 점수를 보고 명령 발행 여부를 결정한다. BLE와 Android는 이후 연결할 출력 경로다.

## 입력 사양

| 항목 | 설계 |
|---|---|
| 센서 | 가속도 3축 + 자이로 3축 |
| 채널 순서 | accX, accY, accZ, gyrX, gyrY, gyrZ |
| 단위 | 가속도 m/s², 자이로 deg/s |
| 샘플링 | 100 Hz, 10 ms 간격 |
| 과거 입력 길이 | 160행, 1.6초 분량 |
| 텐서 크기 | `(batch, 160, 6)`; 한 번 판정할 때 batch=1 |
| 입력 형식 | 정규화한 float32 |
| 판정 주기 | 새 샘플 5행마다, 50 ms |

판정 시각 t는 마지막 실제 샘플의 timestamp다. 입력은 `t-1590 ms`부터 t까지의 160행이며 미래 샘플을 사용하지 않는다. 버퍼가 준비된 뒤에는 50 ms마다 판정한다.

## 전처리와 버퍼

1. 원시 센서 값은 물리 단위로 환산한다. 이미 물리 단위인 CSV에는 환산을 다시 적용하지 않는다.
2. 축별로 `z=(x-μ)/max(σ, 1e-6)`을 적용한다. μ와 σ는 훈련 원본에서 계산한 고정값 6개씩이다. 실행 중 창마다 다시 계산하지 않는다.
3. 축 부호와 중력 성분을 유지한 채 최근 160행을 순서대로 저장한다.
4. 새 샘플 5행이 들어오면 가장 오래된 5행을 밀어내고 CNN에 전체 창을 전달한다.

부팅·재개·샘플 누락 시에는 버퍼와 후처리 상태를 초기화한다. 연속 160행이 채워질 때까지 명령 출력을 막는다. CNN 자체는 이전 추론의 숨은 상태를 유지하지 않는다.

## CNN 레이어 구성

Conv1D는 시간 방향으로 이동하며 6축의 변화를 함께 처리한다. 모든 convolution은 stride=1, dilation=1, bias 사용이다. Pooling은 크기 2, stride=2, valid padding이다. 크기 표에서 batch 차원은 생략했다.

| 순서 | 레이어 | 설정 | 출력 크기 | 파라미터 |
|---|---|---|---:|---:|
| 1 | Input | 시간 160 × 채널 6 | 160 × 6 | 0 |
| 2 | Conv1D + ReLU | 필터 16, kernel 5, same padding | 160 × 16 | 496 |
| 3 | MaxPooling1D | 시간 길이 절반 | 80 × 16 | 0 |
| 4 | Dropout | 비율 0.20 | 80 × 16 | 0 |
| 5 | Conv1D + ReLU | 필터 32, kernel 5, same padding | 80 × 32 | 2,592 |
| 6 | MaxPooling1D | 시간 길이 절반 | 40 × 32 | 0 |
| 7 | Flatten | 시간·채널 특징 펼침 | 1,280 | 0 |
| 8 | Dropout | 비율 0.30 | 1,280 | 0 |
| 9 | Dense + Softmax | 클래스 5개 | 5 | 6,405 |
| | **합계** | | | **9,493** |

첫 Conv는 짧은 움직임 패턴을, 두 번째 Conv는 앞에서 추출한 특징들의 조합을 학습하도록 구성한다. Pooling은 시간 해상도를 줄인다. Flatten은 각 시간 위치의 특징을 별도 입력으로 유지하고, Dense는 전체 창의 특징을 결합해 최종 점수를 만든다. 중간 Dense 은닉층은 두지 않는다.

GAP 대신 Flatten을 선택한 이유는 완료 시점 판정에 쓸 시간 위치 단서를 유지하기 위해서다. Dropout은 학습 중 일부 값을 비활성화하며 실제 추론에서는 꺼진다.

Pooling 이후 한 위치의 국소 수용 범위는 16개 입력 샘플이다. 마지막 Dense가 모든 위치를 결합하므로 최종 출력은 전체 160행을 참조한다. same padding은 창 내부의 특징 계산에 사용되며, 창 끝 t 이후의 센서 값을 요구하지 않는다.

## 출력 사양

출력 텐서는 `(batch, 5)`이며 클래스 순서를 고정한다.

| 인덱스 | 클래스 | 의미 |
|---|---|---|
| 0 | NONE | 현재 새로 완료된 방향 명령 없음 |
| 1 | UP | 위 방향 제스처 완료 |
| 2 | DOWN | 아래 방향 제스처 완료 |
| 3 | LEFT | 왼쪽 방향 제스처 완료 |
| 4 | RIGHT | 오른쪽 방향 제스처 완료 |

v1의 완료 기준은 방향 이동 후 자연 복귀가 끝난 시점이다. 모델은 완료 후 150 ms 동안 해당 방향, 그 밖의 시각에는 NONE을 목표로 학습하도록 연결한다. NONE은 정지 상태만 뜻하지 않으며 동작 진행 중인 구간도 포함한다.

## 명령 발행 모듈

모델의 5개 출력 점수를 50 ms마다 받아 아래 상태를 갱신한다.

```text
버퍼 준비 → 발행 가능
               │
               │ 같은 방향이 2회 연속 조건 통과
               ▼
         방향 이벤트 1회 발행
               │
               ▼
           발행 잠금
               │
               │ 확실한 NONE 2회 연속
               └────────────→ 발행 가능
```

- 방향 후보: 최댓값 클래스가 방향이고, 점수 0.8 이상이며 두 번째 점수와 차이가 0.2 이상.
- 후보가 바뀌면 새 방향부터 횟수를 세고, 조건을 통과하지 못하면 후보 횟수를 초기화한다.
- 재무장: NONE이 최댓값이고 점수 0.8 이상인 판정이 2회 연속일 때 발행 잠금을 해제한다. 중간에 실패하면 NONE 횟수를 초기화한다.
- 잠금 중에도 CNN 추론은 계속하되 명령을 추가 발행하지 않는다.

점수 문턱과 연속 횟수는 첫 설정값이다. CNN의 레이어 구조와 별도로 조정할 수 있다.

## 자원 규모

| 항목 | 설계상 크기·계산량 |
|---|---:|
| 학습 파라미터 | 9,493개 |
| float32 파라미터 값 | 약 38 KB |
| float32 입력 버퍼 | 3,840 bytes |
| Conv/Dense 계산량 | 약 288,000 MAC/판정 |
| 20회/초 판정 시 | 약 5.76M MAC/초 |

파일 형식·중간 특징·런타임·BLE·스택 메모리와 전처리 비용은 별도다. 위 값은 설계 계산이며 보드의 실제 RAM 사용량이나 실행 속도는 아니다. 향후 배포는 int8 변환을 검토한다.
