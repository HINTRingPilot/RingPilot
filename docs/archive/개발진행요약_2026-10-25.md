# RingPilot 개발 진행 요약 및 실험 회고

> **보관 문서:** 2026-10-25 시점의 회고다. 이후 과정과 현재 상태는 [진행기록 요약](../진행기록요약.md)과 [시행착오 정리](../시행착오정리.md)를 본다.

기준일: 2026-10-25 · 목적: 연구·학습·포트폴리오 기록

> 하드웨어·통신 검증에서 시작해, 제스처 데이터 수집과 모델 보정 학습, 실패 원인 분석까지 진행했다. 현재는 최종 모델을 선정한 상태가 아니라 **데이터의 시간 라벨과 명령 발행 방식이 결과에 미치는 영향을 확인한 상태**다.
>
> 실배포는 목표가 아니다. 배포 모델 선정·보드 모델 탑재·출시 수준 운영 검증은 필수 완료 조건에서 제외한다. 측정 조건과 한계를 분명히 남기는 것을 우선한다.

## 1. 지금까지 한 일 한눈에 보기

| 단계 | 수행 내용 | 현재 상태 |
|---|---|---|
| 하드웨어·통신 | XIAO nRF52840 Sense, 스위치·배터리, Android BLE 연결·포인터·클릭 검증 | 기능 단위 확인 완료 |
| 데이터 수집 경로 | 보드의 100 Hz IMU 6축 BLE 스트림 → Android CSV 저장 → PC Python 분석 | 구현·수집 완료 |
| 초기 모델 실험(v1) | 학습·평가 코드가 동작하는지 확인 | 참고용 테스트로 보존 |
| 데이터 재수집(v2) | 자세별 5세션, 사용 가능한 방향 296개와 배경 40개 | 완료 |
| V2-prep | 4초 입력 대응·주석·분할·학습 환경·protocol 고정 | 완료 |
| 기준선 보정 | 6개 분할 × 5 seed, 총 125회 학습 | 완료 |
| 실패 진단 | 조기 발행·무발행·방향 오류·잠금·세션 차이 분해 | 완료한 범위의 근거 확보 |
| NONE 배분 비교 | 세션·클립 배분만 바꿔 125회 추가 학습 | 완료, 일관된 정검출률 개선은 확인 못 함 |
| 발행 지연 비교 | 저장 예측에 0~200 ms 지연을 적용해 재채점 | 완료, 추가 모델 학습 없음 |
| 영상 관찰 준비 | 첫 슬롯 sidecar 코드·순수 Java 검사 | 코드 준비, APK·실물·영상 미검증 |

정식 보정 학습은 **기준선 125회 + NONE 배분 비교 125회 = 250회**다. 각 학습에서 여러 epoch의 예측을 저장한 것이므로, epoch 후보 7개를 곱해 별도 학습 횟수로 세지 않는다. 코드 점검용 짧은 학습은 별도다.

## 2. 개발 방향이 바뀐 과정

### 2.1 먼저 통신과 입력 장치를 확인했다

Arduino/Bluefruit 기반으로 BLE HID와 Custom GATT를 구성했다. Galaxy S10에서 포인터 이동·클릭, 알림 수신과 재연결을 확인했고, 이후 스위치 5개 입력·55mAh 배터리 구동·센터 버튼 System OFF도 확인했다.

이는 **입력·통신·전원 기능의 확인**이다. 학습 모델이 실제 보드에서 제스처를 인식했다는 검증은 아니다.

근거: [하드웨어 보고서](../HardwareBuild.md), [BLE 테스트 기록](BLE테스트.md), [전체 진행기록](../진행기록.md).

### 2.2 초기 데이터와 실험을 그대로 이어받지 않았다

USB·Edge Impulse 경로에서 휴대폰 BLE 수집·로컬 Python 학습으로 전환했다. 초기 BLE v1 실험은 사용자 확인에 따라 정식 성능 비교가 아닌 코드 동작 확인용 테스트로 정리했다.

2026-10-23에는 펌웨어와 앱의 자이로 범위 환산 불일치를 발견했다. 기존 테스트 데이터는 사용자 결정으로 삭제하고 문서·Git 이력은 보존했다. 불일치가 모든 과거 원본을 실제로 얼마나 왜곡했는지까지 확정한 것은 아니다.

이후 새 앱의 ±2000 dps 환산을 확인하고 v2 데이터를 다시 수집했다. v1의 최고 수치나 후보 모델 선정은 v2의 근거로 이어받지 않았다.

## 3. V2 데이터와 실험 조건

### 데이터 구성

| 세션 | 자세 | 사용 방향 클립 |
|---|---|---:|
| P1 | 앉은 자세 | 58 |
| P2 | 누워 팔을 내린 자세 | 60 |
| P3 | 누워 팔을 90도 올린 자세 | 59 |
| P4 | 돌아누워 팔을 꺾은 자세 | 60 |
| P5 | 돌아누워 팔을 꺾지 않은 자세 | 59 |
| **합계** | **5세션** | **296** |

배경은 idle 15개·other 25개로 총 40개다. 사용 원본은 **336개**이며, 사용자 제외 5개는 사유와 함께 별도로 보존했다.

- 센서: 100 Hz, 가속도·자이로 6축, 자이로 범위 ±2000 dps.
- 방향 클립: 4초, 400행, 기록 시작 1초 후 동작 안내. 배경 클립: 10초.
- 사용 원본 336개의 0 시작·10 ms 간격·행 수 검사가 통과했다.
- 완료 시각 후보는 1840~3530 ms, 중앙값 2450 ms다. 방향 296개 모두 양성 창 3개를 확보했다.
- 완료 시각은 센서 기반 자동 후보다. 영상으로 실제 복귀 완료와 일치하는지 확인하지 않았다.

### 모델과 시간 규칙

| 항목 | 조건 |
|---|---|
| 모델 | 2층 CNN, Flatten, 5클래스(NONE·상·하·좌·우), 9,493 파라미터 |
| 입력 | 160행 × 6축, 1.6초 창 |
| 판정 | 50 ms 간격, 첫 판정 1590 ms |
| 방향 라벨 | 자동 완료 시각 e부터 150 ms 미만까지 |
| 나머지 라벨 | NONE. 복귀 도중도 포함 |
| 발행 | 방향 점수 ≥.8, 1·2위 차이 ≥.2를 같은 방향으로 2회 연속 충족 |
| 재무장 | 발행 후 잠금, 확실한 NONE 2회로 해제 |
| 성공 | e부터 e+500 ms 안에 같은 방향을 발행한 경우 원본당 1회 |

이 문서의 **정검출률**은 위 성공 조건을 충족한 방향 원본의 비율이다. 창 단위 분류 정확도, 방향만 맞힌 비율, 실제 휴대폰 조작 성공률과는 다르다. 방향이 맞아도 e 전에 발행하면 조기 발행으로 센다.

### 분할과 학습 방식

- **S:** 한 세션 전체를 보류한다. 공식 S는 P5이며 방향 학습 237개·평가 59개다. P1~P4도 보류 세션을 바꿔 보정했다.
- **C:** 세션×방향마다 3개씩 보류한다. 방향 학습 236개·평가 60개다.
- 보정은 학습용 내부에서만 한다. S는 4개 세션 fold, C는 5개 클립 fold이며 학습 무작위성 seed는 5개다.
- 한 번 60 epoch까지 학습하면서 1·5·10·20·30·40·60 epoch의 예측을 저장했다.
- 선택 점수는 `(정검출 − 방향 원본 미매칭 발행) / 방향 원본 수`. 5 seed 평균 최대 E를 고르고 동점이면 작은 E를 고른다. 배경 오발행은 별도 보고한다.

환경: Windows CPU, Python 3.12.10, TensorFlow 2.21.0, Keras 3.15.1, NumPy 2.5.4. 정규화는 fold 학습 부분만 사용하고 검증 NONE은 줄이지 않았다.

## 4. 주요 실험 결과

### 4.1 기준선 보정: 낮은 정검출률과 많은 조기 발행

각 분할에서 선택한 E의 **내부 교차검증 5 seed 평균**이다.

| 분할 | 선택 E | 정검출률 |
|---|---:|---:|
| S-P5 | 60 | 34.4% |
| C | 1 | 17.8% |
| S-P1 | 1 | 12.3% |
| S-P2 | 1 | 11.4% |
| S-P3 | 5 | 26.8% |
| S-P4 | 1 | 9.6% |

미매칭 발행의 주된 분류는 조기 발행이었다. 그러나 실패가 전부 조기 발행인 것은 아니다. 선택 E에서 S-P5는 33.8%, C는 57.1%의 방향 클립에서 발행 자체가 없었다.

**해석:** 낮은 점수를 보고 바로 모델 구조를 바꾸기보다, 무발행과 발행 시점 문제를 분리할 필요가 생겼다. 선택 점수가 낮은 오발행을 선호하면서 정검출도 적은 E를 고를 수 있다는 점도 드러났다.

근거: [기준선 기록](../experiments/ble-v2/README.md), [첫 진단 보고서](../experiments/ble-v2/diagnostics/calibration-2026-10-25/calibration-diagnostics.md).

### 4.2 NONE 세션 편중: 구현상 배분 문제는 확인했지만 효과는 별개였다

기존 선택기는 같은 종류의 NONE을 경로 순서로 배분했다. 할당량이 한 바퀴를 다 돌기 전에 차면서 일부 세션이 배제됐다. C의 보정 학습에서 P5 방향 클립의 진행 중·완료 후 NONE은 선택되지 않았다.

양성·NONE 총량·종류별 수·클립 안 창 우선순위는 유지하고 **세션·클립 배분만 균등화**해 비교했다.

| 분할 | 선택 E 기존→새 | 정검출률 기존→새 |
|---|---|---:|
| S-P5 | 60→1 | 34.4%→13.0% |
| C | 1→1 | 17.8%→15.5% |
| S-P1 | 1→1 | 12.3%→12.2% |
| S-P2 | 1→1 | 11.4%→9.1% |
| S-P3 | 5→1 | 26.8%→10.5% |
| S-P4 | 1→1 | 9.6%→8.4% |

새 E는 모두 1이었다. 점수는 5개 분할에서 상승했지만 정검출률은 모두 낮아졌다. 특히 S-P5·S-P3는 E까지 달라졌으므로 감소 폭 전체를 배분 변경의 효과로 해석하면 안 된다.

같은 E60에서는 C 36.95%→39.07%, S-P5 34.43%→31.81%로 방향이 달랐다.

**판단:** 세션 편중은 해소했지만 일관된 정검출 성능 개선은 확인하지 못했다. 기본 선택기는 교체하지 않았다. 배분 결함을 발견한 것과 그 결함이 낮은 성공률의 주원인임을 입증한 것은 구분했다.

근거: [NONE 배분 비교](../experiments/ble-v2/none-balance-01/README.md), [모든 E의 대응 비교](../experiments/ble-v2/none-balance-01/comparison.md).

### 4.3 발행 시점·잠금: 같은 모델도 발행 시각에 따라 결과가 크게 달라졌다

원래 예측을 그대로 사용해 발행 후보만 0·50·100·150·200 ms 뒤로 예약했다. 모델을 다시 학습하지 않았고 e·정답 방향을 발행 판단에 넣지 않았다. 내부 잠금은 원래 후보 시각에 시작했다.

모든 지연에 공통으로 관측할 수 있는 후보 구간만 사용해 비교했다. 따라서 이 표의 D0는 앞선 전체 클립 결과와 관측 구간이 약간 다르다.

| 원래 E60 모델 | D0 | D50 | D100 | D150 | D200 |
|---|---:|---:|---:|---:|---:|
| S-P5 정검출률 | 34.3% | 38.6% | 41.7% | 44.5% | 45.7% |
| C 정검출률 | 36.9% | 45.9% | 57.2% | 64.2% | 70.4% |

공통 구간의 조기 발행 클립 비율은 D0→D200에서 S-P5 30.4%→13.2%, C 63.4%→33.9%로 감소했다. 무발행과 배경 발행은 해결되지 않았다. C의 무지연 원시값은 약 36.949%이며 이 표는 한 자리로 직접 반올림했다. 앞선 보고의 약 37.0%와 같은 관측을 가리킨다.

원래 전체 클립에서 누락된 관측 중, 정답 방향의 연속 점수가 성공 구간에 있어도 앞선 발행으로 잠겨 있던 경우는 C E60 632/744, S-P5 E60 233/777이었다. 분모는 같은 원본을 5 seed에서 반복한 관측이다. 잠금을 제거하면 그만큼 성공이 늘어난다고 계산한 결과는 아니다.

**판단:** 낮은 정검출률을 모델의 방향 구분 실패 하나로 설명하기 어렵다. 시간 경계와 발행 상태가 결과에 크게 관여한다. 다만 D200의 70.4%는 **자동 완료 시각 기준의 개발용 재채점 결과**이며 최종 정확도나 전체 프로젝트의 대표 정확도가 아니다. 200 ms를 기본값으로 채택하지 않았다.

근거: [발행 시점 진단](../experiments/ble-v2/event-timing-01/README.md), [지연별 전체 결과](../experiments/ble-v2/event-timing-01/delay-comparison.md).

## 5. 왜 낮고 편차가 큰가 — 사실과 가설

| 구분 | 확인된 사실 | 해석·남은 질문 |
|---|---|---|
| 발행 시점 | 고정 지연만으로 C E60의 정검출률이 크게 변함 | 많은 발행이 자동 e보다 이르다. 모델이 빠른지, e가 늦은지는 미확정 |
| 잠금 | 앞선 발행 후 정답 구간의 점수가 막히는 사례 재현 | 직접 실패 경로는 확인. 잠금 변경의 전체 효과는 별도 비교 필요 |
| 무발행 | S-P5 E60에서 약 34%가 발행 없음 | 방향 점수·margin·연속 조건 중 무엇이 주로 막는지 추가 해석 가능 |
| 세션 차이 | 기존 S-P5 E60 내부 보정의 P2 평균 약 52%, P3 약 11% | 자세뿐 아니라 세션·동작·착용과 fold 학습 구성도 함께 달라 순수 자세 효과로 단정 불가 |
| NONE 배분 | 경로 순서 편중과 특정 세션 배제 확인 | 균등화로 편중은 해소. 일관된 성능 개선은 입증 못 함 |
| 라벨 경계 | e 이후 150 ms만 방향, 그 직전은 NONE | 비슷한 구간을 시간적으로 구별해야 함. 이것이 최선의 정책인지는 미확정 |
| 데이터 범위 | 한 사용자·같은 날·5개 자세 세션 | 일반화 범위가 제한됨. 단순히 데이터 수만 늘리면 해결된다는 증거는 없음 |

**현재의 작업 가설:** 시간 라벨·학습·발행 규칙의 결합이 주요 조사 대상이다. 데이터셋 전체가 불량하다거나, 모델 크기가 작아서 실패했다거나, 완료 주석 하나가 근본 원인이라고 확정하지 않는다.

### 편차를 읽을 때 구분한 것

- **분할·E가 다른 결과:** 9.6~34.4%는 같은 모델 조건의 반복 범위가 아니다.
- **같은 설정의 seed 차이:** 원래 E60의 정검출률은 S-P5 약 29~39%, C 약 35~38%였다.
- **검증 세션 차이:** P2/P3 차이는 세션뿐 아니라 그 fold에서 학습한 자료도 달라진 결과다.
- **S/C 차이:** 평가·검증 구성이 다르므로 두 수치를 빼서 순수 자세 효과나 알고리즘 우열로 해석하지 않는다.

## 6. 실험 신뢰성을 위해 남긴 것

- 학습 전에 코드·주석·분할·선택 규칙을 protocol과 해시로 고정했다.
- 원본을 먼저 나누고 fold 학습 자료만으로 정규화했다. 검증에서 NONE을 줄이지 않았다.
- 같은 seed로 짧은 학습의 재현성을 확인했고, 중간 snapshot과 해당 epoch에서 끝낸 별도 학습을 비교했다.
- 텍스트 줄바꿈에 따른 해시 차이를 정리하고, 과거 결과는 당시 코드 버전으로 확인하도록 했다.
- 기존 보호 702개 파일과 NONE 비교 입력을 보존하면서 새 결과를 별도 경로에 저장했다.
- 마지막 구현 검증에서는 Python 167개와 sidecar 순수 Java 테스트가 통과했다. 이 수치는 테스트 실행 당시의 기록이며 모델 성능 수치가 아니다.
- 상태 추적에서는 25패널·33,545개 원본×seed×E 관측을 저장 발행과 대조했다. 반복 관측을 새로운 독립 데이터 수로 부풀리지 않았다.
- 조기 발행 안에 숨어 있던 방향 불일치, 무발행, 클립 끝 미완료 예약도 별도 표시했다.

### 평가 자료 사용에 대한 정정

각 분할 내부에서는 자기 평가용을 보정에서 제외했다. 그러나 S 회전과 C를 합치면 전체 336개가 다른 분할의 보정 검증에 사용됐다. 따라서 이후 결과를 보고 만든 개선판을 이 자료로 독립 최종 평가했다고 말할 수 없다.

이번 프로젝트는 연구용 비교로 계속 정리할 수 있다. 향후 **독립 일반화 성능**까지 주장하려는 경우에만 별도 자료·평가 설계를 추가한다. 실배포가 목적이 아니라는 이유로 측정 조건이 바뀌는 것은 아니지만, 배포용 검증을 모두 수행해야 할 필요도 없다.

## 7. 현재 결론과 선택

### 현재까지 내릴 수 있는 결론

1. 수집→분할→학습→예측 저장→명령 발행→채점→실패 진단의 실험 경로를 구축했다.
2. NONE 배분의 세션 편중은 발견·대조했지만, 이를 낮은 성공률의 주원인으로 확정하지 못했다.
3. 같은 모델의 발행 시각만 바꿔도 정검출률이 크게 달라져, 시간 기준과 후처리를 분류 성능과 함께 봐야 함을 확인했다.
4. 자동 e의 실제 동작 타당성과 세션 차이의 원인은 아직 결론이 없다.
5. 최종 모델 선정·기본 선택기/발행 정책 교체는 하지 않았다.

### 연구·포트폴리오 관점의 해석

의미 있는 성과는 최고 수치 하나보다 **낮은 결과를 분해하고, 가설을 한 요인씩 비교하며, 반대 결과도 보존한 과정**이다. 세션 균등화가 성공률 개선으로 이어지지 않았다는 결과도 실험 기록에 포함한다.

재현 가능한 파이프라인·분할 누수 점검·시간 라벨과 상태기계의 상호작용 분석은 설명 가능한 수행 성과다. 실제 복귀 완료가 검증되지 않은 70.4%를 '스마트링 인식 정확도'라고만 쓰는 것은 피한다.

## 8. 남은 작업 — 목적에 따라 선택

| 후속 작업 | 필요한 경우 | 현재 상태 |
|---|---|---|
| 무발행/상태 추적을 원본 사례 중심으로 설명 | 현재 모델의 실패를 더 자세히 회고할 때 | 추적 코드·기록 있음, 추가 해석 가능 |
| 자동 e를 영상과 비교 | 실제 자연 복귀 완료와 맞는다는 주장을 할 때 | 동기화 준비·기록 코드만 있음, 관찰 미실행 |
| 다른 잠금·재무장 정책의 단일 요인 비교 | 후처리 영향 연구를 더 진행할 때 | 별도 protocol이 필요한 다음 후보 |
| 새 라벨·입력·모델 학습 | 가중치 재학습이 필요한 가설을 정했을 때 | 아직 요인 미확정 |
| 독립 최종 평가 | 개발 자료 밖의 일반화 성능을 주장할 때 | 미실행, 별도 자료 필요 |
| 보드 탑재·출시/운영 검증 | 실배포까지 목표를 확장할 때 | 현재 필수 범위에서 제외 |

성공률·허용 오발행·허용 지연의 제품 수치는 이전 계획에서는 미합의였다. 사용자 확인으로 실배포가 목적이 아님이 명확해졌으므로, 연구용 분석과 기록을 마무리하는 데 이 수치를 반드시 합의할 필요는 없다. 향후 후보를 채택하거나 실제 사용 적합성을 주장할 때만 필요한 기준을 별도로 정한다. 과거 protocol의 미합의 값은 소급 수정하지 않는다.

영상 기록용 sidecar는 첫/마지막 보드 슬롯·도착·캡처 시각을 별도 JSON으로 남기도록 구현했다. 순수 Java 검사는 통과했으나 APK 빌드·폰 설치·BLE/영상 시간 대응은 미검증이다. **이번 회고를 위해 촬영이나 빌드를 반드시 끝낼 필요는 없으며**, 영상 검증을 했다는 주장만 남기지 않으면 된다.
