# V2 발행 시점·잠금 진단 및 다음 학습 결정 계획

작성: 2026-10-25. 기준 커밋 `a4e3494`. **계획 작성 단계이며 아래 분석·수정·촬영을 새로 실행한 기록이 아니다.**

**목표:** 명령 성공률이 낮은 원인을 무발행·발행 시점·잠금·자동 완료 주석으로 나눠 확인하고, 제품 목표에 맞는 다음 변경 하나를 정한다.

**접근:** 학습 결과와 원래 규칙은 보존한다. 기존 예측으로 상태를 추적한 뒤 발행 지연 한 요인의 개발용 민감도만 비교한다. 영상 독립 관찰은 별도 갈래로 진행한다. 원인이나 후보가 정해지기 전에 125회 학습을 반복하지 않는다.

**실행 담당자:** `executing-plans` 방식으로 단계별 완료 조건을 확인한다. 이번 문서는 실제 수행 승인을 다시 요구하는 절차가 아니라 다음 작업의 범위·판단 근거를 고정하기 위한 계획이다.

## 1. 출발점과 보존할 것

- 원래 보정: 6개 분할·125회 학습 완료. 선택 E의 S-P5/C 정검출률 34.4%/17.8%.

**보존 대상:** 기존 데이터·주석·분할·protocol·config·summary·모델 예측과 모든 현재 학습/실행 모듈. 원래 보호 manifest에 더해 NONE 비교의 코드·spec·protocol·결과·NPZ도 입력 해시 목록에 고정한다. 기존 결과 파일을 새 코드에 맞춰 덮어쓰지 않는다.

이 계획은 앞선 완료 주석 확인 계획에서 끝난 A/B와 NONE 비교를 반복하지 않는다. 미실행인 영상 파일럿과 새 발행 상태 진단을 이어 간다.

## 3. 단계 2 — 저장 예측으로 발행·잠금 상태 분해

- 보조 패널: 같은 두 분할의 E1 및 각 전략의 원래 선택 E, NONE 층화 버전의 동일 조건. 선택 E가 다른 결과와 같은 E 결과를 구분한다.

## 4. 단계 3 — 고정 발행 지연 한 요인의 개발용 replay

**목적:** 일찍 확정한 명령을 일정 시간 뒤에 실행하는 것만으로 시간 채점이 얼마나 달라지는지 확인한다. 센서 기반 e의 오류를 증명하는 실험이나 잠금 제거 실험이 아니다.

### 실행 전 고정

- [ ] 별도 spec/protocol에 후보 추가 지연 `D={0,50,100,150,200} ms`, 분석 패널, 지표, 관측 범위를 저장한다. 결과를 보고 후보를 늘리거나 가장 좋은 지연을 클립/자세/정답에 맞춰 다르게 적용하지 않는다.
- [ ] 후보 생성은 원래 모델 점수와 원래 상태기계 그대로다. 후보 발생 시각 t의 명령을 `t+D`에 예약하고 내부 잠금은 원래 t에 시작한다. 별도 취소·방향 변경·재무장 변경은 도입하지 않는다.
- [ ] 구현은 판정 시각과 모델 점수만 받는다. e·정답 방향·영상 주석·파일 이름을 발행 판단에 사용하지 않는다. '조기 발행이면 기다린다'처럼 정답을 알아야 하는 규칙을 만들지 않는다.
- [ ] D=0은 원래 발행과 정확히 같아야 한다. D>0도 같은 후보의 방향·순서를 보존하고 시각만 D만큼 미룬다.

### 클립 끝에서 비교가 유리해지는 문제 처리

- [ ] 주 비교는 모든 후보에 공통으로 관측 가능한 후보 발생 구간을 쓴다. 원본의 마지막 판정 시각 T, 최대 지연 200 ms에 대해 원래 후보 발생 시각 `t<=T−200 ms`인 후보만 **D=0에도 똑같이** 사용한다. 모든 예약 명령이 원본 안에서 관측 가능해진다. 정답/e에 따라 잘라내지 않는다.
- [ ] 주 비교의 무지연 기준도 이 공통 구간으로 다시 계산한다. 이를 기존 전체 클립 기준선과 섞지 않는다. 배경 분모는 실제 공통 판정 구간으로 다시 기록한다.
- [ ] 전체 클립 보조 결과도 따로 기록한다. `t+D>T`인 예약은 관측 끝의 미완료 건수로 표시하며 조용히 삭제하거나 마지막 시각으로 당기지 않는다. 이런 경우를 제외해 오발행이 줄었다고 주장하지 않는다.
- [ ] 원래 허용 구간이 잘린 P4 `raw_left.16` 등 관측 한계는 계속 별도로 표시한다. e·성공 허용 구간·라벨 폭은 바꾸지 않는다.

### 보고와 판단

- [ ] 정검출·무발행·조기 발행 클립 비율, 시간×방향 교차표, 종류별 미매칭/원본, 배경 발행·관측 구간, 성공 표본 수와 지연 median/p95, 관측 끝 미완료 건수를 후보별로 보고한다.
- [ ] 같은 모델·seed·원본끼리 D−D0 차이와 seed별 상승/하락/동일 개수를 기록한다. 지연이 늘면 일부 조기 발행이 맞는 시각으로 이동하더라도 다른 발행이 늦은 실패로 바뀌는지도 확인한다.
- [ ] 고정 지연은 아예 발행하지 않은 원본을 복구할 수 없다. 무발행 감소나 모델 분류력 향상으로 해석하지 않는다.
- [ ] 단계 1의 요구가 있으면 정검출 하락·미매칭/배경 증가·추가 지연 등으로 조건에 미달한 후보를 명시한다. 요구가 없으면 후보별 교환관계 표까지만 만들고 자동 채택하지 않는다.

완료 조건: 재학습 없이 고정된 5개 후보의 개발용 민감도 표가 생성되고, 정답 누수·미래 참조·끝부분 삭제가 없다. 영상 확인 전에는 '현재 자동 e를 기준으로 한 결과'로만 기록한다.

## 5. 단계 4 — 완료 주석의 독립 확인을 병행

이전 계획의 미실행 영상 갈래를 이어 간다. 준비가 안 돼도 단계 2/3의 읽기 전용 분석은 할 수 있다.

- [ ] 코드: 클립별 첫 보드 슬롯과 캡처 시각 sidecar를 별도로 저장하는 앱 변경을 설계·검증한다. CSV 형식과 기존 원본은 유지한다. 첫 슬롯만 저장한다고 영상 동기화가 완성되는 것은 아니다.
- [ ] 사용자: 동작이 보이는 촬영 기기·고정 방법·영상 보관 위치를 준비한다. 실제 영상 프레임 PTS를 사용하고 명목 FPS로만 환산하지 않는다.
- [ ] 센서 시각과 영상의 연결 표식은 분석할 4초 클립 밖에서 기록한다. 두드림의 진동 전달 오차나 LED의 샘플 시각 대응을 실제로 측정한다. 비프와 CSV 0 ms가 같다고 가정하지 않는다.
- [ ] 먼저 파일럿 3개에서 offset·드리프트·반복 오차를 측정한다. ±50 ms는 최대 절대 시간 대응 오차의 작업 목표로 통일하며, 기존 ±26 ms 추정치를 실측으로 쓰지 않는다. 이 목표를 충족할 근거가 없으면 완료 시각 수정 근거로 사용하지 않는다.
- [ ] 통과 후 초기 개발 관찰 20개(5자세×4방향×1회)를 수집한다. 이 수량은 진단 시작 제안이며 성능 검증의 충분한 표본 수가 아니다.
- [ ] 모델 발행·자동 e를 가린 상태에서 사람이 완료 가능한 프레임 구간을 먼저 표시한다. 시각 대응 불확실성을 포함해 센서 시간의 `[human_lo,human_hi]`로 남긴 후 자동 e를 공개한다. 가시성 부족·관찰자 불일치도 기록한다.

완료 조건: 판정 가능한 수와 자동 e의 구간 안/앞/뒤 관계, 동기화·관찰 오차가 설명된다. 과거 296개에 영상 정답을 소급 적용하지 않는다. 이 자료도 개발 자료다.
