# RingPilot 제스처 인식 모델 구조

지금 반지에 들어간 모델과 판정 방식을 한곳에 정리한 문서다. 기준일은 2026-11-17이고, 모델 조건 이름은 `newtcnrotwarpnoacc`이다. 여기까지 온 과정은 [시행착오 정리](시행착오정리.md)에 있다. 처음 설계한 1D-CNN은 [archive/ModelArchitecture.md](archive/ModelArchitecture.md)에 남겨 두었다.

코드 기준:

| 부분 | 파이썬(학습·평가) | C(보드) |
|---|---|---|
| 모델 정의 | [`ml/model.py`](../ml/model.py) `build_tcn` | [`gesture_tcn.c`](../firmware/gesture_infer/src/gesture_tcn.c) |
| 입력 처리·학습 조건 | [`ml/v2_return.py`](../ml/v2_return.py), [`ml/v2_stream.py`](../ml/v2_stream.py) | `gt_prepare`, [`gesture_runtime.c`](../firmware/gesture_infer/src/gesture_runtime.c) |
| 발행 규칙 | [`ml/v2.py`](../ml/v2.py) `issue_events`, [`ml/v2_erase.py`](../ml/v2_erase.py) | `gesture_runtime.c` |
| 가중치 변환 | [`ml/v2_export_c.py`](../ml/v2_export_c.py) | [`gesture_weights.h`](../firmware/gesture_infer/src/gesture_weights.h) |

## 전체 흐름

```
IMU 자이로 100 Hz ─▶ 영점 빼기 ─▶ 입력 6채널 × 160샘플(1.6초) ─▶ TCN ─▶ 5클래스 점수 ─▶ 발행 규칙 ─▶ BLE로 명령
                    (정지 구간에서 갱신)                          (50 ms마다)                     (발행 뒤 입력 초기화)
```

판정은 50 ms(5샘플)마다 최근 1.6초를 보고 한다. 모델은 "지금 이 순간 동작이 끝나 가는가"를 점수로 내고, 발행 규칙이 그 점수를 명령으로 바꾼다.

## 입력

| 항목 | 값 |
|---|---|
| 센서 | LSM6DS3TR-C 자이로, ±2000 dps, 100 Hz. 사용자 빌드에서는 가속도계를 끈다 |
| 창 | 160샘플(1.6초), 판정 간격 5샘플(50 ms) |
| 채널 | 자이로 3축(gyrX·Y·Z) + 회전각 3축(angX·Y·Z) = 6채널 |
| 정규화 | 채널마다 학습 창의 평균·표준편차로 표준화(회전각 포함) |

- **영점(자이로 바이어스):** 최근 0.5초(50샘플)가 정지 상태(축별 표준편차 3 dps 미만)일 때 그 구간의 중앙값으로 갱신한다. 동작 중에는 직전 정지 구간의 값을 그대로 쓴다.
- **회전각:** 영점을 뺀 자이로를 창 안에서 적분하고, 창 첫 샘플을 0으로 맞춘 뒤 45°로 나눈다. 같은 세기의 자이로 피크라도 "어느 쪽으로 갔다가 돌아오는 중인지"를 구분하게 하려고 넣었다.
- **가속도를 쓰지 않는 이유:** 손목 방향이 바뀌면 가속도에 섞인 중력이 크게 달라져, 처음 보는 자세에서 성능이 떨어졌다. 가속도를 빼자 세션 하나를 통째로 뺀 교차검증(S 분할) 평균 정검출이 91.98 → 97.06%로 올랐다.

## 모델: 인과 TCN

| 항목 | 값 |
|---|---|
| 구조 | 인과(causal) 팽창 합성곱 블록 6개 + 잔차 연결 |
| 블록 | Conv1D(필터 16, 커널 3, ReLU) → Dropout 0.1 → 입력과 더함. 첫 블록만 1×1 합성곱으로 채널 수를 맞춰 더함 |
| 팽창(dilation) | 1, 2, 4, 8, 16, 49 |
| 수용 영역 | 161샘플(창 160샘플 전체) |
| 출력 | 마지막 시점의 특징 16개 → Dense → softmax 5클래스(NONE·UP·DOWN·LEFT·RIGHT) |
| 파라미터 | 약 4,400개(float32) |
| 정규화 층 | 없음 |

마지막 팽창을 32가 아니라 49로 둔 것은 수용 영역이 창 길이(160)를 정확히 덮게 하려는 것이다.

**보드 구현:** 판정에 쓰는 것은 마지막 시점 출력 하나뿐이라, 각 블록에서 그 출력에 필요한 위치만 계산한다(블록별 93·45·21·9·3·1칸). 곱셈-누산은 판정 한 번에 약 9.6만 번이다. PC에서 C 구현과 Keras를 비교한 점수 최대 오차는 5.1e-7, 발행 시각·방향 차이는 0건이었다.

## 학습

| 항목 | 값 |
|---|---|
| 데이터 | 자세를 달리한 5세션(P1~P5)의 4초 클립 334개(방향 294, 배경 40) |
| 정답(양성 창) | 시점 r부터 150 ms 동안 끝나는 판정 창. r = 복귀 피크 뒤 주축 자이로가 피크의 절반으로 내려온 시점 |
| NONE | 양성이 아닌 창(배경 클립, 방향 클립의 나머지 구간)에서 양성 창과 같은 수만큼 종류·클립별로 고르게 뽑음 |
| 증강 | 회전 증강(Y축 ±30°, 기울기 ±15°)과 속도 증강(0.8~1.25배)을 함께 적용한 사본을 클립당 2개 추가 |
| 최적화 | Adam(학습률 0.001), sparse categorical cross-entropy |
| 에폭 | 교차검증에서 1·5·10·20·30·40·60 중 고르고, 보드 모델은 60 |
| 보드 모델 | 334개 전체로 학습(seed 20261021, 60 에폭). 남는 데이터가 없어 이 모델 자체의 성능 수치는 없다 |

정답을 "손이 완전히 멈춘 시점"이 아니라 "복귀 도중"으로 둔 이유: 완전히 멈춘 시점은 작은 떨림까지 기다려 늦게 잡히고 그 앞뒤 창의 차이도 거의 없었다. 복귀 도중으로 옮기자 발행 지연이 약 180 ms 줄었다.

## 발행 규칙

모델 점수를 그대로 명령으로 쓰지 않고 아래 규칙을 거친다.

1. **후보:** 가장 높은 방향 점수가 0.8 이상이고 두 번째 점수와의 차이가 0.2 이상이면 그 방향이 후보가 된다.
2. **발행:** 같은 후보가 판정 2번 연속(50 ms 간격)이면 발행한다.
3. **잠금:** 발행 뒤에는 NONE 점수 0.8 이상이 2번 나올 때까지 다른 발행을 하지 않는다. 한 동작에서 명령이 두 번 나가는 것을 막는다.
4. **발행 후 입력 버퍼 초기화:** 발행 3판정(150 ms) 뒤, 그때까지의 자이로를 영점 값으로 바꿔 앞 동작이 다음 판정 창에 남지 않게 한다. 빠르게 이어 하는 동작이 인식되지 않던 문제를 재학습 없이 해결했다.
5. **명령 없이 끝난 움직임 초기화:** 300 dps를 넘는 움직임 뒤 150 ms 동안 30 dps 미만으로 조용하면, 발행이 없었어도 같은 방식으로 입력을 지운다.

앱에서는 위·아래 명령으로 스와이프하고, 왼쪽·오른쪽 명령은 상하·좌우 모드 전환으로 쓴다.

## 성능과 한계

| 항목 | 값 | 조건 |
|---|---|---|
| 정검출 | S 분할 평균 97.06%, C 98.3% | PC 교차검증, seed 5개 평균 |
| 위·아래 정검출 | 96.1%(S-P3), 96.9%(S-P5) | 현재 앱 규칙으로 재채점 |
| 판정 시간 | 중앙값 13.95 ms | 보드 실측, USB 연결, 정지 상태, 2026-11-16 |
| 보드 메모리 | 프로그램 약 159 KB, 전역 변수 약 51 KB | 빌드 크기 |

- 정검출은 동작 클립 안에서 정답 방향 명령이 나오고 다른 방향 명령은 나오지 않은 비율이다.
- 334개 클립이 모두 개발에 쓰여 독립 평가 데이터가 없다. 위 정검출은 개발용 교차검증 값이다.
- 명령이 아닌 일상 움직임에서 클립당 약 0.2건의 오발행이 나온다. 쓰지 않을 때는 일시정지하는 사용법을 전제로 한다.
