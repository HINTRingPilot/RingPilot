## 주요 관찰

아래는 원래 모델 E60의 **공통 후보 발생 구간** 결과다. `t≤T−200 ms`를 D0에도 동일 적용했으므로 기존 전체 클립 정검출률과 혼합하지 않는다. D는 추가 예약 지연이며 내부 잠금은 원래 후보 시각에 시작한다. 정답 e/정답 방향은 발행에 사용하지 않았다.

| 패널 | D=0 | D=50 | D=100 | D=150 | D=200 | D0→D200 조기 발행 클립 |
|---|---:|---:|---:|---:|---:|---:|
| 원래 S-P5 E60 정검출률 | 34.3% | 38.6% | 41.7% | 44.5% | 45.7% | 30.4%→13.2% |
| 원래 C E60 정검출률 | 37.0% | 45.9% | 57.2% | 64.2% | 70.4% | 63.4%→33.9% |

- 원래 전체 클립의 누락 중 정답 방향의 원시 연속 조건이 있어도 잠겨 있던 사례는 C E60 **632/744**, S-P5 E60 **233/777**로 이전 분석을 재현했다. 5 seed의 원본 반복 관측이며 독립 동작 수가 아니다. 잠금을 없애는 실험은 하지 않았다.
- 고정 지연은 후보의 시각만 이동하므로 공통 비교의 무관측 발행 비율은 S-P5 33.9%, C 3.1%로 모든 D에서 같다. 공통 배경 발행도 D로 바뀌지 않아 약 4.61/분·6.04/분이다. 지연이 모델 분류력·배경 오발행·무발행을 해결했다고 볼 수 없다.
- 전체 클립 보조 비교의 D200 미완료 예약은 seed 평균 S-P5 0.8건, C 0.6건이다. 삭제·시각 당김 없이 원래/예정 시각과 함께 기록했다. 전체 도메인의 배경 발행률에 미완료 예약이 있으면 관측 끝 검열 플래그가 붙는다.
- 200 ms는 시험 후보 중 하나이며 사용자 허용 지연이 아니다. 최고 정검출률을 보고 자동 e를 수정하거나 정책을 채택하지 않았다. e의 타당성을 확인하지 않았으므로 이 수치를 독립 최종 정확도로 쓰지 않는다.

## 검증

- 새 추적/지연/통합 테스트 23개 포함 전체 Python **167개 통과(45.000초)**. 기존 검사 안의 짧은 학습은 코드 점검용일 뿐 이번 분석에 새 모델을 쓰지 않았다.
- 자료형 경계 검토에서 float16 점수를 float64로 변환하면 D0 발행이 달라지는 문제를 발견했다. 실패 회귀 검사 후 입력 자료형을 유지해 수정했다. 원래 점수·margin 비교의 불리언도 변환 전에 기록한다.
- 원래 발행/분류/지연을 저장 JSON과 대조하며 전체 25개 패널, **33,545개 원본×seed×E 관측**을 처리했다. 모든 패널에서 5 seed 모두 포함하고 공통 D마다 후보 수가 같으며 pending이 없음을 검사했다. 좋은 회전 결과만 선택하지 않았다.
- 실행 전 input-manifest에 원래 보호 대상과 NONE 비교 코드·결과·NPZ를 추가 고정했고 분석 후 `verify` 통과. 기존 보호 702개 파일과 NONE 실험 입력은 그대로다. 텍스트 CRLF→LF 해시와 바이너리 raw 해시를 구분했다.
- Android sidecar helper는 JDK 21 / Java17 대상으로 컴파일하고 테스트 통과했다. CSV header·행 formatter는 그대로다. sidecar는 별도 `<csv>.capture.json`이며 독점 생성, 첫/마지막 슬롯·첫 listener 도착·캡처 시작/종료·실패를 기록한다. 모르는 부팅 ID/MTU/버전은 null이다. 도착 시각은 물리 샘플 시각이 아니고 영상 동기화도 아니다.
- APK 빌드, 폰 설치, BLE 수집, 보드 재부팅, 영상 시간 오차, 사람 완료 주석은 검증하지 않았다. 장비/Gradle9.6·AGP9.4·SDK 준비 후 빌드·기기 파일럿이 필요하다.

## 재현

```powershell
& .\ml\.venv\Scripts\python.exe ml/v2_event_timing.py verify
& .\ml\.venv\Scripts\python.exe -m unittest discover -s ml -p 'test_v2_event*.py'
& .\ml\.venv\Scripts\python.exe -m unittest discover -s ml -p 'test_v2_delay_replay.py'
& .\android\tests\run-sidecar-tests.ps1 -JavaHome 'C:\Program Files\Java\jdk-21'
```

`init`은 spec/제품 기준/코드/입력 목록을 고정하고, `run`은 새 출력만 생성한다. 기존 protocol·summary·trace는 덮어쓰지 않는다. 실제 허용 기준을 나중에 합의하면 이 protocol의 기준을 소급 변경하지 않고 후속 의사결정 문서로 남긴다.
