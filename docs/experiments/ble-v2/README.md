# BLE v2 실험 기록

작성: 2026-10-25. 자세별 5세션(P1~P5, 자이로 ±2000 dps, 4초 클립)으로 하는 정식 실험의 기록이다. 계획·고정 조건·발행·채점 protocol·보고 형식은 [학습 계획의 BLE v2 실험](../../TrainingPlan.md#ble-v2-실험--평가-방식-sc-비교-2026-10-25) 절에 있고, 이 폴더에는 실행한 조건·결과·결정만 남긴다.

[BLE v1](../ble-v1/README.md)은 코드 동작을 확인하려던 테스트였다(2026-10-25 사용자 확인). v1의 수치와 채택/미채택 결정은 이어받지 않으며, v1과 v2의 수치를 직접 비교하지 않는다.

## 공통 기록 규칙

- 학습 전에 protocol(분할 해시·고정 조건·데이터 처리 순서·발행·채점 규칙·E 후보와 선택 점수·보고 형식)을 `results/protocol.json`에 시각과 함께 저장한다. 결과를 본 뒤 바꾸지 않는다.
- 평가용은 최종 평가에서 한 번만 연다. 보정·선택은 학습용 안에서만 한다.
- 실행마다 코드 해시와 미커밋 차이, 원본 목록·해시, 주석·분할 버전, 설정, 정규화 계수, seed, Python·TensorFlow·Keras·NumPy 버전, 학습 이력, 시각별 예측, 발행 로그를 `results/<실행 ID>/`에 남긴다. 모델과 입력 배열은 `ml/runs/<실행 ID>/`(Git 제외)에 둔다.
- 결과는 5 seed 평균·범위와 seed별 값으로 쓰고, 미측정 값은 "미측정"으로 쓴다. clip replay 결과를 연속 사용 성능으로 쓰지 않는다.

### 해시 정의 수정과 재고정 (2026-10-25, 학습 전)

처음 만든 주석·분할·protocol(커밋 `805f74a`)의 SHA-256은 파일 바이트 그대로였다. 이 저장소는 `core.autocrlf=true`라 git에는 LF로 들어가고 Windows 작업 트리는 CRLF이며(`dump()`가 쓴 JSON도 CRLF였다), 다른 환경에서 체크아웃하면 모든 해시 검사가 실패한다. 그래서 `digest()`가 CRLF를 LF로 바꿔 계산하도록, `dump()`가 항상 LF로 쓰도록 고쳤다.

- 학습·평가는 한 번도 하지 않은 시점이라 주석·분할·protocol을 지우고 다시 만들었다. 다시 만든 `records.json`과 분할 6개는 **해시 값을 뺀 내용이 처음 것과 완전히 같다**(선택된 평가 원본·fold 배정 동일, 스크립트로 비교).
- 처음 protocol은 커밋 `805f74a`에 남아 있다. 새 protocol의 `hash_note`에도 이력을 적었다.
- 테스트(`DigestTests`)가 LF/CRLF 파일의 해시가 같고 내용이 다르면 다름을, `dump()`가 LF로 쓰는 것을 확인한다.

### 보정 실행기 (2026-10-25)

`ml/v2_cal.py`: `init`(실행 설정과 fold별 정규화 계수 저장), `run`(seed 하나를 모든 fold에서 60 epoch까지 한 번 학습하고 1·5·10·20·30·40·60 epoch의 검증 점수를 저장), `run-all`(seed 5개 병렬), `summarize`(E별 점수와 선택된 E).

- 실행 설정에 분할·records·protocol 해시, 코드 해시, git HEAD·미커밋 목록, 환경(pip 목록)을 저장하고, `run`은 init 이후 코드가 바뀌었으면 거부한다.
- seed별 결과는 `results/V2-<분할>-cal/seed-<seed>.json`(fold별 epoch별 이벤트 집계, 원본별 발행 로그와 분류, val_loss, 창 정확도, 60 epoch 학습 손실). 점수 배열은 `ml/runs/`(Git 제외).
- 선택: seed마다 모든 fold를 합친 (정검출 − 방향 원본 미매칭) ÷ 방향 원본 수, 5 seed 평균이 가장 큰 E, 동점이면 작은 E. 배경 오발행은 점수에서 빼고 따로 보고한다.
- 검증(`ml/test_v2_cal.py` 7개): (1) 한 번 길게 학습하며 중간 저장한 점수가 그 epoch에서 멈춘 별도 학습의 점수와 **정확히 같다**(차이 0.0). (2) 짧은 실제 실행의 구조·집계: 검증 원본이 epoch마다 정확히 한 번, 원본별 합계 = 총합, 검증 창 수 = 판정 시각 수 합(NONE 창을 줄이지 않음), 평가용 원본이 나오지 않음, 결과가 JSON으로 저장됨. (3) 가짜 결과로 선택 규칙: fold는 합산 후 seed 평균, 동점이면 작은 E, 배경 오발행은 선택에 영향 없고 보고됨, 완료 직전 100 ms 조기 발행·지연·잘린 허용 구간 집계.
- 전체 `ml` 테스트 43개(v1 17 + v2 19 + 보정 실행기 7) 통과.

## 보정 결과 (2026-10-25)

학습용 안의 교차검증 결과다. **각 분할의 평가용은 그 분할의 보정에 쓰지 않았다(분할 내부 기준).** 다만 6개 분할의 보정을 합치면 전체 336개 원본이 모두 어느 보정의 검증용으로 쓰였다([자료 재사용 한계](#자료-재사용-한계-2026-10-25)). 실행 ID `V2-<분할>-cal`, 각 분할 5 seed(20261021~25) × fold, 60 epoch까지 한 번 학습하며 1·5·10·20·30·40·60 epoch를 평가했다. 설정·정규화 계수·seed별 원본별 발행 로그는 `results/V2-<분할>-cal/`에 있다. S-P5의 `init`은 깨끗한 작업 트리(커밋 `bd62fa4`)에서 했고, C·회전 4개의 `init`은 앞서 만든 실행 결과 폴더(미추적)가 있는 상태에서 했다(코드 해시는 같다). 어떤 seed도 실패하지 않았다. seed당 45~60초(중앙값 46초), 병렬 5개.

### 선택된 E

선택 점수 = (정검출 − 방향 원본 미매칭 발행) ÷ 방향 원본 수, seed마다 모든 fold 합산, 5 seed 평균, 동점이면 작은 E(protocol에 고정한 규칙).

| 분할 | 선택 E | 선택 점수 | E=1 점수 | E=60 점수 | 정검출률 | 미매칭/원본 | 조기 발행 비중 | 배경 오발행/분 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| S-P5 (공식 S) | **60** | −0.073 | −0.085 | −0.073 | 34.4% | 0.42 | 77% | 4.50 |
| C | **1** | −0.073 | −0.073 | −0.531 | 17.8% | 0.25 | 100% | 1.00 |
| S-P1 (회전) | 1 | −0.046 | −0.046 | −0.087 | 12.3% | 0.17 | 98% | 1.11 |
| S-P2 (회전) | 1 | −0.038 | −0.038 | −0.184 | 11.4% | 0.15 | 98% | 1.07 |
| S-P3 (회전) | 5 | +0.002 | −0.030 | −0.189 | 26.8% | 0.27 | 98% | 2.81 |
| S-P4 (회전) | 1 | −0.010 | −0.010 | −0.134 | 9.6% | 0.11 | 95% | 0.89 |

정검출률·미매칭/원본·조기 비중·배경은 선택 E에서 5 seed 평균이다. 조기 비중은 미매칭 발행 중 완료 시각 전에 나간 발행의 비율(반올림)이다. 배경 오발행은 선택 점수에 넣지 않았다.

### 관찰

- **선택 점수가 거의 모든 E·분할에서 0 이하다**(양수는 S-P3의 E=5, +0.002 하나뿐). 정검출 1개와 미매칭 1개를 같은 무게로 세는 점수라, 조기 발행이 많은 이 모델에서는 덜 발행하는 쪽이 이긴다.
- **선택된 E가 후보 범위의 끝에 몰려 있다**: 1이 4곳, 60이 1곳(S-P5), 5가 1곳. S-P5의 E=60과 E=1은 같은 seed끼리 점수 차이(E60−E1)가 +0.0802, +0.0295, −0.0127, −0.0591, +0.0211(5 seed 순)로 **3개 상승·2개 하락**, 평균 +0.012다. 일관된 방향이 없다는 관찰이며 두 값이 동등하다는 결론은 아니다(같은 seed끼리의 차이는 [진단](diagnostics/calibration-2026-10-25/calibration-diagnostics.md) 5절에 분할별로 있다).
- **E=1이 선택된 분할은 정검출률이 낮고 더 보수적인 후보다.** 선택 E의 정검출률은 9.6~17.8%(S-P5 34.4%, S-P3 26.8%만 높다)이고, 한 번 이상 발행한 방향 클립 비율은 C 42.9%, S-P1 29.2%, S-P2 26.5%, S-P4 20.2%(S-P5 66.2%, S-P3 53.0%)다. 발행을 하지 않는 모델이 아니다. 점수가 0에 가까운 것은 정검출이 많아서가 아니라 미매칭이 적어서다.
- **대부분의 선택 점수가 0 이하라 무발행(점수 0)보다 낫다는 근거가 없다.** 선택 E에서 점수가 0보다 큰 seed는 5개 중 S-P5 0, C 0, S-P1 1, S-P2 1, S-P3 3, S-P4 1개다. 고정한 점수를 따른 선택은 맞지만, 이 점수로 "쓸 만한 모델"이라고 말할 수는 없다.
- **미매칭 발행의 77~100%가 조기 발행**(완료 시각 e 전에 나간 발행)이다. 기존 집계의 `wrong_direction`(S-P5 E=60 평균 4.2건)은 허용 구간 안의 방향 오류만 센다. 조기 분류가 먼저라서 **조기 발행 안의 방향 오류는 거기에 들어가지 않는다.** 따로 세면 조기 발행 중 방향이 정답과 다른 비율이 S-P5 E=60 8.4%(5 seed 합 379건 중 32), C E=1 10.8%(296건 중 32), C E=60 18.4%(877건 중 161)다. 즉 조기 발행의 대부분은 방향이 맞고(이 세 조합에서 81.6~91.6%, 분할×E 42개 조합 전체에서 70.7~95.8%) 일부는 틀리다. 조기 발행은 S-P5 E=60에서 e보다 0~300 ms 전이 71%(median 170 ms 전), C E=60에서 66%(median 220 ms 전)였다. e는 "자이로 에너지 99%가 지난 뒤 180 ms 안정이 시작되는 시점"인 센서 기반 값이라, 모델이 복귀 동작 끝 무렵에 발행하는 것으로 보인다. 이것이 모델의 문제인지 완료 시각 정의의 문제인지는 이 데이터로 가를 수 없다.
- **C는 epoch가 늘수록 전체적으로 나빠진다**(매 epoch 단조는 아니다. 검증 손실이 E=20 0.835에서 E=30 0.818로 잠깐 내려간다): 검증 손실이 0.678(E=1) → 1.006(E=60), 선택 점수가 −0.073 → −0.531이다. E=1이 다른 모든 E보다 높은 점수를 5 seed 모두에서 보였다. 반면 S-P5 보정의 검증 손실은 0.46~0.64 범위에서 움직인다. 한 사례(seed 20261021, fold 0, E=60)의 창 단위 혼동행렬에서 C는 양성 창의 확신한 정답 비율이 72.8%(S-P5 44.8%)로 동작 모양은 더 잘 익혔지만, NONE 창에서 방향이라고 확신하는 비율도 높았다(11.3% 대 6.9%). 한 사례이므로 일반화하지 않는다.
- **세션에 따라 차이가 크다**(S-P5 보정, E=60, 검증 세션별 점수): P1 −0.09, P2 +0.15, P3 −0.19, P4 −0.17. 검증 세션이 P3(팔을 90도 올린 자세)일 때 정검출이 평균 6.4개뿐이다.
- 코드 오류 신호는 없었다: 두 방식의 창 구성·정규화·채점 경로가 같고, 검증 창 수와 원본 수가 기대와 일치했다(`test_v2_cal.py`).

### 계획 규칙에 따른 해석

TrainingPlan의 규칙대로 "정검출이 두 방식 모두 낮으면 평가 방식 차이보다 기준선 자체의 문제로 보고 단일 요인 비교를 따로 계획한다"에 해당한다. 아직 최종 학습·평가는 하지 않았다. 선택된 E 그대로 진행하면 방식 S는 E=60, 방식 C는 E=1이 되어 두 방식이 같은 설정값이 아니라 같은 선택 원칙으로만 묶이고, C는 정검출률 17.8%(발행한 클립 42.9%)의 더 보수적인 모델이 된다.

### 결정이 필요한 것

1. 규칙대로 선택 E(S=60, C=1)로 최종 학습·평가를 진행할지.
2. 평가용을 열기 전에, 학습용 안에서 조기 발행의 원인(라벨·완료 시각 정의, 점수 가중, 후처리)을 새 protocol 버전으로 먼저 조사할지. **(정정)** 이 문장은 틀렸다. 평가용을 "열지" 않았더라도 각 분할의 평가용 원본은 다른 분할의 보정에 검증용으로 쓰였고, 이번 진단까지 포함해 모든 원본이 개발 과정에서 관찰됐다. 새 protocol을 저장해도 이 노출은 없어지지 않는다. 따라서 보정 결과를 보고 만든 개선판의 독립 평가에는 설계를 고정한 뒤 새로 수집한 자료가 필요하다([자료 재사용 한계](#자료-재사용-한계-2026-10-25)).
3. 어느 경우든 선택 E가 후보 범위의 끝이라는 점을 한계로 기록할지, 후보를 넓힐지.

## 자료 재사용 한계 (2026-10-25)

- **분할 내부 기준:** 각 분할의 평가용 원본은 그 분할의 보정(학습·검증)에 한 번도 쓰이지 않았다(6개 분할 모두 겹침 0).
- **전체 개발 과정 기준:** 6개 분할의 보정을 합치면 전체 336개 원본이 모두 어느 보정의 검증용으로 쓰였다(4회 70개, 5회 266개, 한 번도 안 쓰인 원본 0개). 분할별 평가용 원본(C 70, S-P1 66, S-P2 68, S-P3 67, S-P4 68, S-P5 67개)은 전부 다른 분할의 보정 검증에 쓰였다. 이 진단도 같은 예측을 읽었다.
- 따라서 (1) 사전에 고정한 절차(선택 E로 최종 학습 → 평가용에 한 번)를 분할별로 평가하는 것은 가능하지만, 평가 자료가 다른 분할의 개발 과정에서 관찰됐다는 점을 결과와 함께 적어야 한다. (2) 보정 결과와 진단을 보고 공통 설정(완료 시각 정의, 라벨 구간, NONE 구성, 후처리)을 바꾼 **개선판은 이 336개 원본으로 독립 평가했다고 말할 수 없다.** 새 protocol을 저장해도 이 노출은 없어지지 않는다. 개선판의 독립 평가에는 개선 설계를 고정한 뒤 새로 수집해 개발에 쓰지 않을 자료가 필요하다.
- 기존 자료와 보정 산출물을 폐기할 필요는 없다. 개선판의 개발 분석에는 그대로 쓸 수 있다.

## 실행기 보호 보완과 과거 결과 확인 (2026-10-25)

`ml/v2_cal.py`를 실행기 버전 2로 올렸다. 과거 config·protocol·summary·예측 배열은 고치지 않았고 해시도 덮어쓰지 않았다.

| 명령 | 새 검사 |
|---|---|
| `init` | protocol의 분할·records·코드 해시와 현재가 같은지, records 원본 목록이 디스크의 세션 폴더와 같은지(추가·누락 파일), 후보 주석 파일 해시 |
| `run` / `run-all` | config에 고정한 코드·records·분할·protocol 해시가 현재와 같은지(다르면 거부), 결과 저장 전에 스레드 1개·연산 결정성이 실제로 적용됐는지 |
| `summarize` | seed·fold·epoch 누락, 중복 원본, 검증 원본이 분할과 다른 경우, 평가용 원본 혼입, 원본별 합계와 발행 로그의 불일치, 원본이 두 fold에 있는 경우를 검사. 이미 `summary.json`이 있으면 덮어쓰지 않고 거부 |
| `verify`(새) | 읽기 전용. 위 결과 검사 + 저장된 summary와 재집계 일치(선택 E, 모든 E의 평균 점수) |

- 새 결과 파일에는 `runtime`(실제 스레드 수, 결정성 상태, 환경 변수, TensorFlow 버전, 장치)을 기록한다. TensorFlow 2.21에는 결정성 조회 공개 API가 없어 내부 함수를 쓰고, 읽지 못하면 "확인 불가"로 기록해 새 실행이 거부된다.
- **새 실행과 과거 결과를 구분한다.** 새 실행(버전 2)은 현재 코드가 config와 정확히 같아야 한다. 과거 결과(버전 1, 지금까지의 `V2-*-cal` 6개)는 현재 코드와 달라도 손상으로 보지 않고, config에 기록된 코드 해시를 기록된 git 커밋(`bd62fa4`)의 파일과 대조한다. `python ml/v2_cal.py verify --split <분할>`로 6개 모두 통과했고 저장된 summary와 일치한다.
- 과거 protocol은 현재 코드의 `v2_cal.py` 해시와 달라서 새 `init`이 거부된다(테스트로 확인). 개선판 실행에는 새 protocol 파일과 새 `--run-id`가 필요하다. 새 protocol을 만드는 명령은 아직 일반화하지 않았다(다음 실험에서 한다).

## 진단 결과 (2026-10-25)

`ml/v2_diag.py`가 저장된 발행 로그와 분할만 읽어 [진단 보고서](diagnostics/calibration-2026-10-25/calibration-diagnostics.md)(`.json` 포함)를 만들었다. 학습·평가를 하지 않았고 기존 파일을 쓰지 않았다. 채점 우선순위와 선택 점수는 그대로이며, 기록된 분류와 도출한 분류가 모순되는 경우 0건, 6개 분할의 선택 E와 모든 E의 평균 점수가 기존 summary와 정확히 일치한다(최대 차이 0). 독립 검토가 따로 계산한 값(C E=1 발행 클립 42.9%, 조기 발행 안 방향 불일치 32·161·32건, S-P5 E60−E1 seed별 차이)과도 일치했다.

선택 E에서의 값(5 seed 평균):

| 분할 | 선택 E | 발행한 클립 비율 | 정검출률 | 발행했지만 정검출 없는 클립 | 조기 발행 중 방향 불일치 | 점수>0 / <0 / =0 seed |
|---|---:|---:|---:|---:|---:|---|
| S-P5 | 60 | 66.2% | 34.4% | 31.8% | 8.4% | 0 / 4 / 1 |
| C | 1 | 42.9% | 17.8% | 25.1% | 10.8% | 0 / 5 / 0 |
| S-P1 | 1 | 29.2% | 12.3% | 16.9% | 12.7% | 1 / 4 / 0 |
| S-P2 | 1 | 26.5% | 11.4% | 15.2% | 5.7% | 1 / 4 / 0 |
| S-P3 | 5 | 53.0% | 26.8% | 26.2% | 4.2% | 3 / 2 / 0 |
| S-P4 | 1 | 20.2% | 9.6% | 10.6% | 7.6% | 1 / 4 / 0 |

발행한 클립 비율은 한 클립에 발행이 여러 번이어도 한 번만 센다. 무발행 모델의 점수는 0이다.

같은 seed끼리의 epoch 비교(점수 차이의 상승/하락 seed 수):

- C: E=1이 다른 모든 E보다 5 seed 모두에서 높다(E1−E5, …, E1−E60 모두 5/0).
- S-P5: E=60이 E5·E10·E20·E30보다 5/0, E40보다 4/1, E1보다 3/2(평균 +0.012).
- 회전: E1−E60은 S-P2 5/0, S-P4 5/0, S-P3(E5 선택)에서 E60−E1은 0/5, S-P1은 E1−E60이 3/2다.

조기 발행의 위치(보조 진단, 센서 기반 주석이며 영상·사용자 확인이 아니다):

- 완료 시각 e는 센서 기반 주동작 종료 시각보다 10~810 ms 뒤다(296개, 25% 90 ms, 중앙값 175 ms, 75% 280 ms, 300 ms 초과 65개).
- 조기 발행의 63~91%(진단 보고서 6절의 13개 분할×E 조합 전체)는 **주동작이 끝난 뒤, e 전**에 나왔다(대표: S-P5 E=60 75%, C E=1 85%, C E=60 67%). 이 발행들은 e보다 중앙값 105~170 ms 전이다. 주동작 도중의 발행은 9~37%다.
- 해석 한계: 주동작 종료 시각도 같은 도구가 센서에서 계산한 값이다. e가 "자연 복귀 뒤"라는 사용자 의도에 맞는 정답 시각인지, 모델이 더 일찍(주동작 종료 직후) 발행하는 것이 의도에 맞는지는 이 자료로 가를 수 없다.
