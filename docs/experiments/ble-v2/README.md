# BLE v2 실험 기록

작성: 2026-10-25. 자세별 5세션(P1~P5, 자이로 ±2000 dps, 4초 클립)으로 하는 정식 실험의 기록이다. 계획·고정 조건·발행·채점 protocol·보고 형식은 [학습 계획의 BLE v2 실험](../../TrainingPlan.md#ble-v2-실험--평가-방식-sc-비교-2026-10-25) 절에 있고, 이 폴더에는 실행한 조건·결과·결정만 남긴다.

[BLE v1](../ble-v1/README.md)은 코드 동작을 확인하려던 테스트였다(2026-10-25 사용자 확인). v1의 수치와 채택/미채택 결정은 이어받지 않으며, v1과 v2의 수치를 직접 비교하지 않는다.

## 공통 기록 규칙

- 학습 전에 protocol(분할 해시·고정 조건·데이터 처리 순서·발행·채점 규칙·E 후보와 선택 점수·보고 형식)을 `results/protocol.json`에 시각과 함께 저장한다. 결과를 본 뒤 바꾸지 않는다.
- 평가용은 최종 평가에서 한 번만 연다. 보정·선택은 학습용 안에서만 한다.
- 실행마다 코드 해시와 미커밋 차이, 원본 목록·해시, 주석·분할 버전, 설정, 정규화 계수, seed, Python·TensorFlow·Keras·NumPy 버전, 학습 이력, 시각별 예측, 발행 로그를 `results/<실행 ID>/`에 남긴다. 모델과 입력 배열은 `ml/runs/<실행 ID>/`(Git 제외)에 둔다.
- 결과는 5 seed 평균·범위와 seed별 값으로 쓰고, 미측정 값은 "미측정"으로 쓴다. clip replay 결과를 연속 사용 성능으로 쓰지 않는다.

### 해시 정의 수정과 재고정 (2026-10-25, 학습 전)

처음 만든 주석·분할·protocol(커밋 `805f74a`)의 SHA-256은 파일 바이트 그대로였다. 이 저장소는 `core.autocrlf=true`라 git에는 LF로 들어가고 Windows 작업 트리는 CRLF이며(`dump()`가 쓴 JSON도 CRLF였다), 다른 환경에서 체크아웃하면 모든 해시 검사가 실패한다. 그래서 `digest()`가 CRLF를 LF로 바꿔 계산하도록, `dump()`가 항상 LF로 쓰도록 고쳤다.

- 학습·평가는 한 번도 하지 않은 시점이라 주석·분할·protocol을 지우고 다시 만들었다. 다시 만든 `records.json`과 분할 6개는 **해시 값을 뺀 내용이 처음 것과 완전히 같다**(선택된 평가 원본·fold 배정 동일, 스크립트로 비교).
- 처음 protocol은 커밋 `805f74a`에 남아 있다. 새 protocol의 `hash_note`에도 이력을 적었다.
- 테스트(`DigestTests`)가 LF/CRLF 파일의 해시가 같고 내용이 다르면 다름을, `dump()`가 LF로 쓰는 것을 확인한다.

### 보정 실행기 (2026-10-25)

`ml/v2_cal.py`: `init`(실행 설정과 fold별 정규화 계수 저장), `run`(seed 하나를 모든 fold에서 60 epoch까지 한 번 학습하고 1·5·10·20·30·40·60 epoch의 검증 점수를 저장), `run-all`(seed 5개 병렬), `summarize`(E별 점수와 선택된 E).

- 실행 설정에 분할·records·protocol 해시, 코드 해시, git HEAD·미커밋 목록, 환경(pip 목록)을 저장하고, `run`은 init 이후 코드가 바뀌었으면 거부한다.

## 보정 결과 (2026-10-25)

학습용 안의 교차검증 결과다. **평가용은 열지 않았다.** 실행 ID `V2-<분할>-cal`, 각 분할 5 seed(20261021~25) × fold, 60 epoch까지 한 번 학습하며 1·5·10·20·30·40·60 epoch를 평가했다. 설정·정규화 계수·seed별 원본별 발행 로그는 `results/V2-<분할>-cal/`에 있다. 실행은 깨끗한 작업 트리(커밋 `bd62fa4`)에서 시작했고 어떤 seed도 실패하지 않았다. seed당 45~60초(중앙값 46초), 병렬 5개.

### 선택된 E

선택 점수 = (정검출 − 방향 원본 미매칭 발행) ÷ 방향 원본 수, seed마다 모든 fold 합산, 5 seed 평균, 동점이면 작은 E(protocol에 고정한 규칙).

| 분할 | 선택 E | 선택 점수 | E=1 점수 | E=60 점수 | 정검출률 | 미매칭/원본 | 조기 발행 비중 | 배경 오발행/분 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| S-P5 (공식 S) | **60** | −0.073 | −0.085 | −0.073 | 34.4% | 0.42 | 77% | 4.50 |
| C | **1** | −0.073 | −0.073 | −0.531 | 17.8% | 0.25 | 100% | 1.00 |
| S-P1 (회전) | 1 | −0.046 | −0.046 | −0.087 | 12.3% | 0.17 | 98% | 1.11 |
| S-P2 (회전) | 1 | −0.038 | −0.038 | −0.184 | 11.4% | 0.15 | 98% | 1.07 |
| S-P3 (회전) | 5 | +0.002 | −0.030 | −0.189 | 26.8% | 0.27 | 98% | 2.81 |
| S-P4 (회전) | 1 | −0.010 | −0.010 | −0.134 | 9.6% | 0.11 | 95% | 0.89 |

정검출률·미매칭/원본·조기 비중·배경은 선택 E에서 5 seed 평균이다. 조기 비중은 미매칭 발행 중 완료 시각 전에 나간 발행의 비율(반올림)이다. 배경 오발행은 선택 점수에 넣지 않았다.

### 관찰

- **선택 점수가 거의 모든 E·분할에서 0 이하다**(양수는 S-P3의 E=5, +0.002 하나뿐). 정검출 1개와 미매칭 1개를 같은 무게로 세는 점수라, 조기 발행이 많은 이 모델에서는 덜 발행하는 쪽이 이긴다.
- **선택된 E가 후보 범위의 끝에 몰려 있다**: 1이 4곳, 60이 1곳(S-P5), 5가 1곳. S-P5는 E=60과 E=1의 점수 차이(0.012)가 seed 범위(E=60에서 −0.148~0.000) 안이라 사실상 구분되지 않는다.
- **E=1이 선택되면 거의 발행하지 않는 모델이다.** 선택 E에서 정검출률이 9.6~17.8%(S-P5 34.4%, S-P3 26.8%만 높다)다. 점수가 0에 가까운 것은 잘 맞혀서가 아니라 미매칭이 적어서다.
- **미매칭 발행의 77~100%가 조기 발행**(완료 시각 e 전에 나간 발행)이고 방향 오류는 드물다(S-P5 E=60에서 평균 4건). 조기 발행은 S-P5 E=60에서 e보다 0~300 ms 전이 71%(median 170 ms 전), C E=60에서 66%(median 220 ms 전)였다. e는 "자이로 에너지 99%가 지난 뒤 180 ms 안정이 시작되는 시점"인 센서 기반 값이라, 모델이 복귀 동작 끝 무렵에 발행하는 것으로 보인다. 이것이 모델의 문제인지 완료 시각 정의의 문제인지는 이 데이터로 가를 수 없다.
- **C는 epoch가 늘수록 나빠진다**: 검증 손실이 0.678(E=1) → 1.006(E=60), 선택 점수가 −0.073 → −0.531이다. 반면 S-P5 보정의 검증 손실은 0.46~0.64 범위에서 움직인다. 한 사례(seed 20261021, fold 0, E=60)의 창 단위 혼동행렬에서 C는 양성 창의 확신한 정답 비율이 72.8%(S-P5 44.8%)로 동작 모양은 더 잘 익혔지만, NONE 창에서 방향이라고 확신하는 비율도 높았다(11.3% 대 6.9%). 한 사례이므로 일반화하지 않는다.
- **세션에 따라 차이가 크다**(S-P5 보정, E=60, 검증 세션별 점수): P1 −0.09, P2 +0.15, P3 −0.19, P4 −0.17. 검증 세션이 P3(팔을 90도 올린 자세)일 때 정검출이 평균 6.4개뿐이다.
- 코드 오류 신호는 없었다: 두 방식의 창 구성·정규화·채점 경로가 같고, 검증 창 수와 원본 수가 기대와 일치했다(`test_v2_cal.py`).

### 계획 규칙에 따른 해석

TrainingPlan의 규칙대로 "정검출이 두 방식 모두 낮으면 평가 방식 차이보다 기준선 자체의 문제로 보고 단일 요인 비교를 따로 계획한다"에 해당한다. 아직 최종 학습·평가는 하지 않았다. 선택된 E 그대로 진행하면 방식 S는 E=60, 방식 C는 E=1이 되어 두 방식이 같은 설정값이 아니라 같은 선택 원칙으로만 묶이고, C는 거의 발행하지 않는 모델이 된다.

### 결정이 필요한 것

1. 규칙대로 선택 E(S=60, C=1)로 최종 학습·평가를 진행할지.
2. 평가용을 열기 전에, 학습용 안에서 조기 발행의 원인(라벨·완료 시각 정의, 점수 가중, 후처리)을 새 protocol 버전으로 먼저 조사할지. 평가용을 열지 않았으므로 지금은 계획을 바꿔도 평가용이 오염되지 않는다.
3. 어느 경우든 선택 E가 후보 범위의 끝이라는 점을 한계로 기록할지, 후보를 넓힐지.
