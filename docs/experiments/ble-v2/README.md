# BLE v2 실험 기록

작성: 2026-10-25. 자세별 5세션(P1~P5, 자이로 ±2000 dps, 4초 클립)으로 하는 정식 실험의 기록이다. 계획·고정 조건·발행·채점 protocol·보고 형식은 [학습 계획의 BLE v2 실험](../../TrainingPlan.md#ble-v2-실험--평가-방식-sc-비교-2026-10-25) 절에 있고, 이 폴더에는 실행한 조건·결과·결정만 남긴다.

[BLE v1](../ble-v1/README.md)은 코드 동작을 확인하려던 테스트였다(2026-10-25 사용자 확인). v1의 수치와 채택/미채택 결정은 이어받지 않으며, v1과 v2의 수치를 직접 비교하지 않는다.

| V2-S-cal, V2-C-cal | 방식마다 학습용 안의 교차검증으로 고정 epoch E를 정한다 | 계획 |
| V2-S-final, V2-C-final | 학습용 전체로 5 seed 모델을 만들어 평가용에 한 번 적용한다. C − S는 판정하지 않고 크기·seed별 일관성을 기술한다 | 계획 |
| V2-S-P1~P4 | 방식 S의 평가 세션을 돌아가며 바꿔 세션별 변동을 본다(기본, 2026-10-25 검토로 선택에서 올림) | 계획 |

증강(착용 각도 포함), 문턱 튜닝, 구조·입력 길이·라벨 폭 비교는 이 결과를 본 뒤 따로 계획한다. 연속 기록이 없어 연속 사용 성능은 다루지 않는다.

## 공통 기록 규칙

- 학습 전에 protocol(분할 해시·고정 조건·데이터 처리 순서·발행·채점 규칙·E 후보와 선택 점수·보고 형식)을 `results/protocol.json`에 시각과 함께 저장한다. 결과를 본 뒤 바꾸지 않는다.
- 평가용은 최종 평가에서 한 번만 연다. 보정·선택은 학습용 안에서만 한다.
- 실행마다 코드 해시와 미커밋 차이, 원본 목록·해시, 주석·분할 버전, 설정, 정규화 계수, seed, Python·TensorFlow·Keras·NumPy 버전, 학습 이력, 시각별 예측, 발행 로그를 `results/<실행 ID>/`에 남긴다. 모델과 입력 배열은 `ml/runs/<실행 ID>/`(Git 제외)에 둔다.
- 결과는 5 seed 평균·범위와 seed별 값으로 쓰고, 미측정 값은 "미측정"으로 쓴다. clip replay 결과를 연속 사용 성능으로 쓰지 않는다.

## V2-prep 기록

### 실행 환경 (2026-10-25)

- PC: Windows 11 Pro, CPU 20 논리 코어. 네이티브 Windows의 TensorFlow 2.11 이상은 GPU를 쓰지 않으므로 CPU로 학습한다.
- Python 3.12.10(winget `Python.Python.3.12`, 사용자 범위 설치)으로 `ml/.venv`를 만들고 `ml/requirements.txt`를 그대로 설치했다. `pip check` 이상 없음.
- 확인한 버전: TensorFlow 2.21.0, Keras 3.15.1, NumPy 2.5.4. v1 기록의 Python은 3.12.15로 패치 버전이 다르다. 고정 패키지는 같다.
- 이 PC의 기본 Python은 3.14였는데, TensorFlow 2.21.0의 Windows 휠이 cp310~cp313뿐이라(PyPI 확인) 쓰지 않았다.
- 점검: `ml/model.py` 기본 모델 9,493 파라미터, 영 입력 출력 (1, 5)·합 1.0. 기존 단위 테스트 17개 통과(합성 데이터만 사용, v1 3초 기준 코드).
- `ml/v2.py`는 v1과 같이 oneDNN 최적화를 끄고(`TF_ENABLE_ONEDNN_OPTS=0`) 스레드를 1개로, 연산 결정성을 켠 상태로 학습한다. 같은 seed의 재현성은 아래 smoke에서 확인했다.

### 코드 (2026-10-25)

- `ml/v2.py`: 센서 읽기(400행/1000행, 타임스탬프 0부터 10 ms 간격 엄격 검사), 창 생성, 양성 창 수, 정규화, NONE 추출, 발행·채점, 완료 주석 저장, 분할 6개 생성·검증, fold 데이터 구성, 고정 epoch 중간 점수 저장 학습, protocol 저장, smoke.
- `ml/test_v2.py`: 17개. 양성 창 수(v1과 같은 구간 전수 비교, 클립 끝 경계), 센서 파일 검사, 창 정렬·미래 값 없음, 정규화가 주어진 학습 파일만 쓰는지, 발행·채점·NONE 추출이 v1 함수와 같은 결과를 내는지(무작위 300회), 분류 우선순위, 선택 점수에서 배경 제외, 저장된 주석·분할의 일관성과 fold 누수 없음.
- 전체 `ml` 테스트 34개(v1 17 + v2 17) 통과.

### 완료 주석 (2026-10-25)

`tools/suggest-gesture-completions.js`를 세션별로 실행해 `data/annotations/ble-v2/<세션>-candidates.json`에 저장하고, 전체를 `records.json`(원본 336개 SHA-256, 완료 시각, 상태·플래그, 양성 창 수, 사용자 제외 5개와 사유)으로 묶었다. 센서 기반 자동 후보이며 영상·사용자 확인은 없다. 자동 완료 시각을 그대로 쓴다.

|---|---:|---:|---:|---|
| P1 | 58 | 56 | 2 | `early_motion` 2 |

| P3 | 59 | 53 | 6 | `early_motion` 6 |

- **방향 원본 296개 모두 양성 창이 3개다.** 동작 신호를 1초로 늦춘 효과다. 완료 시각은 1840~3530 ms(중앙값 2450 ms)이고, v1처럼 첫 판정(1590 ms) 전에 끝나는 원본이 없다.

- 사용 가능한 자이로 최대값이 ±2000 dps 한계(`near_gyro_limit`)에 닿은 방향 원본은 없다.

### smoke (코드 점검, 2026-10-25)

`python ml/v2.py smoke`: S-P5 **학습용 안의** 보정 fold 하나(검증 세션 P1)로 5 epoch를 같은 seed로 두 번 학습했다. 평가용은 열지 않았다.

- 학습 창은 양성 537개에 NONE 537개(동작 중·완료 후·idle·other 각 약 134개), 검증 창은 4,194개로 58×49 + 8×169와 같다(NONE을 줄이지 않음).
- 같은 seed 두 번의 학습 손실과 검증 점수 차이가 **0.0**이다(epoch 1, 5). 재현이 된다.
- 이 학습의 정검출·발행 수치는 코드가 끝까지 도는지 보려는 용도라 기록하지 않았고 어떤 선택에도 쓰지 않았다.
