# NONE 창의 실제 선택 확인 (학습 부분만, 기술 통계)

> 생성: 2026-10-25T18:37:39+09:00 / 도구: `ml/v2_none_review.py` / 모델 학습 없음. 이 문서는 `choose_training()`이 실제로 고른 NONE 창의 시간 분포를 센 것이며 원인을 주장하지 않는다. 구간은 진단 집계용이고 라벨·성공 기준·선택 규칙을 바꾸지 않는다.

## 1. 무엇을 세었나

- 대상: 보정 실행 6개(S-P5, C, S-P1, S-P2, S-P3, S-P4)의 모든 cv fold(25개). 학습 부분(분할 학습 원본 - fold 검증 원본)만 사용했다. 검증·평가 원본은 읽지 않았고 학습 목록에 없음을 확인했다.
- 재현: `normalization` -> `make_chunks` -> `choose_training(seed=20261021)`. NONE 선택 seed는 고정이라 학습 seed와 무관하다.
- config 대조: `results/V2-<split>-cal/config.json`의 `train_windows_all`, `train_windows_selected`, `train_none_groups`, `train_sources`, `validation_sources`와 25개 fold 모두 정확히 일치했다(일치 여부: True). 하나라도 다르면 실행이 중단된다.
- 구간(방향 클립의 NONE 창, 창 시각 t의 e 기준 위치): `[-300,0)`, `[-600,-300)`, `-600보다 이른 진행 중`, `완료 후(t>=e+150)`. `[e,e+150)`는 양성이라 NONE에 없다. idle·other 클립은 따로 센다.
- **세는 규칙**: 같은 원본은 여러 fold와 여러 분할의 학습 부분에 되풀이해 들어간다. 아래 `관측`은 (원본, fold) 쌍의 합이며 독립 표본 수가 아니다. `고유 원본`은 한 분할 안에서 원본을 한 번만 센다. 서로 다른 분할의 값은 합하지 않는다.

## 2. 선택기가 실제로 하는 일

`choose_training()`은 양성 창 수만큼 NONE을 뽑는다. NONE 종류(idle, in_progress, other, post_completion, pre_cue; 이름순)를 한 개씩 돌아가며, 종류 안에서는 `source_path` 이름순으로 파일을 한 바퀴씩 돌며 각 파일의 창을 seed로 섞은 순서대로 한 개씩 뽑는다. pre_cue 창은 첫 판정 시각(1590 ms)이 큐(1000 ms)보다 늦어 존재하지 않는다.

- 25개 fold에서 진행 중(in_progress) 선택은 fold당 132~143개이고, 진행 중 창이 있는 학습 방향 클립은 fold당 176~190개다. 한 클립에서 뽑힌 진행 중 창은 많아야 1개였다.
- 선택 수가 클립 수보다 적으면 한 바퀴(클립당 1개)를 다 돌기 전에 개수가 차므로 이름순에서 뒤쪽인 클립에서는 진행 중 창이 뽑히지 않는다. fold당 진행 중 창이 뽑힌 클립은 132~143개이고, 그중 `[-300,0)`에서 뽑힌 클립은 43~58개다.

## 8. 해석 한계

- 이 문서는 학습 창 선택 분포의 기술이다. 이 분포가 조기 발행이나 다른 성능 현상의 원인이라는 근거를 제공하지 않는다.
- 구간(300/600 ms)은 이 진단을 위한 집계 경계이며 라벨·성공 기준과 무관하다.
- 같은 원본은 여러 fold와 분할에서 되풀이해 관측된다. 관측 합계를 독립 표본 수로 읽으면 안 된다.
- 완료 시각 e는 센서 기반 자동 후보이며 영상·사용자 확인이 없다. 구간은 그 e 기준이다.
