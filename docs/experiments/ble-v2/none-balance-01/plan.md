# NONE 세션·클립 배분 비교 — 2026-10-25

사용자 승인: 제안 1을 먼저 이어서 수행한다는 2026-10-25 요청. 로컬 작업이며 푸시는 하지 않는다.

1. 원래 선택기의 세션 편중을 합성 데이터 테스트로 재현한다. 새 선택기는 양성·NONE 총수·종류별 할당량과 클립 안 창의 기존 shuffle/pop 우선순위를 유지하고, 종류 안에서 세션→클립 순으로 고정 seed 라운드로빈한다. 용량이 부족한 곳의 몫만 남은 곳으로 재분배한다.
2. 보호된 기존 `v2.py`·실행기·주석·결과는 바꾸지 않는다. 새 선택기/실행기/비교기를 별도 모듈로 추가한다. 원래 학습 함수를 재사용하고, 원래 선택기를 넣었을 때 입력 배열·정규화·검증 창이 기존 경로와 같은지 확인한다.
3. protocol 생성은 spec 경로와 출력 경로를 인자로 받고 배타적으로 생성한다. 코드·spec·원본 목록·주석·분할·기준선 결과·기존 보호 manifest를 고정한다. 과거 protocol은 덮어쓰지 않는다.
4. `spec.json`의 비교 규칙을 새 학습 전에 고정한다. 전략마다 같은 원칙으로 E를 선택한 대응 비교를 주 비교로, 같은 E 대응 비교를 보조로 보고한다. seed 방향 개수는 기술 통계이며 유의성 규칙이 아니다. 초기화 전에 결과를 좋게 만드는 문턱·가중치 변경을 하지 않는다.
5. 테스트와 fold별 불변식을 확인하고 코드 상태를 보존한다. 실험 초기화 시 모든 fold의 원래/새 선택 총량·종류 수·정규화가 같고 평가 원본이 없는지 검사한다. 새 선택의 세션별·클립별 분포와 선택 창 목록 해시를 저장한다.
6. S-P5 → C → S-P1 → S-P2 → S-P3 → S-P4 순으로 실행한다. 분할별 5 seed는 최대 5개 프로세스로 병렬 실행하고, 각 (seed, fold)는 60 epoch까지 한 번 학습해 1·5·10·20·30·40·60 epoch를 저장한다. 총 30 seed 실행 / 125회 학습이다.
7. 매 실행의 환경·학습 이력·검증 예측·발행·정규화·입력 배분을 저장한다. 모두 끝나면 원래 기준선과 대응 비교하고, 개선·악화·교환관계를 그대로 기록한다. 기존 기본 선택기를 자동 교체하지 않는다.
8. 영상 관찰 갈래는 준비 체크리스트만 정리한다. 현재 CSV와 영상의 시각 대응은 측정 전이므로 ±50 ms 달성을 주장하지 않는다. 촬영·앱/펌웨어 변경·원래 기준선 최종 학습/평가는 이번에 실행하지 않는다.

완료 조건: 테스트 통과, 기존 보호 대상 변경/추가/삭제 0, 6개 분할의 5 seed 결과 완비, 모든 E의 재집계 일치, 새 protocol과 실행 해시 일치, 대응 비교와 한계 문서화. 진척·실패·복구도 진행기록에 추가한다.
