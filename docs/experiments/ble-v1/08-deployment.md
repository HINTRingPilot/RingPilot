# BLE 실험 8 — int8·보드 검증과 최종 채택

작성: 2026-10-21 / 갱신: 2026-10-21(개발 평가 v2 적용) / ID: BLE-08 / 상태: 미실행 계획

## 목적·선택 이유

선택한 float 모델을 int8로 변환하고 실제 보드에서 100 Hz 수집·BLE와 함께 실행할 수 있는지 확인한다. 정확도뿐 아니라 출력 안정성과 실행 자원까지 최종 설계 근거로 남긴다.

## 비교와 절차

1. 실험 7에서 잠근 모델·후처리·평가 규칙·허용 기준을 기록한다. [개발 평가 v2](../../archive/TrainingPlan.md#개발-평가-v2--ble-06부터)에 따라 훈련+검증 원본 39개 전체를 고정 epoch E로 다시 학습한다. 정규화는 이 39개에서 다시 계산한다. seed 5개 모델을 모두 만들고, 배포 모델의 seed는 최종 평가 전에 20261021로 정해 둔다. 대표 입력은 이 학습 원본에서만 구성한다.
2. int8 변환 후 validation에서 같은 입력의 float/int8 이벤트 결과와 양자화 차이를 확인한다. 입력/출력 scale·zero point·지원 연산을 보존한다.
3. 후보를 확정한 뒤 미사용 clip·연속 최종 평가를 float/int8에 동일하게 적용한다. clip 최종 평가 22개는 seed 5개 float 모델에 한 번씩 적용해 평균·범위를 보고하고, int8은 배포 seed 모델에 적용한다. 방향 평가 원본은 첫 세션(09:16)이라 세션이 분리된 유일한 평가다. 완료 정답을 보류한 `raw_right.1`은 따로 표시한다. 테스트 결과로 수정하면 그 자료는 개발 자료로 전환하고 새 최종 평가를 확보한다.
4. 보드에서 100 Hz 수집과 BLE를 켠 채 전처리+추론 시간 median/p95/max, peak RAM·Flash, 샘플 누락·발행 동작을 측정한다. 50 ms 판정 주기 충족 여부와 측정 방법·횟수·조건을 기록한다.
5. Android까지 연결한 실제 동작은 관찰 또는 사용자 확인이 있는 범위만 검증 완료로 쓴다.

## 평가·완료 조건

[공통 규칙](README.md)에 따라 보드·코어·런타임 버전, 빌드/측정 로그와 실패 조건을 보존한다. 사전 허용 기준 충족 여부를 판단하고 [최종 설계 결정 기록](final-architecture.md)에 채택 또는 보류를 남긴다. 보드 실행이 없으면 최종 배포 검증 완료로 처리하지 않는다.
