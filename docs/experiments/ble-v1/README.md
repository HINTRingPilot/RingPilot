# BLE v1 실험 기록

작성: 2026-10-21. 현재 [아키텍처 v1](../../ModelArchitecture.md)을 출발점으로 최종 채택 설계까지 판단 근거를 남긴다. **실험 1~2·4~5는 clip 학습·검증 완료, 실험 3은 clip 사전 비교 완료·정식 연속 검증 대기, 실험 6~8은 미실행 계획이다.** 실험 1~5의 미채택 결정은 seed 차이 안의 결과라 "구분 불가"로 해석하며, 실험 6부터 평가 방식을 바꾼다. 과거 USB 실험 1~8과 번호 체계가 별개다. 과거 기록은 [조현준 기록](../../진행기록_조현준.md)에 보존한다.

## 진행 순서

| 번호 | 질문 | 기록 | 상태 |
|---|---|---|---|
| BLE-01 | 현재 설계의 무증강 기준 성능은? | [실험 1 진행 기록](실험1_진행기록.md) | 첫 실행 완료: 명령 검출 0/8, 배포 미채택 |
| BLE-02 | NONE 혼동은 어디서 생기는가? | [실험 2 진행 기록](실험2_진행기록.md) | 3 seed×2조건 비교 완료: 가중치 변경 미채택 |
| BLE-03 | 완료 시점 라벨이 명령 목적에 맞는가? | [실험 3 진행 기록](실험3_진행기록.md) | 150/300 ms 사전 비교 완료·변경 미채택 / 연속 검증 대기 |
| BLE-04 | 1.6초 입력이 필요한가? | [실험 4 진행 기록](실험4_진행기록.md) | 160/120행 비교 완료 / 120행 변경 미채택 |
| BLE-05 | Flatten의 시간 위치 정보가 도움이 되는가? | [실험 5 진행 기록](실험5_진행기록.md) | Flatten/GAP 비교 완료 / GAP 변경 미채택 |
| BLE-06 | 증강과 깊이의 효과를 구분할 수 있는가? | [실험 6](06-augmentation-depth.md) | 계획 |
| BLE-07 | 연속 입력에서 실제 명령을 안정적으로 내는가? | [실험 7](07-continuous-events.md) | 계획 |
| BLE-08 | int8·보드에서도 채택 조건을 만족하는가? | [실험 8](08-deployment.md) | 계획 |

번호를 채우기 위해 불필요한 실험을 강행하지 않는다. 앞선 결과에 따라 후속 순서·범위를 수정하거나 생략하고 이유를 해당 문서에 남긴다. 실험 1은 데이터 준비와 첫 학습을 포함하며, 모델 구조 비교는 그 뒤에 한다.

## 공통 실행·기록 규칙

- 학습·평가의 공통 규칙은 [학습 계획](../../TrainingPlan.md)을 따른다. 데이터 원본을 먼저 분할하고 모든 창·증강본이 부모 원본의 분할을 상속한다.
- 실험별로 채택한 기준 실행 ID를 명시한다. 비교 조건 외의 분할·전처리·학습·후처리를 고정하며, 라벨/창 길이 변경에 필요한 차이는 명시한다.
- 모델과 문턱 선택에는 train/validation 및 개발용 연속 자료만 쓴다. 미사용 최종 평가는 후보·문턱·평가 규칙을 잠근 뒤 실험 8에서 실행한다. 테스트 결과로 수정하면 새 최종 평가 자료가 필요하다.
- 실험 1에서 평가용 원본의 품질·정답 검토는 하되 모델 예측을 보고 정답이나 제외 기준을 바꾸지 않는다. 정답 판정 불가 자료와 사유를 남긴다.
- 현재 배경 자료가 짧고 배경의 세션 전체 분리가 아니므로, 짧은 clip 성능을 장시간/재착용 일반화로 해석하지 않는다. 연속 자료 수집은 실험 1과 함께 준비한다.
- 실행마다 `BLE-01-r01`처럼 ID를 붙이고 코드 버전·미커밋 차이, 원본 목록/해시, 주석 버전, 분할표, 설정, 정규화 계수, seed, 도구/환경 버전, 모델, 학습 곡선, 혼동행렬, 시각별 예측·이벤트 로그 경로를 기록한다. 아직 없는 산출물은 '미생성'으로 쓴다.
- 비교는 같은 seed 집합으로 2~3회 이상 반복해 평균·범위와 원본별 성공 여부를 남긴다. 반복 횟수와 seed는 비교 전에 고정한다.
- **BLE-06부터는 [개발 평가 v2](../../TrainingPlan.md#개발-평가-v2--ble-06부터)를 적용한다.** 원본 단위 5-fold 교차검증, 고정 epoch, seed 5개, 개발 후보/악화/판단 불가의 세 가지 판정을 쓴다. BLE-01~05의 고정 분할·val_loss 선택 결과와 수치를 직접 비교하지 않는다.
- 모델 요약/영 입력 실행, 실제 학습, 오프라인 평가, 보드 실측, 사용자 확인을 구분한다. 미측정 수치는 추정 성과로 채우지 않는다.
