# BLE 실험 7 — 연속 입력과 명령 발행

> **2026-10-25:** 7a는 코드 동작 확인용 테스트였다. 후처리 설정(.9/.2/2/3)은 참고용이다([README](README.md) 참고).

작성: 2026-10-21 / 갱신: 2026-10-21(개발 평가 v2 적용) / ID: BLE-07 / 상태: 7a(clip) 완료 / 7b(연속) 자료 없음으로 미실행

## 목적·선택 이유

선택 후보가 빠른 반복 명령·자연 복귀·일상 움직임에서 실제 사용할 만한 이벤트를 내는지 개발용 연속 자료로 확인한다. 독립 3초 clip을 이어 붙여 연속 자료를 대신하지 않는다.

## 비교와 절차

기준 모델·정규화·라벨·E를 고정한다. 점수 문턱·margin·방향 연속 횟수·NONE 재무장 횟수를 개발용 자료에서 조정한다. 검색 범위를 미리 기록하고 모든 결과를 남긴다. 누락·오발행·중복·지연 중 허용할 기준과 우선순위를 수치로 정한 뒤 후보를 선택한다.

2026-10-21 기준 사용자는 새 연속 수집이 어렵다고 답했다. 연속 자료가 없는 동안에는 단계를 나눈다.

- **7a(clip):** 후처리 설정을 [개발 평가 v2](../../archive/TrainingPlan.md#개발-평가-v2--ble-06부터)의 교차검증 clip replay(방향 35동작, 배경 20초)에서 고른다. 검색 범위와 선택 규칙은 실행 전에 고정한다. 결과는 clip 결과로만 보고하며 연속 사용 성능이라 주장하지 않는다.
- **7b(연속):** 연속 자료가 확보되면 7a의 설정을 검증하고 필요하면 다시 조정한다. 7b 없이 실험 8로 넘어가면 최종 결정 기록에 "연속 검증 없음"을 명시한다.

문턱을 바꾸면 2회 연속 조건에서 양성 1창 원본의 발행 가능성도 바뀐다. 이 원본들의 결과를 따로 표시한다.

## 평가·완료 조건

실제 관측 시간·명령 수·일대일 이벤트 매칭·지연 분포·배경 오발행·재무장 실패를 기록한다. 재착용 조건은 따로 표시한다. [공통 규칙](README.md)에 따라 모델·문턱·평가 규칙·배포 허용 기준을 잠그고 미사용 최종 평가 목록을 확정한다.

### BLE-07a 실행 결과 (2026-10-21, 클립 재생)

- 격자(문턱 .6~.9, margin .1~.3, 연속 1~3, 재무장 1~3, 108개)와 선택 규칙(정검출−미매칭 평균 최대, 동점이면 기본값에 가까운 쪽)을 검색 전에 `results/BLE-07a/protocol.json`에 고정했다. 입력은 BLE-06 CV 예측(조건 4개 × seed 5 × fold 5). 코드 `ml/experiment7a.py`.
- 같은 CV 예측으로 설정을 고르고 평가했으므로 튜닝 후 수치는 낙관적이다. 연속 자료가 없어 7b는 하지 않았고, 연속 검증은 없다.

| 경로 | 설정(문턱/margin/연속/재무장) | 정검출 | 미매칭 | 점수 |
|---|---|---:|---:|---:|
| 기본값, A | .8/.2/2/2 | 16.0 | 12.4 | 3.6 |
| 1번: A 튜닝 | .9/.2/3/2 | 9.6 | 3.6 | 6.0 |
| 2번: 6의 선택 후보 = A (규칙상 판단 불가라 A 유지) | 1번과 동일 | 9.6 | 3.6 | 6.0 |
| 참고: B 튜닝 | .9/.2/2/3 | 20.4 | 11.8 | 8.6 |
| 참고: C 튜닝 | .8/.2/3/3 | 9.8 | 3.8 | 6.0 |
| 참고: D 튜닝 | .8/.2/3/2 | 18.8 | 12.0 | 6.8 |

- 1번과 2번은 6의 규칙 판정이 A 유지라서 같은 결과가 된다. 두 경로가 갈리려면 B를 후보로 인정해야 하는데, 이는 사전 규칙을 바꾸는 일이라 하지 않았다.
- A는 튜닝으로 미매칭을 12.4→3.6로 줄이지만 정검출이 16.0→9.6/35(27%)로 떨어진다. B는 튜닝 후에도 20.4/35(58%)를 유지하지만 미매칭 11.8건(조기 7.4건)이 남는다. 튜닝 후 점수는 B 8.6 > D 6.8 > A·C 6.0이다.
